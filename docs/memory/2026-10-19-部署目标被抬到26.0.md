# 部署目标被 Xcode 抬到 26.0，产物装不上旧系统（2026-10-19）

## 对照结论

拿 `suenmusic-mobile-main`（原版）逐文件对比，iOS 侧只有三处实质差异，
其中**唯一会造成「原版能跑、当前跑不了」的是部署目标**：

| 项 | 原版 / HEAD | 事故时的工作区 |
|---|---|---|
| `IPHONEOS_DEPLOYMENT_TARGET`（App） | 15.0 | **26.0** |
| Widget target | 无 | 有（新功能） |
| `CODE_SIGN_ENTITLEMENTS` | 无 | App + Widget 都接 App Group |

`LastUpgradeCheck` 从 `0920` 变成 `2650`，`DEVELOPMENT_TEAM` 从 target 级挪到
project 级，`ENABLE_USER_SCRIPT_SANDBOXING` / `STRING_CATALOG_GENERATE_SYMBOLS`
等也随之出现——这是 **Xcode 26.5 的 "Update to recommended settings"** 一次
性迁移的指纹。它会顺手把 deployment target 提到当前 SDK 大版本。

## 实证

同一台机器、同一个 Xcode 26.5 的 DerivedData：

| 产物 | 时间 | MinimumOSVersion | 说明 |
|---|---|---|---|
| `App-bbrbpuix…/Debug-iphoneos` | Sep 27 | 15.0 | 原版工程，真机 |
| `App-fnmymnrx…/Debug-iphoneos` | Sep 30 | 26.0 | bundle 为 `com.suenmoney.app`（非本工程口径） |
| `App-frvhkorq…/Debug-iphoneos` | 更早 | 15.0 | 原版工程，真机 |
| `App-frvhkorq…/Debug-iphonesimulator` | Oct 19 21:54 | 26.0 | 被抬过的工程，首次模拟器构建 |

结论：**不是环境差异，是工程配置差异**。MinimumOSVersion=26.0 的包在
iOS 15–25 的设备/模拟器上直接装不上；用 Xcode 16 及更低的 SDK 构建则直接报
`building for iOS 26.0, but the SDK does not support`。

## 处置

4 处 `IPHONEOS_DEPLOYMENT_TARGET` 全部改回 15.0（App ×2、Widget ×2），实测：

```bash
cd ios/App
xcodebuild -project App.xcodeproj -target App -configuration Debug \
  -sdk iphonesimulator SYMROOT=build/check CODE_SIGNING_ALLOWED=NO build
xcodebuild -project App.xcodeproj -target App -configuration Debug \
  -sdk iphoneos SYMROOT=build/check-dev \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO build
```

两个 SDK 都 `BUILD SUCCEEDED`，主 App 与 `PlugIns/SuenMusicWidget.appex`
的 `MinimumOSVersion` 均为 15.0。`import AppIntents` 在 15.0 下不报错
（所有用法都在 `@available(iOS 17.0, *)` 里），不需要抬到 16/17。

**口径**：以后 Xcode 弹 "Update to recommended settings"，不要无脑接受；
至少确认 `IPHONEOS_DEPLOYMENT_TARGET` 没有被改。
