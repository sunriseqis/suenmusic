# 2026-10-23 在播行「高亮时点不到行尾不喜欢按钮」：薄染层吃掉点击

**用户报**：推荐页（专属）里正在播放的歌曲高亮时，点该行行尾的「不喜欢」图标没反应。

## 根因

`TrackItem` 的在播行会叠一层 7% 琥珀薄染（web color-mix(accent 7%, panel) 等价物）：
它在内容 `Stack` 里是**最后一个子节点**且 `width/height 100%` —— 铺满整行盖在最上层，
ArkUI 默认 `HitTestMode.Default` 会**吃掉这一层的点击**，于是行尾 dislike 键、行点击全被挡住。
未在播的行没有这层，所以只有「高亮那行点不动」——现象完全对得上。

## 修法

给薄染层加 `.hitTestBehavior(HitTestMode.None)`（与自绘 toast 同一套做法），点击穿透到下层内容。
顺带全端扫了一遍同类「铺满容器 + 叠在内容之上」的装饰层：目前只有这一处 + toast（toast 早已设为 None）。

## 实测（模拟器）

专属页第 1 行起播（高亮）→ 点该行行尾 dislike 图标 → **自绘弹窗正常弹出**
（dump 里出现「不喜欢 / 不喜欢这首歌 / 不喜欢这位歌手 / 取消」）。

## 教训

- **任何铺满父容器、叠在交互元素之上的装饰层（薄染 / 遮罩 / 高光）都必须显式 `hitTestBehavior(None)`**，
  否则只在「该层出现时」才会丢点击，很难在静态代码审阅里看出来。
- 同类历史 bug：迷你条/键顶高光横线、WebButton 宽度塌爆——都是「看得见的小装饰」引发大问题。
