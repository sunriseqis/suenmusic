## 4. 本轮发现并修复的两个问题

### 4.1 [BUG] 收藏页 `nextCursor: null` 崩溃（P0 级）

- **现象**：进收藏页直接显示「Cannot read property length of null」+ 重试按钮，重试无效
- **根因**：服务端 `GET /api/favorites` 到底时返回 **`nextCursor: null`**（`server/src/routes/favorites.ts:66` 三元 else 分支），客户端只防了 `undefined`（`page.nextCursor === undefined ? '' : page.nextCursor`），null 穿透后 `nextCursor.length` 抛错被 catch 显示成错误文案
- **修法**：`this.nextCursor = page.nextCursor ?? ''`（null/undefined 双兜底），`load()`/`loadMore()` 两处；修复后空态「还没有收藏 / 共 0 首」正常，291 首列表也正常
- **单子已更新**：T2 交接单 §1.2 补注 ⚠️

### 4.2 刘海/手势条安全区避让（用户指出）

- **现象**：`EntryAbility` 设了 `setWindowLayoutFullScreen(true)`（沉浸式全屏），内容从 y=0 起画；真机刘海/状态栏与底部手势条遮挡内容（模拟器实测 TabBar 与手势条重叠，修复后 TabBar 上移 98px = 该机手势条避让高度）
- **根因**：EntryAbility 早已把 `getWindowAvoidArea()` 动态值（`topAvoidHeight`/`bottomAvoidHeight`）写进 AppStorage 并有 `avoidAreaChange` 监听，但只有旧 WebView 壳 `Index.ets` 消费；原生 `NativeRoot`/`LoginPage`/`PlayerPage` 三个根组件全没消费
- **修法**：三个根组件加 `@StorageProp` + 动态 padding。px→vp 用 `UIContext.px2vp()`（**全局 `px2vp()` 已弃用**，第一版触发 4 条弃用 WARN 已换掉）
- **零硬编码**：避让值由系统按机型/折叠态实时推送，不同设备自动适配；验收依据 = 收藏标题 y178、播放页「收起」y213 均在状态栏（底 122px）之下

## 8. Lead 判定（针对执行方在 S4 单子里提出的问题）

**问**：「下拉刷新如纳入本阶段（S4），参考 Home.vue 阻尼参数（阈值 56 / 上限 88 / 阻尼 0.5）；是否纳入由 Lead 拍板。」

**判定：纳入 S4，且只做首页与收藏页两处。**

理由：
1. 两页都是「服务端列表 + 会更新」的形态，下拉刷新是移动端肌肉记忆，缺失最容易被感知；
2. 每日/搜索/队列是**会话型**列表（搜索有输入态、队列有拖拽手势），叠下拉手势会互相抢；
3. 阻尼参数直接照抄 Web 端（阈值 56 / 上限 88 / 阻尼 0.5）—— 视觉手感两端对齐正是 S4 的目标；
4. 实现落在 `List` 的 `onRefreshing`（ArkUI 原生 `Refresh` 组件），不与 `onReachEnd` 分页冲突。

**执行要求**：S4 实施 §十「视觉对齐」表时，下拉刷新排在「首页页头」条目之后做；
完成后在 S4 回执里注明两页各触发一次刷新验证（数据回填 + 不丢滚动位置）。
