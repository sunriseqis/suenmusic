# 2026-10-28 直链播放改造与动态音质开关设计方案

> 关联需求：彻底解决 iOS 播放卡死/超时、彻底移除本地回环代理与缓存层、对齐鸿蒙纯粹 CDN 直链播放、重排播放控制栏并实现动态音质档位切换。

---

## 一、 核心痛点与历史债务清理

### 1. 并发失控与 2GB 缓存暴满清理
- **根因**：`AudioEngine.swift` 在 `setQueue` 时循环调用 `makeItem`，内部调用 `LocalStreamProxy.shared.entry(trackId:)`，瞬间拉起全歌单（30+ 首）并发全量后台下载，导致本地 socket 端口和带宽耗尽，首曲请求 8s 抛出 504 Gateway Timeout，缓存塞满 2GB。
- **解法**：对齐鸿蒙端 `MediaPlayerCore.ets` 机制，**彻底移除 `makeItem` 内的预载**。严格执行「播哪首取哪首，切歌并发恒为 1」。

### 2. 彻底移除本地回环代理（LocalStreamProxy 与 AudioCacheStore）
- **定调**：按照用户拍板，**不再保留任何本地代理和边播边存代码，首期做纯粹的 CDN 直链流式播放（与鸿蒙端完全看齐）**。
- **操作**：
  1. 彻底移除 iOS 端 `LocalStreamProxy.swift`、`AudioCacheStore.swift`。
  2. AVPlayer 直接装载 `AVURLAsset` 消费 CDN `directUrl`。
  3. B 站等需要防盗链头的音源，通过 `AVURLAssetHTTPHeaderFieldsKey` 注入 `Referer: https://www.bilibili.com` 与桌面 UA。
  4. 播放依赖系统底层的内存短时缓冲，零额外文件 I/O，架构降到最简、最稳。

## 二、 动态音质选择系统规范（通过 /grill-me 闭环定稿）

### 1. 交互与生效机制
1. **全局偏好，下首生效**：
   - 用户在音质面板选定某一档位后，作为**全局默认偏好**保存在设备本地（`UserDefaults`）。
   - 当前正在播放的歌曲不打断、继续播完；**下一曲自动按新音质档位拉流**，避免播放中途重新缓冲或中断。
2. **如实展示与降级闭环**：
   - 播放主界面如实显示**当前实际播放的档位**（如当前歌曲无极高，实际降为标准，则主界面显示「标准」图标）。
   - 用户疑惑点击展开音质面板时，不可用的更高档位（如「原声」、「极高」）**显示为灰色禁用态**；
   - 若用户强行点击置灰档位，弹出统一 Toast 提示：「**当前歌曲不支持此音质**」；
   - **全局偏好不丢**：下一首如果具备对应档位，自动恢复为目标音质播放。
3. **多端设备隔离与差异化**：
   - 音质偏好分别独立保存在各端本地（iOS 保存在 `UserDefaults`，鸿蒙保存在 `Preferences`）；
   - iOS 设备天生屏蔽「原声 (FLAC)」档位（最高为「极高」），鸿蒙与 Web 端完整支持并默认选中「原声 (FLAC)」。

### 2. 音质档位与所需 SVG 素材清单

音质按钮支持通过**单色矢量 SVG**（Template 模式）渲染，系统自动适配主题与高亮色。需要准备以下 4 个音质状态图标：

| 内部 Level 标识 | UI 展示名称 | 码率 / 说明 | 建议素材文件名 | 素材尺寸建议 |
| :--- | :--- | :--- | :--- | :--- |
| `lossless` | **原声** | FLAC 无损 (~800k-1000k)，iOS 禁用/隐藏 | `quality_lossless.svg` | 24x24 pt 视口，纯色单色矢量 |
| `exhigh` | **极高** | 320 kbps (高保真 MP3/AAC) | `quality_exhigh.svg` | 24x24 pt 视口，纯色单色矢量 |
| `high` | **高** | 160-192 kbps | `quality_high.svg` | 24x24 pt 视口，纯色单色矢量 |
| `standard` | **标准** | 96-128 kbps (平价档/兜底) | `quality_standard.svg` | 24x24 pt 视口，纯色单色矢量 |

> 💡 **设计提示**：图标建议为 24x24 视口的纯矢量 Path（例如包含 "SQ"、"HQ"、"高"、"标" 或波形相关徽标设计），保持单色（默认透明背景 + 黑色/白色矢量填充），iOS 代码中会使用 `.renderingMode(.template)` 自动染上主题前景色和高亮色。未提供素材前，系统会自动使用优雅的文字/SF Symbol 胶囊兜底。

## 三、 播放页底部控制栏重排

按照用户裁定，播放页顶部保持现状（收起键 + 标题 + 更多菜单），**底部主控制栏重排为 7 个按键**：

```
[播放顺序]   [音质]   [上一曲]   [ 播放/暂停 ]   [下一曲]   [收藏/取消]   [播放列表]
  (mode)   (quality)  (prev)       (play)        (next)     (fav)       (queue)
```

- **宽度适配**：7 键采用柔性间距布局（中小键 32-36pt，上一曲/下一曲 40pt，主播放键 52pt），在 375pt 及以上屏幕上均能完美自适应。
- **音质键交互**：点击直接在上方弹出轻量 Popover / Sheet，列出可用音质，单选后即时勾选并 Toast 提示「已切换，下首生效」。

## 四、 服务端协议扩展（/api/resolve/:trackId）

1. **请求入参**：
   `GET /api/resolve/:trackId?quality={lossless|exhigh|high|standard}&platform=ios`
   - 不传 `quality` 时，默认按当前平台允许的最高档位解析（iOS 为 `exhigh`，其他为 `lossless`）。
2. **响应增加音质字段**：
   ```json
   {
     "ok": true,
     "source": "kugou",
     "directUrl": "https://...",
     "directHeaders": { "Referer": "https://..." },
     "directExpiresInSec": 3600,
     "currentQuality": "exhigh",
     "availableQualities": ["standard", "high", "exhigh"]
   }
   ```
3. **向后兼容**：旧版客户端不读这些字段完全不受影响。

## 五、 实施路线图

1. **Phase 1: iOS 播放内核瘦身（P0）**
   - 彻底删除 `AudioCacheStore.swift` 与 `LocalStreamProxy.swift`；
   - `AudioEngine.swift` 改为消费 CDN `directUrl`（支持 `directHeaders`），删掉 `makeItem` 中的并发预载；
   - 验证真机/编译通过。
2. **Phase 2: 服务端音质解析支持（P1）**
   - 扩展 `/api/resolve` 支持 `quality` 参数；
   - 酷狗与网易云返回歌曲具备的码率档位列表（`availableQualities`）。
3. **Phase 3: iOS UI 与音质选择器（P1）**
   - 底部控制栏重排 7 键；
   - 接入音质 SVG 图标（或兜底徽标）；
   - 实现音质弹出面板、置灰逻辑与 `UserDefaults` 全局偏好存储。
