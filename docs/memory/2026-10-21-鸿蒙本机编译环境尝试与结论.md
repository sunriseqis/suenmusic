# 2026-10-21 鸿蒙本机（Linux）编译环境尝试与结论

> **结论：放弃。** 技术上能拼到"只差一步"，但代价与不可靠性都不划算，已全部还原。
> 保留的唯一资产是 `scripts/check-arkts.mjs`（静态自检，见 §四）。

## 一、为什么想在本机编译

每轮改完代码要等本机 DevEco 智能体编译 15–20 分钟才能拿到 ERROR 列表，
而失败几乎全是**静态错误**。若能自验证，闭环时间能从"小时"降到"分钟"。

## 二、尝试路径与卡点（逐步记录，避免重走）

| 步 | 做法 | 结果 |
|---|---|---|
| 1 | `npm view @ohos/hvigor` / ohpm 查询 | **404 / 空** —— hvigor 不公开发布，随 DevEco 分发 |
| 2 | 从 Windows DevEco 打包 271 MB（`tools/{hvigor,node,ohpm}` + `sdk/default/openharmony/{ets,js,toolchains}`） | ✅ 包完整（63431 条目） |
| 3 | 用本机 node v24 跑 `tools/hvigor/bin/hvigorw.js` | ✅ **hvigor 6.26.8 在 Linux 跑通**（`--version` 正常、`Pnpm install success`） |
| 4 | 检查 ArkTS 编译器 | ❌ 只有 `build-win/bin/es2abc.exe`，**无 Linux 版** |
| 5 | 下载开源鸿蒙 `6.0-Release` SDK（2.32 GB，文件名带 `windows_linux` → 含 Linux 二进制） | ✅ 得到 Linux `ets/build-tools/.../ark/build/bin/es2abc`（`apiVersion 20`） |
| 6 | 拼 `sdk-mixed` = **v26 声明层 + Linux 编译器注入** | ❌ `00308018 SDK management mode has changed`（v26 组件是新格式 `metaVersion 3.0.2`） |
| 7 | 补上 `sdk/default/sdk-pkg.json`（内容向用户索取，`path: "HarmonyOS-26.0.0"`）+ 软链到 `openharmony` | ✅ **版本识别通过**，报错前进到"缺组件" |
| 8 | 报缺 `native,previewer` → 打桩（只放 `oh-uni-package.json`） | ❌ 改报缺 `toolchains,ets,native` |
| 9 | `--debug` 看真实需求 | ❌ 缺的是 **hmscore 层**：`getHmsSdkComponents` 要 `sdk/default/hms`（用户机器上 2.88 GB） |
| 10 | 绕行：影子工程改 `runtimeOS: OpenHarmony` + `sdk.dir` | ❌ 重回 `00308018` —— 新格式组件不被旧 OpenHarmony loader 接受 |

## 三、判断（为什么停）

1. **还差 2.88 GB 的 hms 层**，且是对 Windows 二进制做的"组件存在性"校验，之后再撞什么未知。
2. **拼装本质上是版本杂糅**：v26 声明 + v20 编译器 + Windows toolchains。就算编过，也不能证明"你 CI 能过"，
   只能证明"我这套拼装能过" —— **验证价值被稀释**。
3. 时间成本已超收益：每要一次文件就是一次人工往返，而这台机器本来也没有官方 Linux 支持。

## 四、保留下来的东西（这才是本轮真正的产出）

`scripts/check-arkts.mjs` + `npm run hw:check`：11 条规则，覆盖本轮所有编译失败类型
（`any/unknown`、`const` 重名、成员名撞 ArkUI 内置属性、`void` 上 `.catch`、伪 API、import 缺失、
入口两处不一致、颜色字面量、`@Watch` 顺序、括号平衡、SDK 缺 import）。
**0 误报基线 + 埋雷自测覆盖每一类**；首版曾因"剥字符串把路径/颜色一起剥掉"导致两条死规则（假绿），已修。

## 五、以后若真需要本机/远端编译，优先顺序

1. **用 CI 当编译 oracle**（最优）：用户 CI 是 **GitHub Actions 的 Windows runner**（`windows-latest` 本身就是 VM，
   里面装 DevEco 后由 `devecocli`/`hvigorw.bat` 出未签名 HAP）。推分支 → 读 job 日志即可。
   需要确认：workflow 触发方式、日志可得性（私有库需 token）。
2. 官方 **Linux command-line-tools**（若日后存在可获得渠道）：一套完整官方 SDK，不用拼装。
3. 官方 DevEco 只发 Windows/macOS —— **不要**再尝试用 Windows SDK 在 Linux 上拼装。
