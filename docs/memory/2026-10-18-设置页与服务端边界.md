# 设置页信息架构与服务端边界（2026-10-18）

## 一、边界（先定这个，其他都跟着它）

服务端只负责三件事：**数据同步、AI、cookie 下发**。

因此：

- 歌单导入（含 QQ 歌单）、去重、备份都是**客户端业务**，不能绕服务端
- 音源授权在客户端只做**只读状态展示**；登录由 Web 端完成并下发 cookie
- AI 模型在客户端只做**分配**（决策 / 复核两个下拉），不提供增删改

服务端挂了，本机数据仍是本机数据；文件、WebDAV 任何手段能还原即可。

## 二、设置页结构

无服务端：**单页，无 tab**。

```
播放     蓝牙歌词 / 缓存
资料库    黑名单 / 歌单导入 / 去重 / 数据备份
设备     应用更新 / 主题
账号     登入
```

有服务端：三档。

```
本机     与上面同一份，最后一行变登出
智能     画像（默认折叠）→ 调优 → AI 分配
高级     多服务端 → 音源授权（只读）→ 运行情况
```

一次性任务一律走**底部弹层**：登入、黑名单、歌单导入、去重、数据备份、主题、缓存。
判断标准：它是"做完就关的动作"，不是"常驻偏好"。

## 三、UI 收敛规则（防止再次各管各的）

```
按钮   只有主键（琥珀填充）与次键（面板底 + 发丝线）
容器   只有面板与裸行；禁止面板套面板
间距   行 44 / 行内 12 / 分区 24；禁止用空行当分隔
字阶   标题 26 / 铭牌 11 / 正文 14 / 次要 12
文案   界面不写说明；说明放 README
```

## 四、手势约定

- 服务端行：**右滑**露出「删除」（阈值 56px，最后一条保留）
- 服务端行：按住**序号**竖拖改优先级
- 行本身 `touch-action: pan-y`（不抢页面滚动），序号把手 `touch-none`

## 五、服务端断开的状态模型

```
没配地址 / 未登录     不提示（本地模式本就该安静）
已登录，请求失败       首次 toast「服务器无法连接」（60 秒节流）
持续断开             设置页标题下常驻「服务端已断开」
任一请求成功          常驻行消失
登出                 状态清零
```

实现：`api/client.ts` 派发 `suen:server-unreachable` / `suen:server-ok`，
App 维护 `ui.serverDown`，设置页只读这个状态。client 不依赖任何 store。

## 六、演示用假服务端

`vite.config.ts` 里的 `SUEN_MOCK=1` 中间件，在 dev server 的 `/api` 下返回 fixtures
（账号、会话、B 站授权、AI 模型、画像）。设备访问不到开发机的独立端口，
所以必须挂在 5273 上；地址填 `http://<开发机 IP>:5273` 即可看到服务端分节。

`web/public/design/settings.html` 是设置页的静态稿，仅设计评审用，上线前删除。
