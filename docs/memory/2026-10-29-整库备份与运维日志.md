## 一、备份形态（用户定型，旧逻辑备份作废）

旧的「收藏/黑名单 JSON 备份」已彻底下线（双端入口早砍、本轮代码清理 -812 行）。

唯一形态：
    整库 sqlite -> gzip -> 用密码加密 -> 后缀 .sm
    文件格式 v1：magic 'SUENMUSIC-BACKUP'(16B) + ver(1) + scrypt N(4BE)/r(1)/p(1)
      + salt(32) + nonce(12) + AES-256-GCM 密文 + tag(16)；头部 67B 作 AAD
      明文 = gzip(VACUUM INTO 的库副本)
      密钥 = scryptSync(pwd, salt, 32, N=16384, r=8, p=1)

### 密码逻辑（用户定型）

- 手动/自动备份：首次操作时弹框输入，落库后后续操作直接复用
- 恢复：每次都弹框输入，不落库，只用于本次解密
- 落库的密码用服务端主密钥再加密存 app_settings，任何接口不回传明文/密文（只回 hasPassword）

### 恢复语义（用户定型）

- 整库覆盖，不做账号映射
- 解密 -> 先 VACUUM INTO 一份 .pre-restore-<ts>.db 兜底 -> 覆盖 -> 重开并 migrate
- 轮换持久化 jwt secret（吊销全部刷新令牌 + token_epoch+1）-> 强制重登
- 返回 requiresRelogin，前端据此登出并提示「请用备份里的管理员账号登录」
- 错口令 -> 400，DB 一个字节都不改（验收硬标准）

### 附属能力

- 收藏导出/导入：只含收藏列表，增量合并（重复跳过），不含账号与凭据
- WebDAV 远端列表：GET /api/admin/backup/webdav/list -> {name, href, lastModified}
  （PROPFIND 只请求 getlastmodified，无 size 字段）
- 本地备份列表/恢复：GET /api/admin/backup/local/list、POST /api/admin/backup/local/restore

## 四、教训（延续 2026-10-28）

1. 两个服务端本地列表接口字段名不一致：status.localFiles 用 mtimeMs、local/list 用 lastModified，
   前端 ref<LocalArchiveFile[]> 赋值时类型对不上，子代理卡在 TS2322 反复空转。
   教训：同一领域的两个接口字段命名必须统一；子代理长时间不动要先跑类型检查看是不是卡住了。
2. bash -c 里嵌 heredoc 不可靠，静默无输出。用 node -e 或单脚本文件执行。
3. 日志落盘路径要实际验证：之前只查 journalctl 就断言「没落盘」，其实日志一直在 /tmp/suenmusic-server.log。
   现已改为 StandardOutput=journal，journalctl -u suenmusic -f 可直接看。
