# 2026-10-23 无源分流：连播跳过 / 手动点播不跳（用户复述的既有规则）

**用户原话**：「当列表播放的时候没拿到音源跳过，但是用户手动点这首歌就不跳」。

## 一、规则出处（确实存在，我此前漏了）

- **web**：`web/src/stores/player.ts:1214` `startCurrent({ noSkip: true })` —— 显式点播走 noSkip；
  `handlePlaybackError` 里 `opts.noSkip` 分支（:804 / :904）直接 `return false`（不跳），
  并 `anchorCandidate = track` 给锚定入口。
- **hw 文档**：`docs/dev/hw-native-client.md` §五 命脉 2 原写「无源曲自动跳过（提示 + 600ms 接下一首）」——
  **只写了连播那一半**，漏了「手动点播不跳」，我照着写实现，于是把用户想锚定的歌也跳走了。
- 已在 `docs/dev/hw-native-client.md` 把这条改成两分支表述（连播跳过 / 手动点播停在当前曲）。

## 二、实现（`MediaPlayerCore`）

新增意图字段 `manualLoad: boolean`：

| 置 `true`（显式点播 → 失败不跳） | 置 `false`（自动装载 → 失败跳过） |
|---|---|
| `setQueue()`（用户点歌起播） | `advance(auto)`（自然接续 / 上下一首） |
| `jumpTo()`（用户点某一行） | `restoreSession()`（冷启动续播） |
| `retryCurrent()`（点重试 / 锚定后重装） | `removeAt()` 删当前曲后的原地重装 |

`settleFailure()` 分流：
- **自动装载**且 `hasWayOut`（`index+1<len || list-loop || shuffle`）→ 通知「《X》…已自动跳过」+ 600ms 后 `next()`；
- **显式点播**或已无路可走 → 通知 + **停在当前曲不切歌**，错误行给「重试 / 跳过」，可就地锚定；
- 两条都以 `FAIL_GRACE_MS=2500` 挂起窗口为前提（窗口内自愈则静默撤销）。

- 「跳过/不跳过」是**两条路径**，不是一条策略。以后凡是「失败怎么办」的策略题，
  **先查 web 的 opts.noSkip 分支**再动手，别只按文档里那半句实现。
