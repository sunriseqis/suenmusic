## 一、四条反馈逐条

### ① 不喜欢弹窗用的是系统弹窗，风格割裂 → 换自绘哑光弹窗

- 新组件 `common/DislikeDialog.ets`（`@ComponentV2`）：scrim 背板 + `Tokens.panel` 卡片 + 发丝线描边
  + 圆角 `radiusLg`，两个选项各带图标/主行/说明副行，第三行「取消」无厚度；无歌手信息时「这位歌手」置灰。
  全部颜色走 Tokens，与页面其余浮层同一套质感。
- 接线：`TrackItem` 不再自己弹系统框，只上报 `onDislikeAsk`；**页面持有弹窗状态**——
  `DailyPage`（`@State dislikeAsk: Track`）与 `PlayerPage`（沿用 `sheet === 'dislike'`）。
- `PlayerPage` 原来的「贴推荐卡上弹的小浮层」（`dislikePop`，offset -100%）**整块删除**——
  它正是用户说的「没有弹窗」：浮层被卡片边界裁掉/看不见。现在统一走页面级居中弹窗。

### ② 搜索按钮对齐播放页播放键风格，且不能比搜索框高

`SearchPage`：`NeuBtnChrome.PRIMARY`（琥珀填充块，全端独一份）→ **`GRADIENT`**（与播放页主播放键
同一材质：panel2→panel 渐变凸面 + `Tokens.accent` 字形）；`boxSize` 钉成 `Dim.touchMin`，
**= `NeuInput` 的框体高**（`NeuInput` 根 Row 也是 `Dim.touchMin`），不再显高。

### ③ 专属页不喜欢没弹窗 + 提示漂移

- **没弹窗**：两条路径都修——列表行（`DailyPage`→`TrackItem`）走页面级自绘弹窗；
  播放页推荐卡（原 `dislikePop`）删掉换成同一弹窗。
- **提示漂移**：根因是**系统 toast**——沉浸式全屏窗口下 `promptAction.showToast` 实测会漂到屏幕
  顶部偏右，`alignment: Alignment.Bottom` 也没治住。改为**自绘轻提示** `common/AppToast.ets`：
  AppStorage 双键（文本 + 自增序号）→ `NativeRoot` 根 Stack 最后一层渲染，底部居中、
  底距 = 132 + 底部避让区，`hitTestBehavior(HitTestMode.None)` 不吃点击，2.2s 自动收。
  **8 个页面的 toast 全部切过去**（PlayerPage / DailyPage / SettingsPage / HomePage / SearchPage /
  FavoritesPage / CollectionPage / NativeRoot），系统 toast 一处不剩。
