## 一、 核心需求与设计原则

根据用户明确指令与多轮裁定，本轮改造确立并落地了以下铁律：

1. **音质切换严格「下一首生效」**：
   - 用户在播放界面切换音质只修改本地全局期望档位（`preferredQuality`），**绝不原地重新加载或打断正在播的流**；
   - 彻底避免频繁切流引起的网络卡顿、缓冲转圈与听感割裂。
2. **播放缓存与取流优先级**：
   - **本地缓存（`fd://`）拥有绝对最高优先级**，只要本地有缓存，不管当前选什么音质，直接秒播本地零流量；
   - 无本地缓存时，带期望 `quality` 找服务端拿 CDN 直链（`directUrl` + `directHeaders`），客户端直接连接上游 CDN 播放；
   - **绝不走服务端代理流**（`/api/stream` 仅作极端异常兜底）。
3. **音质图标常亮与视觉对齐**：
   - 播放界面的音质按钮**默认永久高亮**（金色 `Tokens.accent`），无论当前生效的是什么音质；
   - 使用用户提供的 4 个官方矢量 SVG 胶囊图标（`音质-原声.svg`、`音质-sq.svg`、`音质-hq.svg`、`音质-标准.svg`）；
   - 音质面板中，当前曲目不支持的更高档位显示为半透明置灰（`opacity: 0.4`）。
4. **拒绝上游无效白请求（按会员等级精确请求）**：
   - 严禁向上游平台盲目请求其无法提供的档位（如非 VIP 请求无损），避免上游下发 30 秒试听或 404，浪费数百毫秒往返甚至触发风控。

## 二、 上游音源改造与会员三级熔断

### 1. 哔哩哔哩（Bilibili）音源
* **天然上限**：UGC 视频的 DASH 音频流最高为 ~192kbps AAC（等效 256k-320k MP3 听感），**无裸 FLAC 无损流**；
* **标准档精准匹对**：
  - 用户选 `standard` 时：从 DASH 音频流中精准选取最低带宽音轨（Band 30216，~64kbps），返回 `currentQuality: 'standard'`；
  - 用户选更高音质时：选取最高带宽音轨（Band 30280，~192kbps），返回 `currentQuality: 'high'`；
  - 可用档位明确标定为 `['standard', 'high']`，SQ 和原声在客户端自动置灰；
  - 修复了 `resolveFromAnchor` 漏传 `options.quality` 导致选标准音质按钮显示 HQ 的历史缺陷。

### 2. 网易云音乐（NetEase）音源
* **非 VIP / 游客态**：
  - 最高上限为 `exhigh`（320kbps MP3）；
  - **坚决不向上游发送 `lossless` 请求**（避免 30 秒试听和 404 白白消耗网络）；
  - 可用档位下发 `['standard', 'high', 'exhigh']`，客户端「原声」档位自动置灰。
* **黑胶 VIP（`vipType >= 10`）**：
  - 用户选 `standard` 优先拿 128k；选 `exhigh` 拿 320k；选 `lossless` 才请求 FLAC 无损；
  - 提取并保留网易云返回的真实音质等级（`level`）与码率，下发真实 `currentQuality`。
* **Vendor 参数修正**：
  - 去除 `song_url_v1.js` 中写死的 `encodeType: 'flac'`，标准/极高采用 `mp3`，无损采用 `flac`。

### 3. 酷狗音乐（Kugou）音源（三级会员熔断）
* **无会员（未登录 / 凭据失效 / 会员已到期）**：
  - 在 `kgChain` 与 `qqChain` 入口处前置读取 `readKugouLoginState()`；
  - 状态非 `'ok'` 时直接判定酷狗不可用，**直接跳过酷狗转 B 站兜底**，消除 300~600ms 无效上游请求与 60s 试听片段抛弃延迟。
* **普通 VIP（畅听 VIP，`isVip === true && !svipActive`）**：
  - 尝试音质序列强行锁定为 `['128']`，绝不打 `flac`/`high`/`320`；
  - 可用档位仅下发 `['standard']`，高品、SQ、无损全部自动置灰。
* **概念版 SVIP（`svipActive === true`）**：
  - 开放全码率尝试序列（无损 `['flac', 'high', '320', '128']`，极高 `['320', '128']`，标准 `['128']`）；
  - 可用档位全量下发，满足高保真听音需求。

## 三、 客户端架构与取流逻辑闭环

### 1. 鸿蒙端（OpenHarmony / `hw`）
* **本地缓存秒播**：`MediaPlayerCore.ets` 判定 `url.startsWith('fd://')` 时直接赋给播放器，绕过所有网络解析；
* **直链解析超时放宽**：`resolveDirect` 竞速超时从 800ms 放宽至 3000ms，杜绝冷解析时误回退代理流；
* **直链装载**：通过 `media.createMediaSourceWithUrl(direct.url, direct.headers)` 直接喂给系统 `AVPlayer`；
* **图标与交互**：
  - 播放条与全屏播放页采用官方 SVG 图标；
  - `.fillColor(Tokens.accent)` 确保生效档位始终高亮；
  - 音质弹窗每行展示对应胶囊图，置灰档位禁止点击并弹出「当前歌曲不支持此音质」。

### 2. iOS 端（Swift / `ios`）
* **UI 规约对齐**：
  - iOS 端 UI 只有「极高 (SQ)」、「高 (HQ)」、「标准 (标)」，**天然没有「原声」选项**（因 AVPlayer 无法流播 HTTP 裸 FLAC）；
  - 客户端最高仅会发 `quality=exhigh` 请求，服务端自然返回 320k MP3，无需繁琐平台硬守卫。
* **直链时序缺陷修复（杜绝切歌走代理流）**：
  - 修复前：`next()`、`prev()`、`jumpTo()` 直接触发底层同步构建 `AVPlayerItem`，因无直链回退至 `/api/stream/`；
  - 修复后：
    1. `jumpTo` 前置异步 `resolve` 直链并注入 `engine.setDirect`，然后再起播；
    2. `emitTrackChange` 启播时静默触发 `prefetchNextDirect` 预取下一首直链，自然切歌秒起播且 100% 走 CDN 直链。
* **图标对齐**：
  - 同步 4 套 SVG 入 `Assets.xcassets`；
  - `qualityButton` 采用 `.renderingMode(.template)` 配合主题高亮色渲染；
  - 音质弹窗列表补齐对应胶囊图标展示。
