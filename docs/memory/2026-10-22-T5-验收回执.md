## 【⚠️ Tab 动效规格偏离记录】（Lead 知悉）

S4 §二原规格「Tab 切换淡入+上移 8vp」。实施中经 4 轮真机迭代，用户逐轮否决：

1. 整 Tabs 内容上移 8vp → 「向下移动抖动」
2. 仅内容区上移 → 「还是抖」
3. 纯 OPACITY 0.6→1 淡入 → 「闪动」
4. 方向感知滑入 48vp → 「还是抖动」

**用户拍板终稿（原话「这就可以了」）：页面零动效，仅 tab 按钮自身动效**——tabBuilder 选中图标 `.scale(1.15)` + accent 变色 + `.animation({duration: Motion.standard, curve: Motion.curve})`；onChange 仅 `this.currentTab = i`。

即 S4 §二「Tab 切换淡入+上移」一条**未按原规格执行**，以用户实测反馈为准。任何页面级位移/透明度动效在该设备上均被用户读作「抖动/闪屏」，后续单子如涉 Tab 动效请沿用「页面零动效」口径。

## 【首轮验收发现并修复：搜索静默失败】

**现象**：verify_ui 首轮，搜索框输入 `zzqqxxww` 后点击「搜索」/键盘搜索键，UI 纹丝不动停在最近搜索列表。

**根因**（`pages/SearchPage.ets` doSearch，两处叠加的潜伏缺陷，非 T5 改坏——T5 前后提交流程零改动）：

1. `searched` 只在成功时置 true；首搜**在途**和**失败**时 `!searched` 分支仍渲染最近搜索列表 → 骨架屏条件 `searching && sliceCount()===0` 排在 `!searched` 之后永远不触发；首搜失败错误被完全吞掉（err 分支要求 searched=true），观感即「点了没反应」
2. `lastQuery` 只在成功后赋值 → 失败后「重试」按钮 `doSearch(this.lastQuery, 1)` 是空操作

**修复**（SearchPage.ets:177-226, 516-527）：

- 骨架屏分支前置到 `!searched` 之前：首搜发起立即离开「最近搜索」页，给出在途反馈
- `lastQuery = q` 前置到请求发起前：失败后重试有词可试
- catch 里 `first && sliceCount()===0` 时 `searched = true`：首搜失败错误+重试按钮可见
- doSearch 入口/失败补 hilog（原搜索链路零日志，排障全靠猜）

**复验**：verify_ui 第二轮步骤 1-2 通过——zzqqxxww → 骨架屏 → 「没找到相关歌曲/换个关键词试试」空态（截图核验：magnifyingglass 居中无裁剪）；周杰伦 → 单曲结果列表。修复前静默的失败路径现可自证（hilog `SuenMusic_Search`）。
