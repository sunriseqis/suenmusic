# iOS 直连播放：从「进度不动」到能播，以及它的架构上限（2026-10-19）

> 前半段（`setDirectUrl` 缺失、-1002）见 `2026-10-19-iOS直连模式setDirectUrl缺失.md`。
> 本条记录后面几层坑，以及最终确认的边界。

## 一、能播需要同时满足的五件事

直连模式（`baseUrl` 为空）下，iOS 侧要出声，以下缺一不可：

1. **Web 调 `SuenAudio.setDirectUrl` 时原生真的实现**，并把地址记进 `AudioEngine.tracks[i].directUrl`
   与 `LocalStreamProxy.directUrls`。
2. **播放地址优先走本地回环代理**（`http://127.0.0.1:<port>/stream/<id>`），而不是把 CDN 地址直接交给 AVPlayer。
   实测 AVPlayer 直连 B 站只收到 426 字节的探测响应就放弃（`-1002` / 停在 waiting）。
3. **代理按字节判 `Content-Type`**（已有 `playableContentType`），不能透传 `application/octet-stream`。
4. **首次整首下载不带 `Range`**，续拉才带（见 `docs/architecture` 里 iOS 的 40KB/s 限速实测）。
5. **`player.automaticallyWaitsToMinimizeStalling = false` + `playImmediately(atRate:)`**。
   否则 B 站 fMP4 会长期停在 `AVPlayerWaitingWhileEvaluatingBufferingRateReason`——
   现象就是「进度条一动不动」，但音源、代理、Content-Type 全部正常。

## 二、队列不能塞占位条目

`AVQueuePlayer` 会预加载后续 item，失败后**自动推进**。直连模式下后续曲目还没有直链，
如果一起入队：

- 每 100ms 跳一首，直到 Web 的重试上限；
- `itemIndex` 映射错位，`currentItem` 指到别的曲目（表现为「点 A 播 B」）。

修法：`setQueue` / `rebuildQueue` 在 `baseUrl.isEmpty` 时**只入队当前曲目**；
无直链的占位 item 用 `suenmusic://invalid-stream/<id>` 兜底，且失败**不**上报 error
（避免 Web 误判跳曲）。

## 三、换条目不 seek → 进度继承

`AVQueuePlayer` 的时间轴是全局的。`reloadCurrent` 原来只有 `positionMs > 0` 才 seek，
换歌时传 0 就什么都不做 → 上一首 4:19 结束、下一首从 4:20 继续走，但没有声音。

修法：**无条件 seek**（`reloadCurrent` 与 `rebuildQueue` 都要）。

## 四、不要在 `syncNativeAdvance` 里直接 `startCurrent()`

曾按「原生回报 trackChange → Web 重新解析」实现自动接续，结果是：
`startCurrent → load → reloadCurrent → 原生 emit trackChange → syncNativeAdvance` 互相触发，
**每 30ms 重建一次队列**，整首歌起不来（日志：8 秒 137 次 `makeItem`）。

即使加 1500ms 防抖也只是降低频率，根因是闭环。该改动已回退，不要加回来。

## 五、锁屏上限：直连模式无法无限接续

这是架构层面的，不是 bug：

- 解析在 **WKWebView 的 JS** 里（B 站搜索/取流签名、网易云取流）；
- 锁屏后 WebView 的 JS 被系统挂起；
- 原生在后台音频模式下仍活着，但**它不会解析**，只能播已经拿到 URL 的曲目。

所以「预取下一首」只能把断点往后推，预取 10 首 ≈ 30–40 分钟。队列总会用完。

业界（Apple Music / Spotify / 网易云 / QQ 音乐 / YouTube Music）解析都在**服务端或原生**：
锁屏时要下一首，原生自己再发一次 HTTP 请求拿新的签名 URL，不需要 JS。

**结论**：服务端可以拆仓，但 App 运行时必须继续有一个可用的 `baseUrl`；
直连只适合作为「无服务端时的降级」，并接受上述上限。

## 六、iOS 桌面卡片已下线（2026-10-19）

按用户决定，App target 的 `Embed Foundation Extensions` 阶段已移除，
产物不再包含 `PlugIns/SuenMusicWidget.appex`。`ios/App/SuenMusicWidget/` 源码与
`SuenMusicWidget` target 暂时保留（未参与构建），需要恢复时把 Embed 阶段加回即可。

卡片下线的原因：WidgetKit 的时间轴粒度做不到逐句同步，即使每秒推算位置，
歌词滚动与 App 内仍有可感知偏差；原生灵动岛（Now Playing）体验更好。
