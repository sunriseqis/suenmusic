# 2026-10-27 iOS 多服务器频繁切歌锁死：切服状态污染修复

> 用户实测复现特征：3 个服务器地址（局域网/反代/CF 隧道），频繁切歌后 CF 地址锁死、切局域网显 HTTP 400、切反代显不可用，**卸载重装即愈**、再切歌复现。此前把 400 理解成了服务端 badRequest，用户纠正——真因在 iOS 客户端本地状态污染。

## 根因（iOS 代理排查，Lead 复核 diff 通过）
1. **切服残留（成立，主因）**：LocalStreamProxy.configure 只换 base/token 两个字符串，旧 base 的在途 StreamCacheDownloader 与伺服连接全部存活；换服后旧下载器打「新 base + 旧落盘偏移」，旧 token 打新 base → 400/401；内存旧 entry 跨代命中直到重装清 Caches 才恢复——与「卸载重装即愈」精确吻合。
2. **CF 风控（部分成立）**：续拉固定 0.4s×4 次且对上游 4xx 也照样重试，频繁切歌 + stall 自愈叠加，短窗内大量失败请求把 CF 隧道地址轰进风控锁死。
3. URLSession.shared 缓存重放（不成立）：APIClient 全程 reloadIgnoringLocalCacheData、流下载 ephemeral 会话、代理回 no-store。
4. 令牌污染（不成立）：每次 setQueue/rebind 均带新 token。

## 修复（仅 ios/SuenMusic/Player/AudioCacheStore.swift，+81 行）
- 配置代际 configGeneration：configure 检测 base 变更 → invalidateForServerSwitch() 作废全部在途下载 + 内存条目（磁盘完整缓存保留跨服命中）+ close 全部旧伺服连接；下载器携带启动代际，startTask/retry 前核对 isStale()。
- 退避：0.4s → 指数放大（上限 8s）；上游 4xx（416 除外）不再续拉重试，杜绝错误请求放大。

## 服务端配合项（未改代码）
- /api/stream 对无效/过期 t= 令牌应回 401 而非 400（语义区分「重试无用」）；
- CF 已触发的风控锁需在 CF 侧解封；客户端退避只防复发。

## 纪律
- 用户报「400 你理解错了」= 复现特征与代码推断冲突时，必须先要现场证据（报错原文/场景）再定根因，不能拿代码里搜到的 badRequest 就当答案。
- 部署状态：server 端修复已重启生效（pid 3403155）；iOS 端 AudioEngine 预拉 + AudioCacheStore 切服作废需重打包装机。
