# 2026-10-23「怎么」无声无错但系统在走进度 —— 卡死看门狗 + 播控状态未回落

**用户报的 bug（旧版也有）**：这首《怎么》（洛伊Kloe）app 里不播、不出声、**不报错**，
但系统媒体组件显示在播放、进度在走。

## 一、这首歌到底怎么了（数据侧已确认）

- 曲目 id `qq_0038fUAb3hghog`（`怎么` / 洛伊Kloe / 205s）。
- `play_sources`：`ok=0, source=bilibili, bvid=BV1ma4y197Sr, reason=below_threshold, audio_url=''`。
- 服务端日志：`上游解析 … ok=false reason=below_threshold 最佳候选置信度 55 低于阈值 60` →
  `GET /api/stream/qq_0038fUAb3hghog 503`（每次 0.7s 返回）。
- 也就是说：**这首本来就没有可播音源**（B 站置信 55 不足 60），这是我们「手动锚定」要解决的典型曲目。

## 二、为什么表现为「不报错 + 系统在走进度」

1. **AVPlayer 对 503 的反应不统一**：多数情况抛 error（走 fail → 有提示），
   但这首实测既不到 `playing`、也不抛 error（卡在装载中途）→ 我们的 `fail()` 永远不会被调用 →
   **app 侧静默、无提示**。
2. **系统卡片的进度是它自己外推的**：我们只在 `timeUpdate` 里 `updatePlaybackStateFromNative(wantPlay=true, pos…)`，
   一旦上报过 playing，系统媒体卡片就会按 elapsed 自行走秒；而我们失败/停止时**没有把 paused 状态推回去** →
   卡片一直显示在播、进度一直涨。这就是「系统在播、app 不响」的两半原因。

## 三、修法（`MediaPlayerCore`）

- **卡死看门狗** `STALL_MS = 6000`：每次装载挂一个定时器，`STALL_MS` 内没进 `playing`（且仍是本次装载、
  状态不是 playing）→ 记 `装载超时 … 按失败处理` → 走 `fail()`：
  手动点播 → 停在当前曲 + 通知 + 错误行「重试 / 跳过 / 修正音源」；连播 → 通知后跳过。
  进入 `playing` / 重新装载 / 落定失败 / `stop()` 都会清掉看门狗。
- **失败落定必须回落播控状态**：`settleFailure()` 里补 `this.publishState()`（`wantPlay=false` + 当前进度 + 时长），
  系统媒体卡片立刻变「已暂停」，不再自己外推进度。

## 四、复测要点（用户侧）

拿《怎么》手动点播：约 **6~10 秒**内应出现 ①系统通知「没有匹配音源」②播放页错误行
「《怎么》没有可播放的匹配音源，可点『重试』或『更多 → 修正音源』手动锚定」③**系统卡片停在已暂停**；
然后就能从「更多 → 修正音源」给它锚一个能播的视频。
