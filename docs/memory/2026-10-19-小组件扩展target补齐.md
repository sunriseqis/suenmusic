# 小组件扩展 target 补齐（2026-10-19）

> **同日更新**：卡片已下线，App target 的 Embed 阶段已移除（产物无 appex），
> target 与源码保留但不参与构建。原因见
> `2026-10-19-iOS直连播放链路与锁屏上限.md` 第六节。

## 现象

主屏「添加小组件」里搜不到 SuenMusic，`App.app` 内没有 `PlugIns/`。
计划文档 `docs/plan/2026-10-19-小组件扩展未建target.md` 记录过根因：
`ios/App/SuenMusicWidget/` 只有源码，工程里从未建过扩展 target。

## 本次做法：直接写 `project.pbxproj`，不依赖 Xcode GUI

`scripts/build-ios.mjs` 只用 `-target App` 构建，因此扩展必须作为**依赖 target**
挂在 App 上，构建时自动带上并嵌入。

新增内容（id 统一用 `5E…` 前缀，与既有原生文件同一套）：

1. `PBXNativeTarget "SuenMusicWidget"`，`productType = com.apple.product-type.app-extension`，
   product 为 `SuenMusicWidget.appex`。
2. App target 的 `PBXCopyFilesBuildPhase`（`dstSubfolderSpec = 13`）+
   `PBXTargetDependency` / `PBXContainerItemProxy`，产物落到 `App.app/PlugIns/`。
3. Sources 归属：
   - App target：`SharedNowPlaying.swift`、`PlaybackIntents.swift`（就地播放命令）
   - Widget target：上述两个 + `SuenMusicWidget.swift`
   - 同一文件在两个 target 需要**两个 PBXBuildFile**，不能复用。
4. 文件引用统一挂到独立 group `SuenMusicWidget`（`path = SuenMusicWidget`），
   原 App group 里的 `../SuenMusicWidget/...` 相对引用已移除。
5. `CODE_SIGN_ENTITLEMENTS` 两边都接线：App → `App/App.entitlements`，
   Widget → `SuenMusicWidget/SuenMusicWidget.entitlements`
   （两者都是 `group.com.suenmusic.app`；此前 App 侧是孤儿文件，App Group 实际不生效）。
6. `IPHONEOS_DEPLOYMENT_TARGET = 15.0`，与 App 的历史口径一致。
   （曾误设 26.0，导致产物只能装 iOS 26+，见
   `2026-10-19-部署目标被抬到26.0.md`；实测 15.0 下编译通过。）

## 顺带修掉的源码错误

`SuenMusicWidget.swift` 因从未参与编译，藏了一处编译错误：

```swift
// 错：frame(width:maxHeight:) 不存在
.frame(width: 56, maxHeight: .infinity)
// 对：拆成两次
.frame(width: 56).frame(maxHeight: .infinity)
```

**教训**：新增 target 后必须真编译一次，不能只看 `xcodebuild -list`。

## 第二个首装错误：appex 缺 `CFBundleExecutable`

装到模拟器时报：

```
SuenMusicWidget.appex has missing or invalid CFBundleExecutable in its Info.plist
```

可执行文件其实已经在包里（`SuenMusicWidget.appex/SuenMusicWidget`），
但 `SuenMusicWidget-Info.plist` 少了 `CFBundleExecutable` 键——构建系统
**不会**替 appex 注入它（主 App 的 Info.plist 本来就有，所以只坑扩展）。
补上：

```xml
<key>CFBundleExecutable</key>
<string>$(EXECUTABLE_NAME)</string>
```

复测：`simctl install` 成功，`simctl spawn pluginkit -m -i
com.suenmusic.app.widget` 输出 `com.suenmusic.app.widget(1.0)`。

## 验证口径

```bash
cd ios/App
xcodebuild -project App.xcodeproj -target App -configuration Debug \
  -sdk iphonesimulator SYMROOT=build/widget-check \
  CODE_SIGNING_ALLOWED=NO build
ls build/widget-check/Debug-iphonesimulator/App.app/PlugIns
```

验收点：出现 `SuenMusicWidget.appex`；其 `CFBundleIdentifier` 为
`com.suenmusic.app.widget`，`NSExtensionPointIdentifier` 为
`com.apple.widgetkit-extension`，版本号与 App 一致（`build-ios.mjs` 的
命令行覆盖对依赖 target 同样生效）。

## 仍需人工确认

App Group `group.com.suenmusic.app` 必须在开发者账号里存在，且两个
Bundle ID 的描述文件都带上该 capability；代码侧已无遗漏，签名侧无法在仓内验证。
