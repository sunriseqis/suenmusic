# 2026-10-24 T7 客户端：检查更新（有新版交给系统浏览器下载，用户自行侧载）

**用户定的形态**：更新调用系统默认浏览器下载到本地；包依然是未签名，用户自己用移动端侧载工具安装。
→ 所以**不做**应用内下载/校验/静默安装（也避开三方应用无安装权限的坑）。

## 实现

- `Models`：新增 `UpdateCheckReply` / `UpdateArtifact` / `UpdateVersionPair`（对齐服务端 `/api/update/check` 返回）。
- `APIClient`：`checkUpdate(versionName, versionCode, force)`（`force=1` 才让服务端去上游核对）、
  `buildUpdateDownloadUrl(downloadPath, token)`（浏览器发不出请求头，只能靠短期令牌）。
- 设置页「高级 → 设备」新增 **检查更新** 行：行尾显示 `v<当前版本>` / 检查中… / 已是最新 / 新版本 x.y.z / 失败原因；
  点击 → 查版本（`bundleManager.getBundleInfoForSelfSync`）→ `checkUpdate` → 有新版则 `startAbility({action:'ohos.want.action.viewData', uri})` **交给系统浏览器**。
- 错误文案：5xx 优先显示服务端人话；GitHub 404（仓库无 Release）翻成
  「仓库暂无发布产物（上传 SuenMusic-v<版本>-release.hap 到 Releases 即可）」。
- 顺带：环境订阅里那次**无用的卡片重推已删除**（实测无效，白付一次表单刷新），只保留系统态缓存同步。

## 服务端配置（本次已做）

- `server/.env`：`SUENMUSIC_UPDATE_GITHUB_REPO=sunriseqis/suenmusic`（此前为空 → 一直 502），已重启服务端。
- **仍缺**：GitHub Releases 里要有一个 asset，**命名必须是** `SuenMusic-v<版本>-release.hap`
  （服务端 `github-update.ts` 按这个名字筛）。当前仓库没有 Release → API 404 → 客户端显示上面那句人话。
  注意：本地产物叫 `-unsigned.hap`，上传到 Release 时**要改名**成 `-release.hap`。
