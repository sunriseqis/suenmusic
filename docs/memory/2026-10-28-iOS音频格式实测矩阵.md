# iOS 音频格式实测矩阵（2026-10-28）

> 结论先行：**iOS 端只有 MP3 与 fMP4 能播，FLAC 与 OGG 都不走进度。**
> 因此 `preferMp3`（iOS 剔除 lossless）与酷狗 `need_ogg=0` **必须保留**。

## 一、测试方法（绕开一切中间环节）

把四种格式的**真实音频文件**直接下载下来，按 App 缓存命名规则（`safeStem(trackId).bin` + 同名 `.json` meta）
注入模拟器里 App 的缓存目录，让 App 走 `fd://` 本地播放路径 —— **不联网、不重新下载、不经服务端解析**，
纯粹测 AVPlayer 能不能播这个文件。四种格式各绑一首真实曲目：

| 曲目 | 注入格式 | 大小 |
| :-- | :-- | --: |
| 当世界年纪小（任素汐） | MP3（对照组） | 11.3 MB |
| 宝贝爱人（A-Lin） | FLAC（quflac 裸流） | 24.2 MB |
| 多久没有谈天光（杨千嬅） | OGG（qu320 的 ogg） | 11.5 MB |
| 淘金小镇（周杰伦） | fMP4（B 站 -1-30280.m4s） | 3.6 MB |

## 二、结果（实听）

| 格式 | 实听 | 备注 |
| :-- | :-- | :-- |
| MP3 | ✅ 有声有进度 | 对照组 |
| fMP4（m4s） | ✅ 有声有进度 | B 站 DASH 分片可播，此前「fMP4 播不了」的猜测不成立 |
| **FLAC** | ❌ **不走进度** | 能解析但播不动 |
| **OGG** | ❌ **不走进度** | 解析阶段即 Operation Stopped |

## 三、被推翻的两个判断（记录以免重犯）

1. **「iOS 11 起原生支持 FLAC，所以 iOS 可以放开无损」—— 在本链路不成立。**
   通识层面 iOS 对 FLAC 有支持，但在我们这套「无扩展名 .bin + AVPlayer」的实际链路上，FLAC 实听播不动。
2. **「解析成功 = 能播放」—— 错。**
   用 AVURLAsset.load(.duration) 做过一轮解析层测试，MP3 / FLAC / fMP4 全部返回 OK、只有 OGG 失败，
   据此推断「FLAC 可用」并被实听证伪。**load 通过只说明容器/编码被识别，不代表能解码播放。**
   今后判断格式可播性，只认实听或 AVPlayerItem 起到 readyToPlay 且 currentTime 推进。

## 四、第二轮：排除「无扩展名嗅探失败」这个变量（已排除）

第一轮注入的文件统一存成 .bin（无扩展名），AVFoundation 靠内容嗅探判类型 —— 为排除「是嗅探失败而非格式不支持」，
做了第二轮对照：把**同样的字节**用本机 HTTP 服务下发，带正确 Content-Type（`audio/x-flac` / `audio/ogg` / `audio/mpeg`），
服务端解析缓存指向该地址，App 清空本地缓存后走网络播放。

| 格式 | Content-Type | 实听 |
| :-- | :-- | :-- |
| MP3 | audio/mpeg | ✅ 有声 |
| FLAC | audio/x-flac | ❌ **无声** |
| OGG | audio/ogg | ❌ **无声** |

**结论：与扩展名/MIME 无关，FLAC 与 OGG 就是 AVPlayer 播不了。**
`preferMp3`（iOS 剔除 lossless）与酷狗 `need_ogg=0` 必须保留，不再讨论放开 iOS 无损。

（第二轮 URL 形如 `http://127.0.0.1:3999/aN`，不含 `.flac`/`.ogg` 特征串，因此绕过了服务端 `isFlacUrl` 守卫；
测试完成后注入行与服务已清理。）
