## 一、本批修的问题（按用户报障顺序）

### 1. 播放模式只有三档 → 补齐五档
- 枚举扩到与 hw `MediaPlayerCore.PLAY_MODES` 完全一致：
  `order / shuffle / repeat-one / list-loop / shuffle-once`
- 新增 `playOrder`（逻辑播放顺序表）：非随机 = 原序；随机 = **当前曲打头 + 其余洗牌**，切回顺序模式自动还原，不改列表显示顺序。
- `nextLogicalIndex()` / `previousLogicalIndex()` 统一驱动「曲末接续 / 上一首 / 下一首 / 锁屏按钮可用性」四处边界。
- 验收：`SUEN_CYCLE_MODE=5` 钩子逐档打印，日志五档文案与 hw 一致（随机播放/单曲循环/列表循环/随机不重复/顺序播放）。

### 2. 单曲循环：音源比元数据短
- 现象：页面时长显示 3:08（元数据），实际 2:56；播完后**音频重头、进度条冻在结尾**。
- 根因一（时长）：`currentItemDurationMs()` 让**服务端响应头**优先，而服务端在无锚点时会用元数据兜底 → 把 3:08 当真实值。
  → 改为 **`AVPlayerItem.duration` 优先** → 响应头 → 元数据。
- 根因二（进度条冻住）：单曲循环用 `seek(to: .zero)` 重播，时间基留在末尾 → 周期观察者不再回调；且拖动状态 `dragging` 未复位时进度条一直显示旧拖动值。
  → 改为**重建条目**（`rebuildQueue(from: idx, …)`）；播放页在「位置大幅回跳（>3s）/ 换歌」时强制复位 `dragging`。

### 3. 播放队列只装 30 首
- 收藏页：`pageSize = 30` 且点歌传的是当前页 → 队列 30 首。
  → 进页后台 `loadAll()`；点歌前若未拉完先补齐。
  （hw 早有 `ensureAllLoaded()`，iOS 只是追平。）
- 搜索页：每页 30 → **50**（服务端 `limit` 上限即 50，仍一次上游请求）。

### 4. 搜索结果翻页续接队列（双端）
- 翻页时把新一页并入队列尾部 —— 这一页本来就要拉，**零额外上游请求**。
- 双端同名 API：iOS `AudioEngine.appendToQueue` / `PlaybackService.appendToQueue(_:origin:)`；hw `MediaPlayerCore.appendToQueue(tracks, origin)`。
- 防串改：只在「当前队列来源 = 同关键词搜索」时续接；按 `track.id` 去重；随机模式下新曲目洗牌接尾，不打乱在播顺序。
- 明确不做预拉全量：`src/sources/qq/search.ts` 无缓存，多拉一页就是多打一次 QQ。

### 5. 队列抽屉：定位 / 动画 / 性能
- 呼出定位当前曲**居中**：`ScrollViewReader.scrollTo(currentIndex, anchor: .center)`；hw 侧 `scrollToIndex(..., ScrollAlign.CENTER)`（hw 带动画，iOS 瞬时跳）。
- **遮罩慢一拍**：原来整块 sheet 套 `.move(edge:.bottom)` → 遮罩跟着下滑。改为**遮罩 `.opacity` + 抽屉 `.move`** 分开转场（hw 本来就是这么分工）。
- **展开/收起卡顿**：整列表 `opacity` 动画（长列表每帧离屏合成）+ 带动画 `scrollTo`（大量布局动画）。两者都撤销。

### 6. 底栏贴边（上一批延续）
- 去掉 hw 的 `s3`/`s2` 边距，背景延伸进安全区；34pt home indicator 区不可压（iOS 结构性差异）。
