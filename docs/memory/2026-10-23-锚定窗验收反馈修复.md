## 本轮修复（全部在 PlayerPage.ets）

1. **更多菜单对齐**（用户："锚定:bilibi 和下方歌手：XXX 对齐"）
   根因：当前音源行是「标签左·值右」两栏，而歌手/专辑行是「图标 + 歌手：XXX」
   通栏左排，两种版式混用没对齐。修法：全部行统一 web more-menu 两栏版式
   （`.more-k` 小字 t2 标签左 + `.more-v` t1 值右，去 person/opticaldisc 图标；
   值 layoutWeight(1)+textAlign End 兜省略）。修正音源行标签同步改 k 样式。

2. **候选行点击即试听**（用户："点击即调用试听，去除试听按钮，保留锚定按钮即可"）
   candidateRow 整行 onClick → previewCandidate（再点同一行 = 停）；
   删试听/停止按钮，仅保留锚定钮（ArkUI 点击不冒泡，锚定钮不会误触发行试听）；
   试听中的行整行染 panel2 + 副行加「· 试听中」示别。

3. **试听暂停主播放**（用户："试听不会停止在播音频，导致根本听不出是什么"）
   - 新增 `previewPausedMain` 标志；`previewCandidate` 起播前
     `MediaPlayerCore.isPlaying → pause()`（走内核公开 API，状态机零改动）
   - `stopPreview(resumeMain)` 显式参数：停试听/播完/失败/关弹窗/切歌/重搜
     → 恢复主播放；**换行试听与锚定流程传 false**（换行保持暂停直接切新条；
     锚定要先 retryCurrent 重装，先恢复会闪一下旧音源）
   - doAnchor 补 `retryCurrent()` 后显式 `play()`：主播放被试听暂停时
     wantPlay=false，retryCurrent 会按暂停意图重装不播；锚定=想听这首，
     重装后统一起播（web retryAfterAnchor→load 同口径）

4. **"页面外 mystery 按钮"**（用户："看到页面外有个按钮，看不出来是什么"）
   根因：锚定窗搜索行里 NeuInput 没有宽约束（其它使用点都是独占整行或
   width 100%），TextInput 撑满可用宽把「搜索」钮挤出 92% 弹窗外、
   悬在页面边缘。修法：NeuInput 加 `.layoutWeight(1)`，搜索钮收回弹窗内。
   （弹窗打开即自动搜一轮，用户此前不需要点搜索钮也能见候选，故此前未暴露）
