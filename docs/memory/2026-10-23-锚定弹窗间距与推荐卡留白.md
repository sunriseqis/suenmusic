# 2026-10-23 锚定弹窗分块间距 + 推荐卡上下留白对称（含实测数据）

**状态：已修复并装机实测（dump 数值）**

## ① 锚定弹窗：「音源 / 搜索 / 曲目信息 / 搜索结果」之间完全没有间隔

- 根因：`anchorSheet()` 的弹窗卡片内层是 `Column()`（**无 space**），各块只靠自身 padding 撑，块与块之间 gap = 0，
  所以标题、音源行、搜索行、原版参照卡、候选列表全糊成一坨。
- 改法：内层改 `Column({ space: Dim.s3 })`，**所有分块统一吃 12vp 档**（不再逐个调 padding）。
- 连带：音源行原来是上下两条通栏发丝线（`border top/bottom`），和「已锚点 / 原版参照」两张圆角面板行不是一套；
  改成同样的 `panel2` 圆角行（去掉两条通栏线，也顺手少了两条用户反感的横线）。
- **实测**：弹窗内 5 个分块的纵向 gap 全部 = **42px = 12.0vp**（标题 328-454 → 音源 496-573 → 搜索 615-754 →
  参照 796-950 → 候选 992-1135… 每段 gap 均 42px）。

## ② 专属播放页推荐卡：顶部空隙过大、上下不对等

- 根因（实测诊断）：dislike 入口键壳是 **44vp（154px）**，塞在标题 Row 里把整行撑到 44vp，
  标题文字（≈13vp）被垂直居中 → 顶部凭空多出 ≈15vp；而卡片底部只有 padding 12vp。
  → 顶部 24.6vp vs 底部 12.9vp（改前实测），这就是「空隙太大且不对等」。
- 改法（两次迭代才定）：
  - 先试「键绝对定位右上角」：顶部降到 8.9vp，但键（44vp）会压到正文首行（键 y 3~47vp，正文从 29.7vp 起）；
  - 最终：**键壳缩到 36vp 留在标题行**（`Row` 高度由 44 → 36，键仍不撑到正文）+ **卡片 top padding 取 0**
    （36vp 行内居中天然带 ~12.6vp 上留白），底部保持 `s3`=12vp。
- **实测**：顶部留白 **44px ≈ 12.6vp**，底部留白 **45px ≈ 12.9vp**，差 **1px（0.3vp）**；卡片高 342px → **300px**（更紧凑，
  正文全显示无遮挡；dislike 键 `[1025,1485][1151,1611]` 与正文首行 `y=1639` 不重叠）。

## 方法论备注

这类「留白不对等」问题**必须量**：从 dump 取「卡片 top → 标题文字 top」与「正文底 → 卡片底」两个像素距离，
