## 一、修了什么（开工单优先级 1–4，全部落地）

### ① `WebButtons.ets` 宽度塌爆（黑名单/备份弹窗行错乱）—— 根因修复

- **根因（复现确认）**：`WebButton` 非 block 时根 `Stack` 宽度自适应，而顶沿高光是 Stack 内一条
  `Row().height(Dim.hairline).width('100%')`；**百分比宽子组件在自适应容器里按父级最大约束测量** →
  Stack 被撑到整行宽（实测 960×107px 巨板），同行 `Text(row.name).layoutWeight(1)` 被先测量的巨宽
  按钮挤成 0 宽 → 歌名消失、按钮文字顶部居中。
- **改法**：删掉百分比宽 sheen，描边统一由新增 `btnBorder(): BorderOptions` 出（与 `WebIconButton`
  `chromeBorder()` 同一套做法）：ghost/danger 无厚度、primary 只留上沿 `hi` 高光、default 四边 `line`。
  **default 不再画那条 1vp/6% 白内高光**——实机肉眼不可辨，换来 32 处调用点零回归。
- **影响面**：`WebButton` 全部调用点（黑名单行、数据备份弹窗、导入、锚定弹窗、ServerListPage、
  QueueView、LyricView、EmptyState、CollectionPage 等）。自适应宽现在完全由 label 决定。

## 四、坑与教训

- **自适应（内容撑开）容器里禁止出现百分比宽子组件**。这已是第二次栽：批次 D 的 `coverCard` 根
  `.width('100%')` 在 Row 里解析成整行宽。判据：容器 `.width(undefined)` / 无 `layoutWeight` 时，
  子组件只能用固定尺寸或 `layoutWeight`，不能用 `'100%'`。
- **修「看不见的小装饰」优先砍掉它**：1vp 6% 白高光不值得为它引入布局风险。
- **本机编译口径**：`npm run hw:build`（hvigorw 包装器）在这台机子上会走 npm 拉 `@ohos/hvigor-cli` 失败；
  直接调 `hvigorw.js --no-daemon` 会缺 `DEVECO_SDK_HOME`。**正解 = `devecocli build`**（CLT 路径走
  `DEVECO_CLI_CLT_PATH=/opt/clt/command-line-tools`）；偶发 `ping timeout` daemon 报错重跑即可。
