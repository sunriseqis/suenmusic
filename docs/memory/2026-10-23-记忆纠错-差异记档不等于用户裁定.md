## 一、结论先行

**「差异记档」（hw 与 web 不同，记下来备查）从来没有获得用户裁定过**。
Lead 在复盘时把它当成「用户已裁定不补」，属于**把单方取舍冒充成用户裁决**——这是本次要修的记录性错误。
从现在起：任何一项 hw/web 差异，必须在记忆里标明来源三选一——
**① web 能力缺失**（web 也没这功能）/ **② 执行方取舍**（待用户拍板）/ **③ 用户裁定**（附时间与原话）。
没标 ③ 的一律视为**未裁定、开放项**，复盘时不得说成「用户决定不补」。

## 四、教训（写进纪律）

1. **裁定量级最高**：「用户裁定」四个字只能在用户明确表态后使用，且必须附时间与判断依据（原话/截图）。
2. **记档不是裁定的替代品**：执行方单方取舍要显式写「待用户拍板」，并在复盘时作为开放项上报，不能默认关闭。
3. **复盘不得二手定性**：Lead 汇总遗留项时，状态必须回查原始记录，不能凭上一轮汇总的措辞继续转写。
4. **陈旧状态要复核**：播控取证这类「已完成」的项在汇总前重查一次（本轮就翻出一条我没查证的旧说法）。
