# 2026-10-20 飞牛 fnOS 原生应用套件工程与 fpk 构建交付记录

## 一、交付背景与核心定位

在完成服务端单一真相源架构收敛（阶段 1-3）以及多代理全仓深度审计收敛（阶段 4）后，SuenMusic 服务端已具备单端口（3210）统一伺服 Web SPA 与流媒体 API 的全栈能力。

为使 SuenMusic 能够作为系统级**原生套件**入驻家庭 NAS 生态，我们在工程目录 `fn/` 中彻底摒弃 Docker 容器伪应用的包装模式，落地了针对 **飞牛私有云（fnOS）** 的 100% 纯原生应用套件工程，并通过官方 `fnpack` 命令行工具链实现了全自动化的一键打包流水线。

---

## 二、纯原生架构设计对比

| 维度 | Docker 伪应用模式（已废弃） | 纯原生套件模式（当前落地） |
| :--- | :--- | :--- |
| **执行模式** | 宿主机 Docker 后台拉取镜像创建容器 | Debian 12 系统级纯原生进程，直接运行 |
| **环境依赖** | 强依赖宿主机 Docker 守护进程与公网镜像拉取 | **零宿主依赖**，套件内置独立便携版 Node.js 22 运行时 |
| **性能损耗** | 容器网络桥接转发、虚拟化损耗 | **零虚拟化损耗**，原生 IPC/Socket 吞吐 |
| **存储映射** | 需要繁琐配置 UID/GID 权限、容器路径映射 | 飞牛原生 `data-share` 声明，`${TRIM_PKGVAR}` 目录直接读写 |
| **启动速度** | 需等待 Docker daemon、容器创建与端口绑定 | **秒级启动**，原生 Node 进程即刻常驻 |
| **图标与品牌** | 占位模板图标 | 采用官方 1024x1024 主图重采样高清抗锯齿图标 |

## 三、工程落地成果

### 1. 套件工程布局 (`fn/`)
```text
fn/
├── manifest                     # 飞牛核心清单（appname=suenmusic, version=1.5.0, arch=x86_64, 3210 端口）
├── ICON.PNG                     # 64x64 官方品牌应用中心图标
├── ICON_256.PNG                 # 256x256 官方品牌高清桌面图标
├── config/
│   ├── privilege                # 运行身份声明（run-as: package 权限隔离，无 docker 用户依赖）
│   └── resource                 # 声明数据持久化路径映射（suenmusic 与 suenmusic/data）
├── app/
│   ├── bin/
│   │   └── node                 # 独立便携式 Node.js 22.14.0 Linux x64 二进制 (755)
│   ├── server/                  # 服务端源码与纯 JS 生产依赖 (src/index.ts, package.json, node_modules)
│   ├── web/
│   │   └── dist/                # 编译就绪的前端 Web SPA 静态资源
│   └── ui/
│       ├── config               # 桌面快捷方式定义（点击直达 3210 端口 Web 播放器）
│       └── images/              # 多分辨率高清图标（icon_64.png, icon_256.png）
├── cmd/
│   ├── main                     # 原生守护进程调度脚本（处理 start, stop, status，PID 监控与优雅退出）
│   ├── install_init             # 安装前初始化钩子
│   ├── install_callback         # 安装后完成钩子
│   ├── uninstall_init           # 卸载前钩子
│   ├── uninstall_callback       # 卸载后清理钩子
│   ├── upgrade_init             # 升级前钩子
│   ├── upgrade_callback         # 升级后钩子
│   ├── config_init              # 配置变更前钩子
│   └── config_callback          # 配置变更后钩子
└── wizard/                      # 安装向导预留
```

### 2. 自动化构建流水线 (`scripts/build-fn.mjs`)
- 支持一键执行 `node scripts/build-fn.mjs`；
- 自动读取根目录 `VERSION` 并归一化为 SemVer 版本号（`1.5` → `1.5.0`），自动同步至 `fn/manifest`；
- 从官方母版图标 `ios/App/App/Assets.xcassets/AppIcon.appiconset/AppIcon-1024.png` 通过 LANCZOS 滤波生成多尺寸高清 PNG；
- 自动准备便携版 Node.js 22.14.0 Linux-x64 二进制放入 `fn/app/bin/node`；
- 组装 `web/dist` 与 `server` 源码及生产依赖至 `fn/app/`；
- 调用官方 `fnpack build -d .` 自动构建输出并归档至 `output/suenmusic-v1.5.0.fpk`。

## 五、NAS 安装「权限出错」排查与根治修复

在真机测试手动安装首版 `.fpk` 时，飞牛应用中心弹窗报错「权限出错」，经排查定位到三大协同根因并彻底解决：

### 1. 根因剖析
1. **构建容器 Umask 导致权限过度收窄（致命）**：
   - 容器 root 默认 `umask 077`，构建时解压和创建的文件为 `0600`（`-rw-------`），目录为 `0700`（`drwx------`），只有 root 具备访问权；
   - 飞牛 AppCenter 安装器与原生进程以独立非 root 用户（`package` 用户）身份解压与探测包内资源，因无法穿透 0700 目录与读取 0600 文件直接抛出 `EACCES (Permission denied)`，前端即提示「权限出错」。
2. **`config/resource` 包含非法共享名（斜杠路径）**：
   - 早期历史遗留了 `{"name": "suenmusic/data"}`，而在 Linux Samba/fnOS 存储管理中，共享文件夹名严禁包含斜杠 `/`，底层调用 `setfacl` / Windows ACL 时直接报错。
3. **`config/privilege` 缺少显式账户声明**：
   - 未显式声明 `username` 与 `groupname`，导致系统无法准确为 `data-share` 中的 `suenmusic` 用户分配精确的用户组映射。

### 2. 修复措施落地
1. **构建脚本全局注入 `process.umask(0o022)`**：
   - 在 `scripts/build-fn.mjs` 装配完成后，增加全局目录递归 `chmod 755`、文件递归 `chmod 644`、脚本与 `bin/node` 赋权 `chmod 755`；
   - 保证输出的 `.fpk` 内部以及内层 `app.tgz` 内部所有资产全部具备标准的跨用户只读/执行权限。
2. **规范 `config/resource` 与 `config/privilege`**：
   - `config/privilege` 显式写入 `"username": "suenmusic"`, `"groupname": "suenmusic"`；
   - `config/resource` 移除 `suenmusic/data`，只保留合法的单级共享目录 `suenmusic`。
3. **安装钩子自愈闭环 (`cmd/install_callback`)**：
   - 在安装回调钩子中自动检查并补齐 `${TRIM_APPDEST}` 与 `${TRIM_PKGVAR}/data` 的读写权限，避免宿主机 ACL 继承导致的二次权限阻塞。
