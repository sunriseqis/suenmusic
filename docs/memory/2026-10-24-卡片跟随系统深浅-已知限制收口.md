# 2026-10-24 卡片「跟随系统深浅」实时性 —— 已知限制收口

**用户结论**：「依然一样。不过没事。就这样，实际使用不影响。」

## 现象（保留记录，避免以后重复investigate）

「跟随系统」模式下切系统深浅：
- 卡片**不会立刻**变色；
- 把 App 唤回前台后立刻变；
- 否则要等系统定时刷新表单（`SuenFormAbility.onUpdateForm`）才变。

## 已试过且**无效**的三条路

1. **卡片用资源色** `$r('app.color.card_*')`（T12 之前就是这么做的）——
   实测卡片并没有跟随系统（这也正是最初「卡片只有浅色没有深色」的由来），故改为 payload 驱动。
2. **`Ability.onConfigurationUpdate` 里重推**（`d4128e1`）—— 后台收不到回调，前台唤回才触发。
3. **应用级 `ApplicationContext.on('environment')`**（`349e6a7`）—— 订阅注册成功（日志可证），
   但卡片仍然不实时；推断卡片渲染侧（FormRenderer / 桌面宿主进程）对 payload 变更的**重绘时机**受限，
   我们的推送不必然触发它立即重绘。

## 现状与兜底

- 「浅色 / 深色」显式模式**完全正常**（切设置立刻重推，实测 2 张卡即时变化）；
- 「跟随系统」模式下：卡片最终会变对（前台唤回 or 系统定时刷新），只是不实时；
- 用户裁定：**可接受，实际使用不影响**，不再投入。

## 若将来要彻底解决（仅记录，未做）

- 方案 A：卡片改回资源驱动 → 牺牲「跟随 app 内设置」的能力（与用户 2026-10-23 的裁定冲突）；
- 方案 B：App 存活期间用低频定时器主动比对并重推（治标，增加唤醒）；
- 方案 C：查 FormKit 是否有「强制重绘/版本号」机制（需查官方文档，未查）。
