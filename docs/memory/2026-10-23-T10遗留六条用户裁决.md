## 二、第 1 条的补充解释（人话版，等用户再定）

播放页「更多」菜单里现在有一行「当前音源」，hw 只有两种显示：

- 你手动锚定过 → 「B 站 · 已锚定」
- 没锚定过 → 「未解析」

**web 端这一行显示的是「这首歌此刻到底从哪个音源播出来的」**（网易云 / Bilibili），并且逐曲变化。
差别就是：hw 只知道「你锚没锚过」，不知道「这首歌实际从哪来的」。

hw 要做到，需要在内核里记下服务端解析结果（`/api/resolve` 返回体里的 `source` 字段，
`APIClient.resolve()` 方法其实已经写好、但一直没被调用过）。代价：每曲多一次轻请求（或复用 stream 响应）。
**待用户一句话**：这一行要不要显示真实音源？要 → 我排工；不要 → 就把这行文案固定成现在这样并记档。

## 三、第 2 条的实现（已交付）

- 新增 `hw/entry/src/main/ets/common/Notifier.ets`：`notificationManager.publish` 发基础文本通知；
  固定 id（3001）让新提示覆盖旧提示；**首次使用才请求一次通知授权**，用户拒绝则静默降级（应用内 eyebrow 提示仍在）。
- `EntryAbility.onCreate` 注入 `UIAbilityContext`（`Notifier.init(this.context)`）。
- `MediaPlayerCore.fail()` 两个出口都发通知：
  - 常规失败（还有路可走）→「没有匹配音源 / 《X》没有可播放的匹配音源，已自动跳过」→ 600ms 后 `next()`（原有语义不变）
  - 连续失败到上限 →「连续多首没有匹配音源 / 已暂停播放，请检查网络或稍后再试」
- **不弹任何应用内弹窗**（用户明确要求）。
- 门禁：check-arkts 0E/4W 基线不变；`devecocli build` BUILD SUCCESSFUL（ArkTS WARN 5 = 既有 syscap）。
