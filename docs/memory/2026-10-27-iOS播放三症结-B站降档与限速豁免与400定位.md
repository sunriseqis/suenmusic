# 2026-10-27 iOS 播放三症结：B 站降档、限速豁免与 400 定位

> 用户报 iOS 端：网易云启播缓慢 / B 站音源大多不可播 / 频繁切歌服务端报 HTTP 400。双代理并行排查（iOS 端 + 服务端），Lead 复核 diff 与 tsc 通过。

## 根因与修复

1. **B 站不可播·主根因＝方案 A 未覆盖 B 站链路**：preferMp3 原只收紧网易云/酷狗，resolveTrackSource 恒取 fnval=4048 最高码率 DASH m4s；叠加 streamRate 对带 Range 请求的 40KB/s 下限限速，B 站 fMP4 起播卡 EvaluatingBufferingRate（2026-09-26 实测注释佐证）。MIME 嫌疑排除：iOS 本地嗅探与服务端 sniffAudioType 逐条一致，fMP4+audio/mp4 实测可播。
   - 修复：bilibili/stream.ts getAudioStream/resolveTrackSource 增加 options，preferMp3 时 DASH audio 取**最低**码率档（实测同曲 184052→65698）；resolver.ts 三处 fallback + resolveFromAnchor 全透传。
2. **限速**：routes/stream.ts streamRate 增 isIos 参，iOS 带 Range 不限速；Web/鸿蒙公式不变。
3. **网易云启播慢**：netease/source.ts ①songUrlV1 data[0].code===404（无版权档）直接下一档；②凭证 301 时 break 跳过剩余音质档、搜索 code 301 立即 fail 交 B 站，不再逐级白烧。
4. **HTTP 400**：parseId 对 %2C 核查无问题（三种形态实测）；400 真因待定＝客户端发了无合法前缀的 id。stream.ts:319 badRequest message 现附原始 id 前 40 字符，真机复测看日志即可定位。
5. **iOS 侧最小修复**：AudioEngine.makeItem 在拼 URL 前先 LocalStreamProxy.shared.entry(trackId:) 预热，保证直连回退路径缓存下载已启动。

## 补充（第一服务端代理迟到回执，已合并验收）
- 负缓存跨端共享：resolver.ts 失败结果同键双写（不带 :mp3 后缀），iOS 失败后他端同曲 0ms 命中（修复前必再打 upstream）。
- 400 真凶确认：bvid 全等正则 /^BV[0-9A-Za-z]{10}$/ 对 AVPlayer 预探测带尾巴请求 400 → 放宽为前缀匹配截前 12 位；trackId 含 % 走 safeDecode 再 parseId。resolve.ts:51 的 BVID_RE 未改（resolve 链路非本次症状）。
- 实测环境事实：账号「八十九啊」vipType=0（无黑胶），cookie 有效；未观察到 301，301 短路为防御性修复。
- 合并核验：双代理同文件改动无重复代码块，tsc + test:resolver 69 项全过。
