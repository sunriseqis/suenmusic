# 真机暴露的三处缺陷（2026-10-17）

首轮本地优先改造装上真机后，三个"看起来是同一个问题"的现象，实际是三个独立的根因。
记下来是因为每一个的**表现都极具误导性**。

## 1. 红心点了没存 —— IndexedDB 不能克隆 Vue 的 Proxy

**现象**：点红心，图标立刻变红；杀进程重开，全没了。

**根因**：IndexedDB 用结构化克隆算法写值，而 Vue 的响应式对象是 **Proxy**。
`objectStore.put(proxy)` 直接抛 `DataCloneError: #<Object> could not be cloned`。
调用方传的 `props.track`、`player.currentTrack` 全都是 Proxy。

**为什么难发现**：

- 界面已经乐观更新了，看起来"存上了"；
- 异常在 `ldbPut` 里被静默吞掉（当时的写法是"存储失败不该打断播放"）；
- 诊断页的"本地存储"测试用的是**纯对象**，一直是绿的。

**修法**：写入前 `JSON.parse(JSON.stringify(row))`（`localdb.ts: toPlain`），
并且失败必须 `console.error`，不能完全无声。

**教训**：存储层的自测必须用**和真实调用同形状**的对象。纯对象测不出 Proxy 的坑。

## 2. 续播没了 —— 恢复会话被登录态挡着

**现象**：播到一半杀进程，重开后播放条空白、进度 0。

**根因**：`App.vue` 里恢复会话的 watch 条件是 `session.isLoggedIn`，而直连模式
没有登录 —— 这段逻辑从来没执行过。**数据其实一直在 localStorage 里**
（`suenmusic.lastSession`，快照是新的、位置也对），只是没人读。

**修法**：`watch(() => session.bootstrapped)`。队列属于这台设备，不属于账号。

**教训**：把"数据归属"从账号改成设备时，所有以登录态为开关的本地功能都要复查一遍。

## 3. 直连能解析但播不了 —— MediaItem 的 URI 在入队时就固化了

**现象**：日志显示 `[direct] 解析成功 ... bw=184052`，ExoPlayer 状态却是
`ERROR(7) Source error`，播放器一路跳歌。

**根因**：原生队列条目的 URI 是在 `setQueue` → `MediaSession.Callback.onAddMediaItems`
里用 `SuenAudio.streamUrlFor(id)` 组装的。直连地址要等解析完才有，入队时是空串，
之后 `setDirectUrl` 只更新映射表，**不会改已经建好的 MediaItem**。

**修法**：`setDirectUrl` 之后调 `reloadCurrent({index, positionMs, autoplay:false})`
让原生重建这一条（它会重新取 `streamUrlFor`）。出声仍交给统一的 `el.play()`。

**教训**：原生播放器的地址是"入队时固化"的，任何后置的地址变更都必须显式重建条目 ——
这和锚定换源必须 `reloadCurrent` 是同一个道理。

## 4. 顺带：QQ 搜索 2001 是"几十秒级"的抖动，不是 60 秒冷却

真机日志里连续两次请求都是 `req.code=2001`，约一分钟后同样的请求返回 `code:0`。
所以：

- 重试要等得比想象中久（1200ms / 2400ms 两档，总等待 ≤ 4 秒）；
- 文案要写"被限流，约几秒到一分钟恢复"，而不是笼统的"搜索失败"。

服务端的 `qqCooldown` 是"整站共用出口"的自我保护；客户端单用户不需要那么保守。

## 5. 歌词加载失败 —— 同一个端点这次不带 JSONP 外壳

**现象**：本地模式下歌词一直失败。

**根因**：QQ 歌词接口（`c.y.qq.com/lyric/fcgi-bin/fcg_query_lyric_new.fcg`）
**有时返回纯 JSON、有时带 `MusicJsonCallback(...)` 外壳**。代码无条件找括号剥壳，
而歌词正文里本来就有括号（`[00:00.00]晴天 - 周杰伦 (Jay Chou)`）——
`indexOf('(')` 命中歌词里的那个，切出一段乱码，`JSON.parse` 必然失败。

**修法**：只有首字符不是 `{`/`[` 时才按 JSONP 剥壳。

**教训**：解析 JSONP 不能用"找第一个括号"，要用"判断是不是 JSON"。
内容里出现同种字符是常态。

接口本身是好的：`retcode:0`，歌词、翻译都齐。

## 6. 续播恢复了，但界面显示 0:00 —— 原生位置没回写 UI 状态

**现象**：原生播放器已经在上次的位置（status 里 `positionMs=176931`），
播放页却显示 `0:00` 和"已停止"，看起来又像"续播丢了"。

**根因**：恢复时 `autoplay:false`，`pendingSeekMs` 只交给了原生队列；
`applyPendingSeek()` 依赖 `loadedmetadata` 之类的媒体事件才会把 `positionMs`
同步回 store —— 不出声时这些事件不一定触发。更糟的是：下一次 `saveSession()`
会把 `positionMs`（0）**写回快照**，把真实进度覆盖掉，问题就从"显示错"变成"真丢了"。

**修法**：`restoreSession` 成功后显式 `positionMs.value = snap.positionMs`
（顺带补 `durationMs`）。

**教训**：凡是"只把状态交给原生、等事件回传"的地方，都要问一句
"事件不来的时候，UI 和持久化会拿到什么值"。
