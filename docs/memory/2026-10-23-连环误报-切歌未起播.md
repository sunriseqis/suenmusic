# 2026-10-23 连环误报根因：切歌用 `loadCurrent(auto || wantPlay)`，失败后 wantPlay=false → 只 prepare 不 play

**用户报**：列表播放遇到无音源/无声的曲子 → 报错并跳下一首 → **之后每一首都报错**，但其实都正常。

## 根因（一行）

`advance()` 尾部原本是：

```ts
await this.loadCurrent(auto || this.wantPlay);
```

而 `settleFailure()` 会把 `wantPlay` 置 false。于是：
1. A 曲失败 → `wantPlay=false` → 自动跳过 → `next()` → `advance(false)` → `loadCurrent(false || false)` = **false**；
2. `loadCurrent(false)` 里 `pendingAutoplay=false` → AVPlayer 正常 `prepared`，但 `prepared` 分支因为
   `pendingAutoplay=false` **不会调 `play()`** → 永远停在 `prepared`；
3. 6s 卡死看门狗：`装载超时 6000ms 仍未起播（状态=prepared）` → 判失败 → 再跳过 → 无限连环。

日志实证（连环 20 次，全部 `状态=prepared`）：

## 修法

「切歌 / 重试 / 上一首」的语义就是**播**，不能靠 `wantPlay`（它表达的是上一首的播放意图）来推：

| 位置 | 改前 | 改后 |
|---|---|---|
| `advance()` 尾部 | `loadCurrent(auto \|\| wantPlay)` | **`loadCurrent(true)`** |
| `retryCurrent()` | `loadCurrent(forcePlay \|\| wantPlay)` | **`loadCurrent(true)`** |
| `prev()` | `loadCurrent(this.wantPlay)` | **`loadCurrent(true)`** |
| `settleFailure()` 自动跳过 | `this.next()`（= advance(false)，队尾会停） | **`this.advance(true)`**（保留连播/回绕/重洗语义） |

## 实测（模拟器）

- 装新版后：`怎么` 失败 → 错误行 + 重试/跳过；点「跳过」→ 下一首《偏爱》**0:07 / 3:30 正常播放**，无连环报错。
- `hilog` 里连续 12 秒无 `装载超时`、无 `失败落定`。

## 教训

- **`wantPlay` 是「意图」，只能表达用户/连播想不想播，绝不能拿来推导下一次装载要不要起播。**
  本端已经在这一个变量上栽了三次（T4 重装成暂停态、今日的失败落定误判、这次的连环误报）。
  → 规矩：`loadCurrent()` 的 autoplay 参数**只由调用方语义决定**（点播/切歌/重试 = true），不读全局意图位。
- 卡死看门狗是这次能一眼看出「状态=prepared」的关键——失败链必须可观测。
