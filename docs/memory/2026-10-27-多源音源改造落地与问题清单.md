## 二、本轮修复的线上问题

### 1. 服务端一直没在 systemd 下运行（影响面最大）

```
现象：systemd MainPID=0，端口 3210 被一个 14:23 起的野进程占着
后果：所有 systemctl restart 都是空转，改了代码看不到效果（web/hw「新功能不存在」多半是这个）
处理：清理野进程后 MainPID 与端口 PID 一致；重启即生效
```

### 2. web `index.html` 启动时缓存导致前端永远是旧包

改为**按 mtime 热读 + no-cache**：`web` 重新构建后刷新页面即生效，不必重启服务端（`app.ts`）。

### 3. 歌手页混入他人条目 / 全部「未知歌手」/ 无封面

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 混入「夏日入侵企画的救赎（版本1）」「730. …」等 | 歌曲与专辑的归属过滤都有「**没有 mid 就直接放行**」+「过滤后为空退回全部」两个洞 | 改 mid 命中**或歌手名命中**（归一 + 异体字 企画→企划）；去掉退回全部的兜底 |
| 专辑列表整列「未知歌手」 | 专辑搜索分片给的是 `singerName`/`singerMID` **字符串**，而 `adaptQQAlbum` 只认 `singer/singers` 数组 | 无数组时按字符串拆分构造 artists（含头像 URL） |
| 封面空白 | ① QQ「原声/上传」条目 `al.mid`/`al.name` 皆空；② 搜索分片常不带专辑，详情接口才有 | ① 无专辑 mid 时封面退回**歌手头像**（确定性 URL、零请求）；② 列表阶段 `enrichMissingAlbums()` 主动详情回源（限 10 条/页）；③ `backfillCovers()` 用本地库同曲封面回填 |
| `@…创作的原声` 这类无语义条目 | 短视频原声不是歌 | 名称命中「创作的原声」或 `@/#` 开头直接过滤 |

> 关于「点播放后封面就补上」：确认是**详情接口有专辑、搜索分片没有**，播放链路触发详情回源落库。已把该机制前移到列表阶段，不再依赖用户点播放。

### 4. 歌手页多源合一与去重

- `qq_ar_` 歌手页第 1 页也并一次酷狗+网易云（之前只有 QQ 单源）；
- 统一 `dedupeArtistSongs()`：去重键 = 歌名（去括号）+ 是否 Live + **拆分排序后的歌手集合**（`、，&/／+` 归一）；
- **时长感知**：同键内 `|Δdt| ≤ 8s` 才算重复；差异大的保留为不同版本（用户明确要求，避免吞掉真实版本）；
- 噪声：`<45s` 丢弃；同名组内 `<最长版本 70%` 的残片丢弃。

结果：`qq_ar_` 40→33 首（同名组 5→2）、`ne_ar_` 40→36 首。

### 5. 收藏与音源角标（web/hw）

| 问题 | 修复 |

| 搜索/首页列表不显示收藏态（红心不亮、序号不染色）：`favorites.ensureLoaded()` 只在收藏页与设置页调用 | 移到 `App.vue` 登录后全局拉一次 |

## 四、关键不变量（后续改动别破坏）

1. **零翻唱**：酷狗只认 `IsOriginal===1`、网易云只认 `originCoverType===1`；跨源对质用两源认证歌手并集；变种词清洗（伴奏/纯音乐/钢琴/DJ/慢摇/变速/remix/片段/消音/和声/翻唱/cover）。
2. **元数据即播放源**：酷狗条目落库必须带 `kugouMeta`，否则 `kg_` 直取退化为按名搜索。
3. **试听片段识别**：tracker 的 `timeLength` 优先，缺失时 `Content-Length ÷ 码率`；低于曲目 70% 一律跳过（避免「播到 60 秒自动跳下一曲」）。
4. **优先级**：源钉 > 手动锚定 > 自动锚点（用户裁定保留）> 取流链。
5. **建库保护**：夜间窗口 3:00–6:00 + 每轮外网配额 + QQ 冷却，逐一不可绕过。
