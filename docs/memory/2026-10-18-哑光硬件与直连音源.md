# 哑光硬件：设计约束与直连音源（2026-10-18）

## 一、设计语言的四条硬约束

改任何界面前先过这四条，违反任意一条都会退回"旧版皮肤"：

1. **不用外阴影。** 层次只有三种手段：面板色差（`--panel` vs `--bg`）、
   1px 发丝线（`--line`）、顶沿内高光（`--hi`）。双向明暗阴影是 neumorphism
   的软塑料来源。
2. **厚度是稀缺资源。** 全站只有播放键是"凸起的零件"，其余控件一律无底色、
   无边框、无阴影。五个控件全做成按钮，就变成一排遥控器。
3. **琥珀只表示状态**：当前播放、进度、激活项、已收藏的序号。
   它不承担品牌装饰，也不允许被用户改色。
4. **圆角是 6/10/14/18，没有胶囊。** `--r-pill` 曾经是 999px，
   导致标签导轨和"播放全部"仍是旧版胶囊 —— 收到 12px 后才和控件同体系。

## 二、两个会让设计"看起来没生效"的隐蔽问题

### 强调色被运行时覆盖

`stores/ui.ts` 曾在启动时把旧 6 色选择器的颜色写进 `--accent` 的 inline style，
优先级高于 `tokens.css` —— 结果设计稿的琥珀从来没生效过，真机量到的是 `#E0783C`。
现在 `applyAccent()` 不写任何变量，颜色只由 `tokens.css` 决定。

### 2px 进度条填充高度恒为 0

`.track` 设了 `height: 2px` **加 1px 边框**，内容盒被压成 0，
内部的 `.fill { height: 100% }` 自然是 0 —— 界面上只剩一个圆点。
细轨道一律不要边框，直接用背景色。

## 三、列表：行必须有底色

`TrackRow` 的 `.row` 下面就是右滑动作区（橙色/红色）。
把行背景改成 `transparent` 后，整列会变成橙色块。
行必须有不透明底色（`var(--bg)`），分格靠 `border-bottom: 1px solid var(--line)`。

## 四、直连音源的真实链路

```
锚点（本机 localStorage）──命中────────────────────────► 直接取流
        │未命中
        ▼
网易云（搜索 → 打分 → 取流）──拿到整首───────────────► source: netease
        │试听 / 版权限制 / 无结果
        ▼
B 站（搜索 → 打分 → playurl）──────────────────────► source: bilibili
```

### 网易云不需要加密

服务端用的是 vendored NeteaseCloudMusicApi（weapi/eapi）。但直连模式实测发现
这两个旧接口**仍然开放、无需加密**：

```
GET https://music.163.com/api/search/get/web
GET https://music.163.com/api/song/enhance/player/url?id=&ids=[]&br=
```

所以客户端可以直接用 `CapacitorHttp` 调，不必搬加密层。

### 试听 = 失败

`freeTrialInfo` 非空的响应一律丢弃，逐级降码率（320k → 192k → 128k）再试；
全失败才交给 B 站。理由：30 秒的"能播"比"播不了"更让人恼火。

### 网易云翻唱极多，必须校验歌手

"晴天(深情版)" 这类翻唱靠"标题包含 + 时长接近"能打到 80 分。
规则：

- 曲目有歌手信息 → 候选的 artist/title 必须包含任一歌手
- 没有歌手信息 → 标题必须**完全相等**（附加后缀骗不过去）

命中率会下降，但放错版本用户第一耳就能听出来，比播放失败更糟。

## 五、锚定是最高的解析权威

`resolveDirect` 的顺序是：**先查锚点**，命中就直接取流，跳过搜索与打分。
用户手工指定的版本不能被算法覆盖。

换源后必须做两件事，否则"锚定了却听不出变化"：

1. `clearDirectCache(track.id)` —— 清直连解析缓存（否则还是旧地址）
2. `SuenAudio.evictCache({ id })` —— 清原生音频缓存（否则旧字节盖住新音源）

本机锚点存在 `localStorage['suenmusic.anchors']`，不跨设备；
服务端锚点只在配置了服务端时生效。
