## 3. 本轮三个关键修复（根因 + 证据）

### 3.1 [BUG] 取消收藏全线「请求格式不正确」（A 路阻断，P0 级）

- **现象**：收藏页/搜索/每日/首页右滑取消收藏均 toast「请求格式不正确」；收藏动作正常
- **根因**：鸿蒙 http 栈对**不带 extraData 的请求也会默认注入 `Content-Type: application/json`**，Fastify 遇「JSON Content-Type + 空 body」直接 400 `FST_ERR_CTP_EMPTY_JSON_BODY`，经 `server/src/app.ts:122` 统一错误体即「请求格式不正确」。DELETE 无 body 首当其冲，POST 带 body 不受影响——与现象完全吻合
- **证据**（curl 三组对照，当时服务端）：`DELETE` 无 Content-Type → 401 正常到达路由；`DELETE` + `application/json` + 空 body → 400 复现；`DELETE` + `text/plain` + 空 body → 401 正常
- **修法**：`buildHeaders` 显式声明 Content-Type（body 非空=`application/json`，空=`text/plain`），对所有 `raw()` 请求生效
- **注**：曾把同文案误判为 verify_ui 工具自身报错，实为应用 toast——同文案先查服务端

### 3.2 [BUG] Tabs 横滑切页抢走行内右滑手势

- **现象**：右滑列表行会意外跳转相邻 Tab（前两轮验证失败「意外跳转搜索页」的根因）
- **根因**：`NativeRoot` 底部 Tabs 默认支持横滑切换，与行内水平手势竞争
- **修法**：`.scrollable(false)`。底部 Tab 切换仍可点击，横滑切页非移动端肌肉记忆（且与右滑手势永久冲突），弃之

### 3.3 [BUG] 跨页收藏状态不同步（B 路附加项）

- **现象**：搜索页右滑收藏后切收藏页看不到新曲目，杀进程才可见
- **修法**：AppStorage 收藏集合版本号 `K_FAV_REV`：三个普通页 toggle 成功后 `bumpFavRev()`，收藏页 `@StorageProp(K_FAV_REV) @Watch` 触发 `load()`。收藏页自身取消收藏已本地剪枝不 bump（不触发整页重载、不跳滚动位置）。版本号只做 UI 刷新通知，不进播放内核（守总表六条之 4）

## 5. 数据注记与残留限制

- **数据 291 vs 767**：补验单头注「生产库已换入 favorites=767」，模拟器实测 291 首。分页/取消/点歌/手势的功能判定不受影响，数据量差异请 Lead 知悉（若 767 为预期，生产库换入可能未生效或账号不同）
- **跨页 favIds 琥珀染色短暂过期**：普通页 `favIds` 只查未知 id（增量），在其他页收藏/取消后回到本页，旧曲目的琥珀序号可能短暂过期，下次搜索/翻页自愈。仅影响染色显示，不影响收藏真相（真相在服务端+收藏页 `K_FAV_REV` 即时刷新）
- **限流节流边界**：`retryAfterMs` 只在收到 degraded 响应后生效（客户端无法预知服务端冷却），首个触发请求会真实到达服务端并被服务端冷却分支快速返回——两端配合，无上游压力

## 6. 验证方式与环境注记（本 session 新坑）

- **手势验证转手动**：verify_ui 自动化在模拟器上不可靠——从屏幕最左缘（x≈30px）起滑被系统侧边 gesture dock 截获；`uitest uiInput swipe` 快速边缘滑动会唤出系统手势坞/中转站教程弹窗；`drag` 不精准。**结论：手势交用户手动，工具只用于布局 dump/截图**
- **`uitest dumpLayout` 能暴露 TrackItem 内部节点**（序号、动作区文字、行文本与 bounds），可做程序化断言——此前「ForEach 行不暴露」的结论**错误**，更正
- **同文案先查服务端**：「请求格式不正确」曾同时是 verify_ui 失败报告文案与应用 toast，先 curl 服务端分辨
- `uitest screenCap` 输出文件实为 PNG（扩展名 .jpeg）；多模态识别需复制为 .png
- 主模型不支持看图，截图分析走 `recognize_ui_components`
