# iOS 编译四报错与单仓同步（2026-10-19）

## 现象

Xcode 编译 App target，4 个 error，全部形如：

```
ios/App/App/capacitor.config.json: No such file or directory
ios/App/App/config.xml: No such file or directory
ios/App/App/public: No such file or directory
```

三个路径全在 `ios/App/App/` 下 —— 那是 Capacitor 的**原生 target 目录**，
`webDir`（`public/`）、原生配置副本（`capacitor.config.json`）和 Cordova 存根
（`config.xml`）都放这里。第 4 个 error 是这三个缺失的汇总失败。

## 根因

**单仓合并后，iOS 工程从未在新布局下跑过 `cap sync`。**

1. 2026-10-16 仓库由 `suenmusic-server` + `suenmusic-mobile` 合并为单仓
   （`web/capacitor.config.ts` 顶部有说明），但 iOS 侧的同步动作一次都没跑过。
2. `ios/App/App.xcodeproj/project.pbxproj` 的 Resources 阶段引用三个**生成物**，
   它们在磁盘上不存在（三者都被 `ios/.gitignore` 排除，不随仓库分发）：
   - `capacitor.config.json` —— `cap sync` 的 copy 步骤写入
   - `public/` —— `cap sync` 把 `web/dist` 整目录拷入
   - `config.xml` —— **Capacitor 8 的模板已不再生成它**，见下
3. `config.xml` 是历史遗留：本工程的 pbxproj 由旧版 Capacitor 模板生成，
   那时 Resources 里有它；Capacitor 8.5.2 的 `ios-spm-template.tar.gz` 已不含
   此文件，`cap sync` 也不会补。.gitignore 却仍把它列为"Generated Config files"——
   **没有任何工具生成它**。详见计划文档 `docs/plan/2026-10-19-iOS-config-xml残留引用.md`。
4. 为什么没人跑过 sync：`scripts/build-ios.mjs` 还指着双仓时代的
   `../suenmusic-server/web`，`npm run ios:sync` 直接死在前置检查，
   文档化流程实际上不可用。

## 修复清单

1. 在 `web/` 目录跑 `npx cap sync ios`（**必须站在 web/ 跑**，
   `capacitor.config.ts` 在那里，`ios.path: '../ios'` 才解析得到）——
   生成 `capacitor.config.json` 与 `public/`。
2. 手工补 `ios/App/App/config.xml`（Cordova 标准存根，见该文件本身）。
3. `bash scripts/fix-ios-vendor.sh` —— `cap sync` 会把
   `CapApp-SPM/Package.swift` 改回远程 GitHub 依赖，此脚本恢复本地 vendor 路径。
4. 修 `scripts/build-ios.mjs`：`WEB_DIR` 改为仓内 `web/`，删双仓注释。
5. `xcodebuild` 实测 **BUILD SUCCEEDED**（参数见 `docs/dev/ios-build.md`）。

## 附带发现：web 构建链路也是断的

`web/node_modules/.bin` 为空（包本体在，bin 链接没建），
`npm run build` 报 `vue-tsc: command not found`，全链路构建死在第 1 步。
`cd web && npm install` 后恢复（17 个链接），`package-lock.json` 零改动。
CI 不受影响——CI 跑 `npm ci` 会重建链接。

## 长期口径

- **`cap sync ios` 必须站在 `web/` 跑**；站在仓库根或 `ios/` 跑都不会同步对地方。
- **`cap sync` 之后必须跟 `bash scripts/fix-ios-vendor.sh`**，否则 SPM 去连
  GitHub Releases 拉 xcframework，直连大概率超时。
- iOS 生成物三件套（均 gitignored）：`capacitor.config.json` / `public/` / `config.xml`。
- **单仓铁律：任何脚本、配置、文档只允许仓内相对路径**，禁止 `../` 跨仓引用与
  本地绝对路径，否则 CI 必挂。本次 `build-ios.mjs` 的教训正是如此。
- node 走 nvm；非交互 shell 的 PATH 里可能没有 node，构建请在交互式终端跑。
