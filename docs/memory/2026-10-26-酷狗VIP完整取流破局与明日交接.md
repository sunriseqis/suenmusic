## 一、前序为什么只拿到 60 秒片段 / 报 `20018`（根因复盘）

前序排查在 `2026-10-26-酷狗接入交接-暂停点.md` 中误判“卡在 `vip_token`”，实际由以下三个代码缺陷叠加导致：

1. **跨 `appid` 混用导致 `token` 被网关判定失效（`20018`）并污染数据库**：
   - 扫码轮询（`kugou-login.ts`）使用 `appid=3116`（概念版）签发 `token`；
   - 但旧版 `stream.ts` 硬编码了 `APPID = '1005'`（标准版）去调 `/v6/priv_url`；
   - 概念版 `token` 传给 `appid=1005` 必返 `error_code: 20018`（token invalid），旧代码随即调用 `markKugouCredentialInvalid()` 在 `app_settings` 写入 `kugou.credentialsInvalidAt`，把有效凭据永久打标为“授权已过期”，后续请求全部降级为匿名请求，因此上游只给 60 秒试听片段！
2. **取流端点错误（`/v6/priv_url` vs 概念版三步认证链）**：
   - 对照 `EchoMusic`（内联 `MakcRe/KuGouMusicApi`）实测，概念版（`appid=3116`, `clientver=11440`, 盐 `LnT6xpN3khm36zse0QzvmgTZ3waWdRSA`）取 VIP 完整音频走的是：
     1. `POST http://gateway.kugou.com/v2/get_res_privilege/lite`（`x-router: media.store.kugou.com`）获取各音质档位（`flac`/`320`/`128`）对应的真实 `hash` 与 `album_audio_id`；
     2. `GET https://gateway.kugou.com/v1/user_verify`（`x-router: Vipuser.kugou.com`）用概念版 `token` 换取短期 `auth` 令牌；
     3. `GET https://gateway.kugou.com/v1/authorization` 校验后，请求 `GET http://tracker.kugou.com/v5/url`（带 `auth`、概念版 `token`、以及 `key = md5(hash + '185672dd44712f60bb1736df5a377e82' + '3116' + mid + userid)`）直接返回完整 FLAC/320 CDN 直链。
3. **设备指纹（`guid` / `mid` / `dfid`）在各模块分裂且 `mid` 含十六进制字符**：
   - 旧代码在 `kugou-login.ts`、`kugou-status.ts`、`stream.ts` 里各自计算不同的 `mid`，且 `ensureDfid()` 只返回占位符 `'-'`；
   - 酷狗网关要求扫码、会员查询、验权、取流全程使用同一组 `(guid, mid, dfid)`；
   - **关键坑点**：`kugouvip.kugou.com/v1/get_union_vip` 要求 `mid` 必须是**纯十进制数字字符串**（即 `BigInt('0x' + md5(guid)).toString(10)`）。若在末尾拼接 `md5(guid).slice(0, 7)`（含 `a-f` 字母），`get_union_vip` 会直接报 `error_code: 20017 (params invalid)`。
