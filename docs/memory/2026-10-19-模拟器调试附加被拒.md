# 模拟器调试附加被拒：包缺 get-task-allow（2026-10-19）

## 现象

Xcode Run 到 iOS 模拟器（iPhone 17 Pro / iOS 26.5 / Xcode 26.5 / macOS 26.7），
安装成功但 LLDB 附加失败：

```
Could not attach to pid : "9420"
Domain: IDEDebugSessionErrorDomain
Code: 6
RawUnderlyingErrorMessage = "attach failed (Not allowed to attach to process. ...)"
```

## 最终根因（已闭环验证）

**构建出的 App 没有 `com.apple.security.get-task-allow`，内核拒绝交出 task port。**

1. debugserver 日志实测：`::task_for_pid(pid=9420) => err = 0x5 (os/kern) failure`，
   重试十次后 `Attach failed`。
2. Apple 官方文档（Debugging tool entitlement）：即使 debugserver 自带
   debugger entitlement，也拿不到**没有 get-task-allow 的进程**的 task port。
3. 产物实测：`codesign -d --entitlements :-` 为空 dict；连手工写
   get-task-allow 的 entitlements 文件接 `CODE_SIGN_ENTITLEMENTS` 也被剥空。
4. Xcode 26.5 规格文件（`DarwinProductTypes.xcspec`）写明：
   `ENTITLEMENTS_ALLOWED = "$(__IS_NOT_SIMULATOR)"` —— **模拟器产品从设计上
   不允许 entitlements**；生成的 `App.app-Simulated.xcent` 只有
   `application-identifier`，从来没有 get-task-allow。
5. **重签名验证成功**：给产物补签
   `codesign --force --sign - --entitlements <含 get-task-allow 的 plist>` 后，
   `simctl install` + `launch --wait-for-debugger` + `lldb process attach`
   **直接 attach 成功**（`Target 0: (App) stopped`）。

## 为什么这台机器上必现（关键环境因素）

本机是 **Hackintosh（i7-8700，OpenCore 风格 boot-args）**，boot-args 含
**`amfi=0x80`**，内核日志显示：

```
boot-args = ... amfi=0x80 ...
(Sandbox) disabling app bundle & container protections because amfi_get_out_of_my_way is set
AMFI: unable to obtain local signing public key from AKS: e00002e6
AMFI: developer mode is force enabled on this platform
```

在正常 Mac 上，缺 get-task-allow 时还能走 macOS 的调试授权路径
（taskgated + 管理员密码弹框）；本机 AMFI 被关、本地签名公钥取不到，
taskgated 的 `SecTrustEvaluate/SecKeyVerifySignature` 直接判否，
**不会弹密码框**——只剩 get-task-allow 这一条路。

## 已排除的错误方向（别再走）

- **不是** "macOS 开发者模式没开"：AMFI 日志明确 `developer mode is force enabled`，
  `sudo DevToolsSecurity -enable` 在这台机器上无效。
- **不是** 工程签名配置错：`CODE_SIGN_STYLE = Automatic` + `DEVELOPMENT_TEAM`
  正常；`ENTITLEMENTS_ALLOWED=NO` 是 Xcode 对模拟器的既定行为。
- 不是架构/Rosetta（本机 Intel，x86_64 正常）、不是磁盘或模拟器状态。

## 为什么"原应用"没这个问题（DerivedData 实证）

不是"旧包侥幸带 entitlement"，而是**调试目标不同**。本机留存的三次历史构建：

| DerivedData | 构建时间 | 产物 | get-task-allow |
|---|---|---|---|
| App-bbrbpuix… | Sep 27 | Debug-**iphoneos** | ✔ |
| App-fnmymnrx… | Sep 30 | Debug-**iphoneos** | ✔ |
| App-frvhkorq… | Sep 26 | Debug-**iphoneos** | ✔ |
| App-frvhkorq… | **Oct 19 21:54** | Debug-**iphonesimulator** | ✘ |

之前全部是真机包，`get-task-allow` 由**开发描述文件**提供，所以能调试；
今天 21:54 是这台机器上**第一次构建模拟器包**，Xcode 26.5 不注入该
entitlement，于是 attach 被拒。**真机与模拟器是两条不同的签名路径**，
"之前能调、现在不能"的差异就在这里，与工程配置无关。

## 解法

### 单次（已验证）

```bash
# 1) 生成 entitlements
cat > /tmp/get-task-allow.plist <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict><key>com.apple.security.get-task-allow</key><true/></dict></plist>
EOF
# 2) 重签构建产物
codesign --force --sign - --entitlements /tmp/get-task-allow.plist <App.app>
# 3) 装进模拟器后手动启动（不要用 Xcode Run，它会重新安装覆盖签名）
xcrun simctl install <device-udid> <App.app>
```

### 常规化（已落地并验证）

Xcode 的 Run Script build phase **在 CodeSign 之前**执行，事后重签会被
Xcode 的签名步骤覆盖。现改为 **scheme 的 BuildAction PostActions**：

- `ios/App/App.xcodeproj/xcshareddata/xcschemes/App.xcscheme`（新建共享 scheme）
  在 build 结束、install 之前执行 `scripts/fix-ios-sim-entitlement.sh`；
- 脚本只对 `PLATFORM_NAME=iphonesimulator` 生效，先生成含
  `com.apple.security.get-task-allow` 的临时 plist，**先签内嵌 appex 再签外层**，
  避免嵌套签名失效；
- 因为不读 scheme，`xcodebuild -target App`（CI / 打包）完全不受影响。

实测（`xcodebuild -scheme App -sdk iphonesimulator`）：

```
fix-ios-sim-entitlement: 已补签 get-task-allow → …/Debug-iphonesimulator/App.app
codesign -d --entitlements - App.app → com.apple.security.get-task-allow = true
simctl launch --wait-for-debugger → lldb process attach → Process 15497 stopped
```

⚠️ 不要用 `CODE_SIGNING_ALLOWED=NO` 绕过：模拟器虽不校验签名，但
`-Simulated.xcent` 的 app-groups 与签名流程耦合，可能连带影响 Widget 共享。
