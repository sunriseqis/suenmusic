## 一、iOS 原生音频死锁根本原因分析

在回滚直连模式前，iOS 端频繁出现「无法自动切下一首」、「锁屏后播放停止」、「播放到一半跳回开头」等顽疾，经源码级排查，根本原因如下：

1. **直链模式破坏了 AVQueuePlayer 的队列能力**：
   - 直连模式下，Web 端在每首曲目即将播放的瞬间才发起动态取流；
   - 原生插件为了防止 AVQueuePlayer 对未解析直链的条目预加载失败，在 `setQueue` 与 `rebuildQueue` 中强加了 `let directOnly = baseUrl.isEmpty; if directOnly && track.directUrl.isEmpty { continue }`；
   - **后果**：AVQueuePlayer 原生队列中**仅存在当前播放的一首歌曲**。
2. **曲末停播导致 iOS 立即收回后台保活**：
   - 在 `itemDidEnd` 中，当上一首歌放完时，由于队列中没有下一首，触发了 `else if self.baseUrl.isEmpty, self.player.items().count <= 1`；
   - 该分支执行了 `self.playingIntent = false`，没有调用 `player.advanceToNextItem()`；
   - 音频流一旦停止，iOS 系统在熄屏状态下会立即挂起 WebKit JS 引擎；
   - JS 引擎被挂起后无法执行异步直链解析，也无法调用 `reloadCurrent`，导致后台切歌彻底卡死。
3. **全局时间轴承接上一首偏移**：
   - AVQueuePlayer 的时间轴是全局的，未执行明确绝对 `seek(to: .zero)` 会导致下一首歌曲带着上一首的进度继续计时，表现为“有进度无声音”或“跳回开头”。

## 二、重置改造内容

### 1. `ios/App/App/SuenAudioPlugin.swift`
- **恢复原生完整队列**：
  - 彻底移除 `directOnly` 跳过未解析直链的代码；
  - `setQueue` 与 `rebuildQueue` 恢复装载 `[startIndex, 队尾)` 的全部曲目；
  - 每一首曲目都统一指向 `LocalStreamProxy`（`http://127.0.0.1:<port>/stream/<id>`）或服务端代理 `/api/stream/<id>?t=<token>`；
- **修正 `tailOnly` 顺序插入**：
  - 修复多曲目追加时重复在 `current` 之后插入导致的倒序隐患，改为链式顺序插入；
- **原生接续杜绝后台挂起**：
  - 移除曲末 `baseUrl.isEmpty` 的停播中断分支；
  - 队列非空时始终调用 `player.advanceToNextItem()`，音频无缝过渡，系统后台音频 Session 永不断流；
  - 若队列耗尽（如列表循环整队播放完），原生侧直接 `rebuildQueue(from: 0, positionMs: 0, autoplay: true, reason: 1)` 环绕接续；
- **绝对归零**：
  - `rebuildQueue`、`setQueue`、`reloadCurrent` 均显式调用 `player.seek(to: CMTime)`，杜绝跨条目时间轴污染；
- **清理冗余直链特判**：
  - 移除 `isPlaceholder` 检查；
  - 移除 `makeItem` 中由客户端伪造 B 站/网易 Referer 的 Hack，流媒体请求全权交给服务端及本地回环代理。

### 2. `ios/App/App/SuenAudioCache.swift`
- 移除 `LocalStreamProxy` 内的 `directUrls` 直连绕行映射；
- 统一由 `upstreamRequest` 向上游服务端拉流：`http://<baseUrl>/api/stream/<id>?t=<token>`；
- 保持 4GB 磁盘 LRU 缓存、容器字节嗅探（解决 B 站 fMP4 报 octet-stream 拒播问题）以及断点续拉（206 Partial Content）；
- `NetworkMonitor` 监听网络环境变更，在蜂窝/Wi-Fi 切换瞬间触发 `AudioCacheStore.shared.retryStalledDownloads()`，毫秒级取消死连接重连，消除弱网 30s 假死。
