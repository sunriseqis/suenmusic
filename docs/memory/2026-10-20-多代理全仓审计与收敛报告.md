## 一、审计背景与执行机制

为确保彻底清除直连模式遗留与 IndexedDB 本地优先实现，严格回归「服务端单一真相源」架构方案（`docs/plan/2026-10-20-回归服务端单一真相源架构方案.md`），本次任务调动了 3 个专项子代理，针对三大代码域展开多维比对与穿透审计：

1. **子代理 1（服务端架构审计员）**：比对 `suenmusic/server` 与 `suenmusic-server/server`，核验 18 项数据库迁移、路由契约、多源音源解析链路、动态流控与 Range 206 上游代理；
2. **子代理 2（移动原生播放管道审计员）**：比对 `suenmusic/ios`、`suenmusic/android`、`suenmusic/hw` 与 `suenmusic-mobile`，核验 iOS `AVQueuePlayer` 全队列加载、换歌绝对归零、4GB LRU 磁盘缓存、Android Media3 `ExoPlayer` 前台服务保活及双重 `customCacheKey` 机制；
3. **子代理 3（前端与方案落地审计员）**：审计 `web` 端直连代码物理清除、全局统一路由守卫（全端拦截）、数据层单一真相源（收藏/不喜欢/去重/备份/锚定）以及哑光硬件设计系统。

## 二、子代理核心审计发现与修复闭环

### 1. 服务端（Server）
- **比对结果**：
  - 100% 继承并对齐原服务端核心能力：QQ 音乐元数据搜索（`COMM_SEARCH`）、B 站 WBI 验签与多维置信度打分模型（阈值 60/65）、流媒体 Range 206 分片代理、`bytes=0-0` HEAD 嗅探真实总长度、`X-Audio-Duration-Ms` 响应头注入、动态上游流控（`throttle-stream.ts` 40KB/s 保底）、SQLite 游标分页与单调同步。
  - 保留并健全单仓架构升级：管理员角色体系（迁移 018）、`requireAdmin` 鉴权、Web 端同源 HttpOnly 会话支持、单端口静态托管、`VACUUM INTO` 在线热备。
- **发现差距与修复闭环**：
  - **网易云 CIDR 漏考**：`suenmusic-server` 包含的 64KB CIDR 表 `china_ip_ranges.txt` 遗漏。已补全至 `server/src/vendors/netease/data/china_ip_ranges.txt`。
  - **口令过短错误码遗漏**：`services/auth.ts` 中口令长度预校验未传递 `'weak_password'` 错误码。已修复。
  - **测试用例多源自适应**：`scripts/resolver-test.ts` 补充网易云与 B 站多源链路自适应断言，63/63 项验收用例全部通过。

### 2. 移动原生播放管道（iOS / Android / HarmonyOS）
- **iOS 管道**：
  - `AVQueuePlayer` 彻底剔除 `directOnly` 跳歌判定，全量装载队列；
  - 修复 `tailOnly` 顺序插入倒序 Bug，恢复链式递增插入；
  - 换歌绝对归零：`setQueue`、`reloadCurrent`、`rebuildQueue` 显式 `player.seek(to: .zero)`，杜绝时间轴继承导致的“有进度没声音”；
  - `advanceToNextItem()` 原生接续，无需唤醒 WebKit JS 引擎，解决后台断流挂起；
  - `SuenAudioCache.swift` 4GB 磁盘 LRU 缓存、Range 206 支持、`NWPathMonitor` 切网毫秒级自愈已验证。
- **Android 管道**：
  - **清理直连 Referer**：移除了 `SuenAudioCache.java` 中硬编码的 `Referer: https://www.bilibili.com`，避免反向代理或 CDN 针对外来 Referer 的 403 阻断；
  - **清除直连残留**：移除了 `SuenAudio.java`、`SuenAudioPlugin.java`、`SuenAudioService.java` 中的客户端直连旁路与 `anyDirect` / `direct` 分支，统一收敛至服务端流代理与曲目 ID 缓存；
  - 验证 Media3 `customCacheKey`（条目与 CacheKeyFactory 双重设防），避免 `?t=<token>` 轮换导致全量缓存失效。
- **HarmonyOS 管道**：
  - 彻底清空并重新同步 `hw/entry/src/main/resources/rawfile/assets/`，彻底排除了历史遗留的 `DirectProbe` 与 `localdb` 代码分片；
  - 哑光硬件桌面卡片（`SuenFormCard.ets`）与 `HarmonyAVSessionManager` 播控桥梁工作正常。

### 3. 前端（Web SPA）
- **物理清零**：
  - 物理删除 `web/src/api/direct/`（8 个文件）、`web/src/offline/localdb.ts`、`web/src/views/DirectProbe.vue`；
  - 彻底清除相关路由与孤立调用点。
- **全端统一登录守卫**：
  - 所有平台未登录统一拦截至 `/login?redirect=...`；
  - 原生壳支持配置服务端地址、动态管理员初始化检测；
  - 离线弱网下由 `restoreCachedUser()` 挂载快照保活，离线不踢出。
- **关键边界隐患修复**：
  - **Web 端专属（推荐）入口找回**：将 `MobileShell.vue` 与 `DesktopShell.vue` 中的 `!!ui.baseUrl.trim()` 替换为 `hasBackend()`，修复了 Web 浏览器端因同源 baseUrl 为空串导致专属推荐入口被隐匿的 Bug；
  - **原生流代理离线防空**：重构 `native/bridge.ts` 的 `setQueueFromTracks`，移除了 `directMode` 空串置换，离线弱网下由本地会话或持久化基地址兜底，保证原生 LRU 缓存正常定位；
  - **导入备份即时生效**：`Settings.vue` 导入备份后调用 `favorites.reload()` 与 `dislikes.reload()`，突破 `loaded.value` 缓存守卫，实现数据即时渲染。
