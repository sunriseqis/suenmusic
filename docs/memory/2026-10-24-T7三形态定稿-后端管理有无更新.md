# 2026-10-24 T7 定稿：有没有更新由后端管理，客户端只有三种形态

**用户裁定**：「有没有更新是后端管理的，客户端检查更新只有 3 种形态：后端有新包则提示有新版本；
无新包或无包 → 不检查时显示版本号、检查后显示已是最新。」

## 服务端（后端负责判断有无更新）

- `github-update.ts#listReleases`：**HTTP 404 视为「无包」**（返回空列表）而不是抛错 502。
  404 的两种成因——①仓库没有 Release ②仓库是私有且未配 token——都属「后端没有可用包」，
  统一让 `/api/update/check` 正常回 `available:false`，不再让客户端看到「更新源不可用」。

## 客户端（严格三形态）

| 形态 | 行尾文案 | 触发 |
|---|---|---|
| ① 未检查 | `v1.6.0` | 初始状态（版本号取自 bundleManager）|
| ② 检查后无包/无新包 | `已是最新` | `available=false`（含后端无产物）|
| ③ 后端有新包 | `新版本 x.y.z` | `available=true` → 同时拉起系统浏览器下载 |

- 检查中**不新增**「检查中…」文案（保持当前形态），失败也**不新增**错误文案，只弹 toast；
  防重入用 `checkingUpd` 布尔。

## 实测（模拟器）

```
点前：检查更新 / v1.6.0      ← 形态①
点后：检查更新 / 已是最新     ← 形态②（后端当前 404→无包）
```

## 一个必须由用户解决的阻塞项（服务端读不到 Releases）

- 实测 `GET https://api.github.com/repos/sunriseqis/suenmusic` → **404**：仓库是**私有**的，
  未认证读取 Releases 一律 404。所以现在「永远已是最新」是**符合规格**的结果，但也就收不到更新提示。
- 解法二选一：①给服务端配 `SUENMUSIC_UPDATE_GITHUB_TOKEN`（PAT，需 repo 读权限）；②把仓库改公开。
- 另：Release 里的 asset **命名必须是** `SuenMusic-v<版本>-release.hap`（本地产物叫 `-unsigned`，上传需改名）。
