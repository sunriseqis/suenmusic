# 2026-10-24 发行产物命名定稿 + 更新链路（服务端→浏览器下载）本地端到端验证

## 1. 命名（用户裁定）

> 发行产物就是 `suenmusic-<版本>.ipa / .hap / .fpk`；无论后续优化什么，除非改 `VERSION`，
> 发行永远覆盖为 `suenmusic-1.6.0.hap` 这种同名文件。

- 服务端 `artifactName()` 从 `SuenMusic-v<版本>-release.<ext>` 改为 **`suenmusic-<版本>.<ext>`**
  （`github-update.ts`）。版本号唯一来源 = 仓库根 `VERSION`。
- **副作用**：旧命名 `SuenMusic-v*-release.hap` 不再被识别；GitHub Releases 里的 asset 必须按新名（同版本覆盖上传）。

## 2. 本地端到端验证（假 1.7.0）

做法：绕开 GitHub（私有仓无 Release），直接在服务端缓存目录放一个假产物 + 元数据：

```
server/data/updates/harmony/suenmusic-1.7.0.hap   ← 复制自 output 的 1.6.0 unsigned 包（2,038,241 B）
server/data/updates/harmony/latest.json          ← versionName=1.7.0 / versionCode=1070000 / sha256
```

**验证结果（全链路通）**：

| 环节 | 证据 |
|---|---|
| 服务端 check | `available:true`，`latest.versionName=1.7.0`，签发 `downloadToken` |
| 令牌下载（模拟浏览器，无 Authorization 头） | `http=200 bytes=2038241`，md5 与源文件一致 |
| 客户端读取 | 设置→高级→设备→检查更新 → 行尾变「新版本 1.7.0」 |
| 客户端拉起浏览器 | dump 到浏览器「名称：suenmusic-1.7.0.hap 大小：2.04 MB / 立即下载」 |
| 浏览器完成下载 | 下载管理出现 `suenmusic-1.7.0.hap 2.04 MB 打开` ✅ |

注：服务端 fastify 只记 4xx/5xx，成功下载不打日志（所以日志里 grep 不到 download 属正常）。

## 3. 清理方式

假产物在 `server/data/updates/harmony/`（`server/data/` 已被 .gitignore 忽略，不会入库）。
撤掉只需删该目录下 `suenmusic-1.7.0.hap` 与 `latest.json`，客户端随即回到「已是最新」。

## 5. 2026-10-24 追加裁定（本轮）

- 假 1.7.0 已清理：server/data/updates/harmony/ 整目录删除；再查 /api/update/check 回 available:false、latest:null。
- 旧应用不需要平滑升级（后端不同 → 侧载重装即可），因此 versionCode 不必迁就已装的 20175。
- versionCode 公式采纳：major*1000000 + minor*10000 + patch*100
  → 1.6.0 = 1060000、1.6.1 = 1060100、1.7.0 = 1070000、2.0.0 = 2000000（int32 上限 2147483647，余量充足）。
  ⚠️ 位宽约束：minor < 100 且 patch < 100，否则撞号（实测 1.6.100 → 1070000 与 1.7.0 相同；1.100.0 → 2000000 与 2.0.0 相同）。
