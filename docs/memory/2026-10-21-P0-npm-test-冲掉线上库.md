# 2026-10-21 P0：`npm test` 会把**线上库**冲掉（已修）

> 触发发现：更新通道改造过程中需要重跑测试 → 重启服务后 `suen` 账号消失。
> 本文件是纯复盘；更新通道的实现细节见 `docs/dev/update-channel.md`。

## 二、P0：`npm test` 会把**线上库**冲掉

### 2.1 现象

在本机跑完 `npm test` 后，之前建的 `suen` 账号**凭空消失**，只剩测试 fixture（tester/tester2/…）。
实测复现：跑前 `["pwchanger","suen","tester","tester2","throttle"]` → 跑后 `suen` 没了。

### 2.2 根因（两处叠加）

1. **备份/恢复路由读的是 `config.dbPath`，不是"进程实际打开的库"**
   —— 测试全都 `openDatabase(tmpDb)` 开临时库，但 `/api/admin/backup` 与 `/api/admin/db/restore`
   按 `config.dbPath`（= 线上库文件）操作。于是测试里的"备份→恢复"把**临时库的内容覆盖进了线上库文件**。
2. **恢复后重开连接不带路径**
   —— `openDatabase(path = config.dbPath)` 的默认参数在调用时求值；恢复流程 `closeDatabase()` 后
   无参重开，会切回 `config.dbPath`，即"换库"，导致恢复后读到的数据与刚写进去的不一致
   （表现为 `恢复后差异账号消失` 断言失败）。

### 2.3 修法

```ts
// db/index.ts
let activePath: string | null = null;          // 记住首次打开的路径
export function openDatabase(path?: string) {  // 去掉默认参数
  const target = path ?? activePath ?? config.dbPath;
  activePath = target; ...
}
export function currentDatabasePath(): string  // 备份/恢复一律用它
```

`routes/admin.ts` 的备份/恢复全部改用 `currentDatabasePath()`；
`api-test` 的恢复断言改为**重新登录后再数账号**（恢复必然换掉库，备份快照里没有之后建立的会话 —— 原断言测的其实是"会话没了"）。

### 2.4 验证

```
npm test 全绿：db/qr/zip 通过 · resolver 63 · api 225 · cli 18 · business 228
跑完后再查库：["pwchanger","suen","tester","tester2","throttle"] —— suen 保住 ✅
```

## 三、教训

- **"测试会污染生产数据"这类问题只有真跑一次才发现得了**：单元测试全绿、tsc 全绿，但跑一次就把账号冲掉了。
- 凡是"按配置路径操作文件"的地方（备份/恢复/迁移），都应该改为**问正在使用它的那一方**（SQLite 的
  `pragma_database_list` / 记录的 `activePath`），而不是问配置。
- 断言要测**它声称测的东西**：`恢复后差异账号消失` 原来混进了"会话失效"的副作用，重新登录后才测到数据本身。
