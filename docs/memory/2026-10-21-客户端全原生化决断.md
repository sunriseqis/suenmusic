## 一、为什么这次不接受"混合/折中"

用户口径（原话要点）：**"我不需要折中的妥协方案，我甚至可以接受暂时砍掉安卓端，只做鸿蒙和 iOS 端的开发。而不是弄一个各种小 bug 影响体验的伪迭代版本出来。"**

工程依据（本项目自己的历史）：

- 直连实验失败的第一根因是**让 WebView 承担系统级职责**：iOS 锁屏 5~15 秒挂起 WKWebView 的 JS → WBI 签名/流解析失效 → 原生队列只剩 1 首 → 曲末停播 → 系统吊销后台音频权限。
- 解析层已经迁回服务端（对），但**鸿蒙至今仍让 WebView 的 `<audio>` 承担"播放"** —— 同类错误换了一层。
- 混合方案（播放页原生 + 长尾 WebView）会让状态出现两个 owner。直连时代"8 秒 137 次 `makeItem` 的闭环"就是这种双 owner 的直接后果。

**结论：要么全原生，要么别做这次迭代。**

## 二、决断内容

1. **iOS**：SwiftUI 全原生（删 Capacitor 壳）。
2. **鸿蒙**：ArkUI 全原生（删 ArkWeb 容器）。
3. **Android**：**冻结在 v1.5**，停止功能迭代（保留安装包，是否下架待定）。
4. **Web SPA**：保留但**降级为管理面板**（只承载服务器配置，正好与 `requireWebAdmin` 渠道闸一致）。

## 三、两端可复用的现有资产（别重写）

- iOS：`SuenAudioCache.swift`（1438 行，4GB LRU + `LocalStreamProxy` 本地回环 + Range 续拉）整体保留；`SuenAudioPlugin.swift`（1553 行）抽出 `AudioEngine` 即可。
- 鸿蒙：`EntryAbility`（长时任务/安全区）、`SuenFormCard`/`SuenFormAbility`（卡片）、`NowPlaying`（卡片 payload/歌词窗口）保留；`PlayerControlHub`（卡片反控 WebView 的通道）与 `HarmonyMediaTakeover`（接管层）**作废删除**。
- 本轮刚写的接管层（310 行）会删掉，但其中的 AVPlayer / AVSession / 长时任务 / filesDir / Range 知识 **1:1 转移到原生播放内核**。

## 四、服务端几乎不动

客户端用到的 API 只有 **31 条路径**，全部已存在并有 490 项断言覆盖。原生化**不需要改服务端**。
注意：本轮已删除 plaza 三端点与用户歌单整链，原生客户端**不要**把它们加回来。

## 五、阶段门禁（防"伪迭代"）

S0 iOS 骨架生（六条命脉：登录/列表/播放/锁屏/切歌/断网缓存，3–5 天）
→ S1 iOS 功能对齐（1.5–2 周）→ S2 鸿蒙骨架生（3–5 天）
→ S3 鸿蒙功能对齐（2 周）→ S4 打磨（1 周）→ S5 切换与冻结（2–3 天）。

**每阶段真机验收不过就停下修，不带病推进。**

## 六、已拍板（2026-10-21）

1. **iOS 最低版本 = 26.0**，不再兼容低版本（macOS 15 都能跑 iOS 26 虚拟机，兼容低版本没有收益）。
2. **鸿蒙 = 26.0.0**（HarmonyOS NEXT 6），同样不兼容低版本。
3. **Web 面板保留，且它是 PC 端唯一客户端**（PC 不做原生客户端）→ SPA 必须继续是完整客户端，
   只能去掉原生壳专属代码；**不能**把 Home/Search/Favorites/Daily/Collection 页面删掉。
4. **Android 封库**：不再更新、不再有 CI 构建、不再分发上架。
