## 一、Android 桌面卡片（唯一还没做的大块功能）

按 `docs/plan/2026-10-19-桌面卡片设计定稿.md` 从零实现（RemoteViews）：

```
provider     SuenWidgetProvider（基类，渲染逻辑全在这）
             ├ SuenWidget2x2Provider → xml/suenmusic_widget_2x2.xml（小卡）
             └ SuenWidget2x4Provider → xml/suenmusic_widget_2x4.xml（宽卡）
快照         SuenWidgetState：SharedPreferences「suen_widget」单一真相源，
             封面异步下载到 filesDir/widget/cover.jpg
数据链       SuenAudioService（切歌/播放态/歌词行/5s tick）→ 快照 →
             AppWidgetManager.updateAppWidget → provider 按 options 宽度选布局
按钮         卡片 PendingIntent 广播 → 服务内 RECEIVER_NOT_EXPORTED 接收器
             （服务活着才绑点击；死了三键灰掉不响应，与鸿蒙 alive 分流一致）
收藏         web favorites store 经新桥 setWidgetFavorite 同步图标态；
             点击只打开 App（切换要过服务端，卡片不做乐观切换）
```

关键决策：

- **两个 provider 入口**（小卡/宽卡）而不是一个靠尺寸猜：选择器里一目了然，
  且小卡拉宽时 options 宽度 ≥240dp 会自动升级成宽卡布局
- **封面走文件 + setImageViewBitmap**：RemoteViews 跨进程不能读 file://，
  FileProvider 给 launcher 授权也绕，直接在本进程解码传 Bitmap 最稳
- **进度是静态快照**：设计定稿要求；额外加 5s 轻量 tick 让进度条不至于完全冻结
- **歌词三行**取服务已有的时间轴（当前行 ±1，当前行固定下标 1），
  不新增 web→原生的歌词通道

已知未验：真机效果（本机构建通过，APK 在 output/test/）。

## 二、数据库恢复（导入）

`POST /api/admin/db/restore`（requireWebAdmin，bodyLimit 200MB，base64 传文件）：

```
校验   文件头 SQLite format 3 → 临时连接 PRAGMA integrity_check →
       必需表 users / schema_migrations
兜底   VACUUM INTO <db>.pre-restore-<ts>.db（保留不删，路径随响应返回）
替换   closeDatabase → 删 -wal/-shm → rename 覆盖 → openDatabase → migrate
       （上传旧 schema 库也能恢复，迁移自动补齐）
回滚   替换/迁移失败 → 兜底拷回 → 重开 → 补迁移；回滚也失败则 500 提示手动抢救
```

界面：`AdminMaintenance.vue` 备份下载下方加「恢复数据库」区（选文件 → 警示 →
window.confirm → 上传 → 结果统计）。注意 JWT 无状态：恢复后旧令牌仍可用，
但只对恢复库里存在的账号有效。
