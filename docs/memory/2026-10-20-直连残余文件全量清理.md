## 一、清理背景

在完成阶段 1、2、3 的功能重构与全链路测试后，为了彻底兑现方案中“拒绝‘能跑就行’的修补匠心态”与“不留死代码、不留双轨逻辑”的架构决断，对代码库进行了全局依赖审查与物理清理。

---

## 二、清理与收敛清单

1. **彻底物理移除废弃目录与组件**：
   - `web/src/api/direct/`：已物理删除（含 `anchor.ts`、`catalog.ts`、`home.ts`、`matcher.ts`、`netease.ts`、`playlist.ts`、`resolve.ts`、`upstream.ts` 共 8 个直连取流与签名脚本）；
   - `web/src/views/DirectProbe.vue`：已物理删除；
   - `web/src/router/index.ts`：移除 `/probe` 诊断路由；
   - `web/src/offline/localdb.ts`：已物理删除（废弃客户端 IndexedDB 主数据库）。

2. **离线功能（去重与备份）回归服务端 API**：
   - `web/src/offline/dedupe.ts`：
     - 原先：直接在客户端 IndexedDB 读写，无法影响服务端真实数据；
     - 改为：统一调用服务端 `/api/favorites/dedup/preview` 与 `/api/favorites/dedup`，由服务端高效 SQL 进行「歌名 + 主歌手」分组并保留最早收藏项，执行后联动 `favorites.reload()` 刷新视图。
   - `web/src/offline/backup.ts`：
     - 原先：导出与导入仅操作端侧 IndexedDB；
     - 改为：导出直接读取服务端收藏曲目 (`fetchFavoriteTracks`) 与不喜欢列表 (`fetchDislikes`)；导入直接通过服务端 `/api/favorites/import` 与 `/api/recommend/dislike` 回写。

---

## 三、最终构建与交付产物

- **Web 构建**：运行 `npm run build`，编译产物中原先存在的 `localdb` 与 `DirectProbe` JS 分片已完全消失，核心 Bundle 更加轻量高效；
- **平台同步**：最新纯净 Web 产物已通过 `npx cap copy` 同步至 Android (`android/app/src/main/assets/public/`) 与 iOS (`ios/App/App/public/`)，并手工复制至鸿蒙 (`hw/entry/src/main/resources/rawfile/`)；
- **Android APK**：`./gradlew assembleDebug` 7s 编译成功，输出调试 APK。
