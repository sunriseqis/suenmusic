# 2026-10-22 用户裁定：首页播放类按钮不回补 + T10 关注项补充

> 来源：用户对 T10 交接单（`docs/plan/2026-10-22-鸿蒙端-T10-UI全面接入.md`）的批注。
> **规则**：用户在验收中做出的「移除/不加」类裁定，当场落入记忆文档——
> 防止后续 web-parity 单子按「web 有就要有」机械回补已裁掉的东西。

## 裁定一：首页播放类按钮不回补（T5.5 已移除）

- **事实链**：T5.5 验收中用户提出移除首页新歌区「播放全部」按钮（理由：点任意一首
  即全量装填播放队列，按钮冗余）→ 已删（按钮 + `Copy.playAll` + playSongs 中间层）。
- **web 侧真相**：web `TrackRow.vue` **没有**行内独立播放按钮——行本身整行可点即播放
  （aria-label「播放 xxx」），行内只有红心（和专属页的 dislike 组）。T10 原稿 §2.1
  「web 每行有播放按钮 → 补行内播放钮」是 Lead 预扫误记，**作废**。
- **约束**：后续任何单子不得给首页补「播放全部」或行内播放钮，除非用户重新提出。

## 裁定二：T10 需额外关注两处（原差距清单漏/未展开）

1. **迷你播放控件（PlayerBar compact / hw 迷你条）**：用户指出差距项没写。web 移动版
   `.mini` 形态 = `neu-raised-md` 凸面条 + 顶部 `neu-inset` 内嵌细进度条 + 封面（含
   占位）+ 歌名/歌手省略行 + 播放键，**整条点击展开全屏页、左右滑动切歌且滑动后合成
   click 不展开**（miniDragX ±80px 拖拽跟手）。逐元素对齐。
2. **底部 Tab 按钮（tabbar）整体风格**：用户指出差距大。web `MobileShell.vue` `.tabbar`
   = 图标 + 12px label 组合、active = t1 色 + `::after` 短指示条、整格触摸目标 ≥44px。
   hw 现为 sys.symbol 图标 + 文字 + 选中 scale(1.15)/accent（T5 动效定稿保留），但整体
   风格与 web 有明显差距——T10 需并排比对后对齐（动效口径不变：页面零动效 + 按钮级反馈）。
