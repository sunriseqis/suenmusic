## 六、纪律补录：提交必须跟 push

2026-10-25 复查发现**本地领先 origin 12 个提交** —— 从 iOS 批③起我把命令写成
`git commit -q -m ... && git log -1`（为了少一行输出），把 `git push` 漏掉了。

规则：**每条提交命令都必须以 `git push origin main` 收尾**，并在结束时用
`git status --short --branch` 确认没有 `ahead N`。
`-q` 只可能影响输出噪声，绝不能连带删掉 push。

## 八、起播慢（像等缓存）——根因与修法

链路：`AudioEngine.streamUrl()` 原来**无条件优先** `LocalStreamProxy`（127.0.0.1）→ 代理另开 URLSession 下载 → 按 256KB 泵给 AVPlayer，
而代理首包要`等上游响应头（12s）`+`等首字节嗅探 Content-Type（3s）`。实测服务端本身 `ttfb=0.34s`，所以慢在代理的串行等待。

修法（2026-10-25）：
1. `streamUrl()` **只在整首已落盘（`AudioCacheStore.isComplete`）时**走代理；否则直连 `/api/stream`，并用 `LocalStreamProxy.shared.entry()` 后台预热缓存。
2. 代理 `metadataTimeout` 12s → **1.5s**，首字节嗅探 3s → **0.3s**。
3. 打点：`[Start] play() 进入 / 令牌就绪 / 首字节 / 首次 playing`，用于实测前后对比。

## 九、Live Activity 封面（用户要求与旧版一致：歌名/歌手/封面齐全）

- widget 渲染进程**不能联网**，`AsyncImage` 不工作（系统报 Archive nil）。
- 做法：主 App 下封面 → `UIGraphicsImageRenderer` 缩到 **64×64 JPEG（q0.5，约 1–2KB）** → 放进
  `PlaybackActivityAttributes.ContentState.coverJPEG`（`Data` 自动 base64 随状态传输）→ widget 用 `UIImage(data:)` 渲染。
- 缓存：`LiveActivityController.coverCache[url]`，首次下完回调里再 `force` 推一次活动。
- 注：查 git 历史，本仓库从未有过 ActivityKit 实现（`git log -S ActivityKit` 只有我这条），
  所以用户记忆中「旧版灵动岛信息齐全」来自别的构建/别的 App —— 我们这版按同样信息量补齐。

- **灵动岛：可用**（模拟器 iPhone 17 上用户目视确认正常）。日志也有证据：渲染进程建起了

  → 属模拟器对**锁屏** Live Activity 的渲染限制（灵动岛走另一条渲染路径），**需真机验证**。
- 旧仓 `suenmusic-mobile` 已核实：`grep -rl 'ActivityKit'` **无任何文件** —— 旧版从未有过 Live Activity。
- 因此：岛 = 我们新做且已生效；锁屏卡 = 待真机（iPad 锁屏即可验，无需灵动岛）。
