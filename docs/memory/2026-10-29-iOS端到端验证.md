## 四、推荐语（发现并修复一个兼容 bug）

**问题**：`reason_for_display` 是审核精炼流程新增字段，该流程上线**之前**生成的歌单只有旧 `reason`，
读取路径只读新字段 → 存量用户整份歌单没有推荐语。

实测证据：
```
ai.daily.active:1  有 display 28/38   ← 修复后生成
ai.daily.active:2/4/5/6  有 display 0/40   ← 修复前生成，只有旧 reason
iOS 客户端：[Reco] 推荐理由 0 条；当前曲命中=否
```

**修复**：读取路径按「新字段优先、旧字段兜底」读（`p.reason_for_display || p.reason`），
两者都过同一道 `clampDisplay`。旧 reason 未经审核筛选属「审核没工作」而非「审核否决」，
兜底符合「只救审核没工作」的口径。

**修复后**：
```
API：40/40 首有 recommendReason
iOS：[Reco] 推荐理由 40 条；当前曲命中=是
样本：「寻光」→「郑云龙醇厚美声，弦乐层层推进的宏大叙事感」
```

## 六·补：真机验证（2026-10-29 晚）

**用户真机确认：灵动岛 / Live 已回归。**

这是昨晚那个根因修复的最终确认 —— 因果链完整闭合：

```
mpv 的 ao=audiounit 把会话改成 MoviePlayback + mixWithOthers(opts=1)
        ↓
iOS 判定本 App 为「次要音频」
        ↓
次要音频不参与 Now Playing
        ↓
锁屏 / 控制中心 / 灵动岛 全都不出媒体面板
```

修复后 `opts=0`、`mode=Default`，真机面板恢复。

**过程中我走错过一次**：先按「参照项目也没有」判定为预期行为，用户纠正后重新查，
才发现是两个参照项目都调了 `audio_session.configure()`（等价于我们的 setCategory），
而我们只在启动时设了一次、mpv 改完再没人纠正。
