# 2026-10-26 搜索三处缺陷修复与「酷狗+网易云+QQ」零翻唱架构定稿

## 一、搜索三处缺陷修复（已交付并上线，`6a9d4e3` / `6a9d643`）

### 1. 搜索分类为「歌手」时结果恒为空
- **根因**：鸿蒙端（`hw`）与 iOS 端（`ios`）搜索请求固定传 `limit=50`（`PAGE_LIMIT = 50`），而 QQ 音乐上游 `DoSearchForQQMusicDesktop` 在 `search_type: 1`（歌手分片）下有一个未文档化的硬限制——**只要 `num_per_page > 40`，上游直接返回 `code: 0, list: []` 空数组**（`num_per_page <= 40` 则正常返回歌手列表）。
- **修复**：
  - [`server/src/sources/qq/search.ts`](../../server/src/sources/qq/search.ts)：在 `fetchSearchSlice` 中对 `singer` 分片做上限钳制 `const effectiveLimit = slice === 'singer' ? Math.min(limit, 30) : limit`；
  - [`server/src/routes/catalog.ts`](../../server/src/routes/catalog.ts)：同步将 `hasMore.artist` 判据对齐为 `result.artists.length >= Math.min(limit, 30)`。
- **验证**：实测 `GET /api/search?q=周杰伦&type=artist&limit=50` 返回 11 位歌手，不再为空。

### 2. 搜索清除按钮不会清除搜索结果 & 搜索历史消失
- **根因**：
  - **鸿蒙端（`hw/entry/src/main/ets/pages/SearchPage.ets`）**：`NeuInput` 点击清除按钮（`×`）仅将绑定的 `keyword` 置为 `''`，未触发清空回调；`SearchPage` 的 `searched` 仍为 `true`、旧结果列表仍挂在界面上，导致「最近搜索」历史区（仅在 `!this.searched` 时渲染）无法重新显示。
  - **Web 端（`web/src/components/neu/NeuInput.vue` & `web/src/views/Search.vue`）**：`NeuInput` 缺少内置一键清除（`×`）按钮；`Search.vue` 在输入框清空时未重置结果，且未渲染本地搜索历史标签。
- **修复**：
  - `hw`：`SearchPage.ets` 为 `@State keyword` 增加 `@Watch('onKeywordChange')`，当输入被清空时立即调用 `clearSearchState()` 清空 `songs/albums/artists/playlists`、置 `searched = false` 并刷新 `recentList()` 恢复搜索历史展示。
  - `web`：`NeuInput.vue` 补齐一键清除按钮（`×`）与 `clear` 事件；`Search.vue` 监听 `query` 为空自动清空结果，并补齐 `suen_recent_search` 最近搜索历史胶囊与清空能力。
- **构建产物**：已重编 `web/dist`、重启 `suenmusic.service`、重编并安装鸿蒙 [`output/suenmusic-2.0.0.hap`](../../output/suenmusic-2.0.0.hap) 与飞牛 [`output/suenmusic-v2.0.0.fpk`](../../output/suenmusic-v2.0.0.fpk)（59.12 MB）。

## 二、「酷狗为主 + 网易云为辅 + QQ 兜底/门面」零翻唱方案定稿（明日实施）

通过 `/grill-me` 逐层对齐并实测上游报文，最终确立了兼顾**「绝不显示翻唱」、「补齐网易云独有原唱（如《知我》、夏日入侵企划）」、「规避 QQ 2001 限流」与「拿到酷狗元数据即拿到播放源（点播 0 二次搜索）」**的完整方案，详见计划单：

👉 **[`docs/plan/2026-10-26-多源元数据聚合与零翻唱直取方案.md`](../plan/2026-10-26-多源元数据聚合与零翻唱直取方案.md)**

### 核心决策纪要
1. **角色分工**：
   - **QQ 音乐**：保留负责**首页、排行榜、歌单广场**（权威度高）；在搜索与建库中退居**第三顺位兜底**（仅当酷狗限流/异常时补位）。
   - **酷狗音乐**：作为**搜索、歌手热门歌曲、后台建库的第一主源**。因酷狗概念版每日自动签到已具备完整 FLAC/320k 取流能力，且搜索返回天然带齐 `FileHash / SQFileHash / HQFileHash / AlbumID / MixSongID`，**搜到元数据即拿到播放源，点播时直接按预存 hash 取流（0 次二次搜索）**。
   - **网易云音乐**：作为**并发辅源**，专门补齐酷狗/QQ 缺失的独有原唱（如《知我 - 国风堂/哦漏》）与独立乐队作品（如「夏日入侵企划」的《想去海边》《尘星》《夏末的歌》）。因当前无网易云黑胶 VIP，`ne_` 独有曲目点播时直接走 **B 站**取流。
2. **「零翻唱」三级过滤（绝不显示任何翻唱）**：
   - **单源官方原唱硬门槛**：酷狗强制要求 `IsOriginal === 1`；网易云切 `/api/cloudsearch/pc` 并强制要求 `originCoverType === 1`（直接团灭 `originCoverType === 2` 的翻唱与 `0` 的野鸡合辑）；QQ 剔除 `version === 7/28`。
   - **跨源原唱对质审判**：只要任一源通过官方标记认定了某歌名的正牌原唱歌手（如网易云认证《知我》原唱为 `国风堂/哦漏`），同名曲目中凡歌手不符的无标条目（如 QQ 的 `江肆 / 安子须`）一律判定为翻唱并剔除。
   - **衍生变种清洗**：过滤一切器乐/钢琴/伴奏/DJ/慢摇/变速/抒情版/片段，**仅保留原唱歌手本人的官方演唱会 `(Live)` 版**（排在录音室原版之后）。
3. **同曲去重与混排**：
   - 同曲去重主权按 **`酷狗 (kg_) > 网易云 (ne_) > QQ (qq_)`** 保留主键（以保留酷狗直取流 hash 凭证）；
   - 多源不同曲目按 **「精确命中置顶 + 酷狗与网易云原唱 1:1 交替穿插（Interleave）」** 排序。
4. **后台建库风控保护**：
   - `library-builder.ts` 切换为「酷狗为主 + 网易云为辅 + QQ 兜底」，但**严格保留「仅凌晨 3:00–6:00 闲时窗口」与慢速特遣策略**，防止全天建库把网易云（405）或酷狗打进限流。
