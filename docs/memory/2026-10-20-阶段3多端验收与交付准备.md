## 一、架构收敛与重构总结

本次重构彻底废弃了 10/17 ~ 10/19 期间妥协的“客户端直连”与“本地优先（IndexedDB）”实验分支，**全面回归服务端作为单一真相源（Single Source of Truth）的高可用架构**：

1. **核心边界收敛**：
   - **服务端**：SQLite 集中管理用户体系（Admin/Member）、收藏、历史、歌单、手动音源锚点（Anchor），统一承担 B 站 WBI 签名、Cookie 扫码维系与音源流代理（`/api/stream/:id` 支持 Range 206 透传与自动自愈）；
   - **移动端（iOS / Android / 鸿蒙）**：原生全队列加载（`AVQueuePlayer` / Media3 `ExoPlayer`），搭配端侧 4GB 磁盘 LRU 缓存与网络状态监听（`NetworkMonitor` / `ConnectivityManager`），彻底根治后台切歌冻结、锁屏断流与切网卡死；
   - **Web / 桌面端**：轻量化哑光硬件（Matte Hardware）响应式界面，全平台共用一套统一协议。

## 三、真机实测指引（Checklist）

完成服务端部署与客户端安装后，建议按以下测试用例进行体验验收：

| 序号 | 验证场景 | 操作步骤 | 预期效果 |
| :--- | :--- | :--- | :--- |
| **TC-01** | **初次开箱与登录** | 新装客户端打开，输入服务器地址 | 自动拦截至登录页；若库为空自动提示「创建管理员」；登录后进入首页并记住地址 |
| **TC-02** | **跨端收藏与锚点同步** | 在 Web 端收藏一首歌曲或手动锚定音源 | Android / iOS 端刷新或重新切歌，收藏状态与指定音源立即生效同步 |
| **TC-03** | **iOS 锁屏连续切歌** | iOS 端播放歌单，锁屏熄屏挂后台 1 小时以上 | 原生 `AVQueuePlayer` 连续自动跳下一首，不卡在曲末，后台音频保活不断 |
| **TC-04** | **网络切换（弱网断网）** | 播放过程中切断 Wi-Fi（切换到蜂窝），或弱网环境下暂停后恢复 | `NetworkMonitor` 毫秒级重试，音频从已缓存字节无缝续播，不跳回开头、不卡死 30 秒 |
| **TC-05** | **离线冷启动进入** | 开启飞行模式后彻底杀掉 App 重开 | `session.bootstrap()` 识别本地有效凭据直接放行，进入离线态播放磁盘已缓存歌曲 |
| **TC-06** | **桌面卡片** | 安卓桌面添加 SuenMusic 小卡/宽卡，播放中切歌、点三键、收藏一首 | 快照随播放状态刷新（封面/歌词/进度），按钮可控播放，收藏图标同步；服务退出后回空态、三键灰掉 |
| **TC-07** | **数据库恢复** | Web 面板「数据维护」上传此前的备份 .db | 校验通过后整体替换，账号/曲目回到备份时状态；非法文件被 400 拒绝；自动留 `.pre-restore-*` 兜底 |
| **TC-08** | **管理操作渠道边界** | 管理员在原生壳设置页逐区查看；用 Bearer 令牌直接打 `/api/admin/*` | 原生壳不见账号管理/数据维护/AI 模型/运行情况；Bearer 打管理接口一律 403（「管理操作仅限 Web 面板执行」） |
