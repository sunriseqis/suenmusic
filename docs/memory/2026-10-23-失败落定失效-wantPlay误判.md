# 2026-10-23「1 分钟没有任何报错」真凶：挂起窗口用 wantPlay 判恢复（永不落定）

## 真凶（一行逻辑错）

`fail()` 里 2.5s 挂起窗口的到期回调原本写的是：

```ts
if (this.wantPlay) { return; }   // 误把「播放意图」当成「已恢复播放」
```

但 `wantPlay` 是**播放意图**，失败后它一直是 `true`（只有 `settleFailure()` 里才清），
于是窗口到期**永远命中这个 return** → 既不发通知、也不写 `np_error`、也不停 → 
用户看到的就是「点了《怎么》过 1 分钟一条报错都没有」。

改成判真实状态：`if (pl !== null && pl.state === 'playing') return;`

并且因为这次是冷启动续播（`manual=no`，自动装载）所以按规则跳到下一首。

## 顺带确认的三条链路（本次一并验证）

1. `装载失败于[prepare] code=5400102` + `装载失败于[AVPlayer] code=5411004` 属于**同一次失败的双报**，
   `failHandled` 正确挡下第二次（日志有 `fail 被 failHandled 挡下`）。
2. 6s 卡死看门狗（`装载超时`）在 AVPlayer 既不报错也不到 playing 时兜底，按同一条 `fail()` 走。
3. `settleFailure()` 里补的 `publishState()` 让播控立即变暂停，系统卡片不再自己外推进度。

## 教训

- **「意图」和「状态」不能混用**：`wantPlay` 是意图（用户想不想播），`player.state` 才是状态（有没有在播）。
  本端已有过一次同类教训（T4 的 `wantPlay=false` 导致重装成暂停态）。
- 新增的 `fail 处理中 / fail 被挡下 / 失败落定` 三条 hilog 保留：失败链是黑盒，必须能从日志还原决策。
