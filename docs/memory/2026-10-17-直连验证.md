# 无后端直连：真机验证结论（2026-10-17）

**结论：三端可以脱离自建后端直接使用。三个问题全部在真机上验证通过。**

验证方式：`output/test/SuenMusic-android-debug.apk` 里的诊断页（`/probe`），
真机、移动网络、**零登录凭据**。第二轮全绿。

```
✅ 取 buvid3 / buvid4              游客设备标识，不需要登录
✅ QQ音乐 搜索（元数据）            命中 5 首
✅ B站 搜索（search/all/v2）       有候选
✅ 本地存储读写                    IndexedDB 写入并读回
✅ 解析音频地址                    playurl 拿到音轨
✅ 音频 CDN Referer 校验           带 Referer 可播
✅ 原生播放器播放直连地址           出声
```

## 一、最容易踩的坑：fetch 会静默丢弃「禁止头」

**第一轮真机全灭（5 种请求头组合全是 412，返回体一字不差），根因在此。**

`Origin` / `Referer` / `Cookie` 属于 **fetch 规范的禁止头**（forbidden header
names），`fetch()` 会**静默丢弃**它们 —— 不报错、不警告。所以：

```js
// ❌ 这三个头一个都发不出去，请求等价于"仅 UA" → B站回 412
fetch(url, { headers: { 'User-Agent': UA, Referer: '...', Cookie: 'buvid3=...' } });
```

**踩坑时的诊断要点**：如果多个请求头组合得到**完全相同的响应体**，
说明请求头不是变量 —— 它根本没发出去。这比逐个试头快得多。

**正确做法**：原生环境直接调 `CapacitorHttp.request()`，把 headers 当参数交给原生层。

```js
// ✅ 插件 API 路径，headers 由原生发送
import { Capacitor, CapacitorHttp } from '@capacitor/core';
const res = await CapacitorHttp.request({ url, method: 'GET', headers: { 'User-Agent': UA, Referer, Cookie } });
// 返回 { status, data(已解析), headers, url } —— data 不需要 .json()
```

已核实的两点（不要凭印象）：
- `@capacitor/android/.../plugin/util/CapacitorHttpUrlConnection.java:setRequestHeaders`
  把每个头原样 `setRequestProperty`，**不做任何过滤**
- `Bridge.java:663` 在 `registerAllPlugins()` 里**无条件注册** `CapacitorHttp`
  —— 它是核心插件，**不经过 `capacitor.plugins.json`**（那个文件对核心插件一直是 `[]`，
  看到空数组不要以为没注册）

⚠️ 另外：`capacitor.config.ts` 里开 `plugins.CapacitorHttp.enabled` **只影响
`fetch`/`XMLHttpRequest` 的补丁**。补丁没生效时不会报错，只是头被丢掉。
**要可靠就别依赖补丁，直接调插件 API。**

## 二、B站：游客能拿到什么

**凭据分两层，别混为一谈（混了会得出"必须登录才能播"的错误结论）：**

| 凭据 | 性质 | 怎么拿 | 作用 |
|---|---|---|---|
| `buvid3` / `buvid4` | **游客设备标识** | `GET /x/frontend/finger/spi`，**无需登录** | 过反爬，搜索/cid/playurl 都要 |
| `SESSDATA` | 登录凭据 | 扫码登录 | **只影响音质档位**，不是播放前提 |

**端点必须用 `search/all/v2`**：

```
✅ /x/web-interface/search/all/v2?keyword=...     沙箱实测 20 个视频候选
❌ /x/web-interface/search/type?search_type=video  沙箱实测 0 候选
```

服务端一直用的是前者，直接照抄它。响应是**分段结构**：

```ts
// data.result[] 里每段带 result_type，视频在 'video' 那段
for (const sec of json?.data?.result ?? []) {
  if (sec?.result_type === 'video') return sec.data ?? [];
}
```

**搜索必须限流**：服务端专门做了 400ms 串行间隔，注释写着「B站搜索敏感，
并发突发会触发 -412 风控」。客户端照做（实测用 500ms）。

**音频 CDN 强制校验 Referer**：带 → 206，不带 → **403（一个字节都拿不到）**。
而浏览器/WebView 发不出 Referer —— 这就是音频**必须走原生播放器**的原因。
Android 侧在 `SuenAudioCache` 的 http 数据源上补默认头即可。

**不需要 `Origin`**（沙箱实测 `UA + Referer + Cookie` 即可 200）。这点有用：
Android 的 `HttpURLConnection` 对 `Origin` 有额外处理，绕开它少一个变量。

## 三、QQ音乐：元数据主力，零凭据

`u.y.qq.com/cgi-bin/musicu.fcg` 的 `DoSearchForQQMusicDesktop`，**不带任何凭据**
即可用，只要 UA + `Referer: https://y.qq.com/`。

`req.code === 2001` 表示**风控冷却**，不是参数错误 —— 服务端有 `qqCooldown`
处理这个码，客户端也要认。

## 四、原生侧的硬拦截（脱离后端的第一处卡死）

`android/.../SuenAudioService.java` 原先：

```java
if (SuenAudio.getBaseUrl() == null || SuenAudio.getSessionToken() == null) {
  return Futures.immediateFailedFuture(new IllegalStateException("尚未配置服务器地址或流会话令牌"));
}
```

**没配服务器地址就直接抛异常** —— 这是"脱离后端"在原生侧最先卡住的地方。
改法是加"直连例外"：整队条目都有 `directUrl` 时放行。

## 五、复现方式

```bash
cd web && npm run build
npx cap sync android
cd ../android && ANDROID_HOME=... ./gradlew assembleDebug
# 装到真机 → 停在登录页 → 底部「无后端直连诊断 →」→ 开始诊断
```
