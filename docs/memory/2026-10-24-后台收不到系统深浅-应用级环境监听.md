# 2026-10-24 「切系统色后只有唤回 app 卡片才变色」：改用应用级环境监听

**用户实测**：切系统深浅后，**唤回 app 前台**卡片立刻变色；不退前台就绝不变色，**哪怕切歌也不变**。

## 两个根因

1. `Ability.onConfigurationUpdate` 在应用**后台时经常收不到** → 我们的 `onConfigurationUpdate` 里的重推不会发生；
2. 更关键：系统态缓存 `Theme.sysDark` / `AppStorage['system_dark']` 因此**一直是旧值**，
   所以哪怕切歌触发了 `AVSessionManager.syncCard()`，`Theme.darkNow()` 算出来的仍是旧的深浅 → 卡片纹丝不动。
   「唤回前台」时 Ability 收到配置更新 → 缓存刷新 → 随后那次推送才把卡片改正。

## 修法

- 注册 **应用级环境订阅** `ApplicationContext.on('environment', EnvironmentCallback)`（SDK 注释明确写了覆盖
  「system dark/light color mode change」，且退到后台也会回调）。
- `SuenEnvCallback extends EnvironmentCallback`：`onConfigurationUpdated(cfg)` → `applySystemColorMode(cfg.colorMode)`。
- `applySystemColorMode(cm)`：`Theme.syncSystemDark()`（现在**返回是否发生变化**）→ 仅在变化且当前是
  「跟随系统」时 `pushSnapshotToCards(snap, sysDark)`。`Ability.onConfigurationUpdate` 也复用同一函数（去重后不会重复推）。

## 实测

装机日志确认：`系统环境监听注册成功`（应用级订阅注册成功）。
模拟器无法用 hdc 改系统深浅（无 `persist.sys.darkmode` 参数），**本条需用户实机复测**。

## 仍存限制（如实记档）

- 推送依赖 **App 进程活着**；进程被系统回收后，卡片只能由系统定时刷新兜底，
  届时走 `SuenFormAbility.onUpdateForm` → `Theme.darkFor(ctx, ctx.config.colorMode)`（扩展进程的 config 是准的）。
  → 观感是「过一会儿自己变对」。要彻底实时，只能让卡片改回资源驱动（但那会失去跟 app 内设置的能力），属取舍。
