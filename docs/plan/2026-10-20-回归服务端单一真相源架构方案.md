## 一、背景与决断

10/17 ~ 10/19 期间尝试的「无后端直连」与「本地优先数据层（IndexedDB）」在 Android 侧通过 `CapacitorHttp` 验证可行，但在全端落地（特别是 iOS 端）遇到无法逾越的系统级限制：
1. **iOS 锁屏挂起 JS**：无法在后台执行 B 站 WBI 签名加密与动态取流；
2. **切歌死循环与队列断流**：原生队列阉割成单曲以防跳歌，导致曲末断流被 iOS 立即剥夺后台音频权限；
3. **数据割裂**：本地优先导致收藏、历史、播放进度与关键的“手动锚点（Anchor）”沦为单机孤岛，三端体验彻底撕裂；
4. **反爬维护风险**：客户端直连将风控规则与签名加密下放到客户端，任何规则微调都需要重新签名发版。

**核心决断**：拒绝“能跑就行”的修补匠心态，**彻底终止客户端直连与本地优先路线，全面回归以服务端为单一真相源（Single Source of Truth）的高可用架构**。

## 二、保留与清理边界

```
                  【统一架构边界】
┌────────────────────────────────────────────────────────┐
│            服务端 (Server as Single Source)            │
│  - 单一真相源：SQLite 存储 收藏 / 历史 / 进度 / 锚点     │
│  - 集中特权：Admin 账号体系 / AI 模型配置 / 音源扫码     │
│  - 统一流网关：/api/stream/:id (带 Range / 节流 / 自愈)│
└───────────────────────────┬────────────────────────────┘
                            │ 标准 API & 字节流
         ┌──────────────────┼──────────────────┐
         ▼                  ▼                  ▼
   【iOS 端】          【Android 端】      【Web/桌面端】
   - AVQueuePlayer    - Media3 ExoPlayer  - HTML5 Audio
   - SuenAudioCache   - 磁盘 LRU 缓存     - 响应式 UI 同步
   (本地 4GB 磁盘代理)
```

### 1. 彻底清理（废弃）
* 废弃 `web/src/api/direct/` 目录；
* 移除客户端所有直连解析（`resolveDirect`、`matcher`、`directQQPlaylist`、`directSearch` 等）；
* 移除端侧 IndexedDB（`offline/localdb.ts`）作为主数据库的逻辑，恢复乐观更新 + 服务端持久化；
* 移除原生端 `setDirectUrl` 与 `directOnly` 队列跳过逻辑。

### 2. 完整保留（资产）
* **单仓工程（Monorepo `suenmusic`）**：彻底杜绝多仓库未提交导致的 CI 产物不一致；
* **管理员特权与多用户体系**：首个注册为 Admin，普通成员隔离；Admin 独享全局扫码、AI 模型增删改、账号维护；
* **客户端轻量化设置页**：移动端不承载 AI 增删改、不承载复杂的扫码绑定，保持纯粹的播放器体验；
* **哑光硬件（Matte Hardware）全新视觉**：无外阴影、琥珀状态色、平铺发丝线、精炼的桌面版式与移动端交互。
