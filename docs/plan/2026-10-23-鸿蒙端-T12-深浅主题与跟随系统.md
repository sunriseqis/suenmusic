## 一、目标（对齐 web，不多不少）

web 现状（`web/src/stores/ui.ts` + `web/src/styles/tokens.css`）是**三态**：

| 态 | web 行为 | hw 要求 |
|---|---|---|
| `system`（默认） | `prefers-color-scheme` 跟随系统，系统切换即时生效 | 跟随系统深浅，**系统切换即时生效（不重启、不重进页面）** |
| `dark` | `data-theme='dark'` 强制深色 | 同 |
| `light` | `data-theme='light'` 纸白浅色 | 同 |

持久化：web 存 `localStorage['suenmusic.theme']` → hw 存 `preferences`（与其它设置同口径）。
入口：设置页「主题」区（T10 §2.5 已预留该区块，现为空壳）。

**卡片**：桌面卡片（2x2 / 2x4）**自动跟随系统深浅**（不跟 app 的手动覆盖，卡片由 FormAbility 渲染，以系统为准）。

## 二、现状与差距

| 项 | 现状 | 差距 |
|---|---|---|
| 令牌 | `common/Tokens.ets`（由 `scripts/gen-brand-tokens.py` 从 web `tokens.css` 生成）**已含浅色全套**（`bgLight/panelLight/…`）但**全部没人引用** | 需要「当前主题 → 取哪一套」的解析层 |
| 类型 | `Tokens.x` 是 `string` 常量，直接进 `.backgroundColor()/.fontColor()` | 若走资源化需改 `ResourceColor`（接受 `$r('app.color.*')`） |
| 主题态 | 无。`AppStorage` 无主题键，无 `getHostContext().config.colorMode` 监听 | 需要 `Theme` 状态层 + `onConfigurationUpdate` 接线 |
| 系统跟随 | `module.json5` 无色彩模式声明；Ability 未处理 `onConfigurationUpdate` | 需要监听 `Configuration.colorMode` |
| 强制覆盖 | 未用 `ApplicationContext.setColorMode()` | 需要（仅 `dark`/`light` 态调用，`system` 态清回 `COLOR_MODE_NOT_SET`） |
| 资源目录 | `resources/base/element/color.json`（浅）+ `resources/dark/element/color.json`（深）**只有启动窗等零星几项** | 需要把全套语义色灌进两套 `color.json` |
| 卡片 | `forms/SuenFormCard.ets` 颜色**硬编码/深色** | 卡片色改走资源 → 系统深浅自动切换 |
| 硬编码色 | 全端散落 `#E5484D`（danger）、`#FFDAD6`、`#8A1F18`（收藏红底）等豁免色 | 需要**浅色版对应值**（浅底红字对比度要够），逐处核 |

## 三、方案（三阶段，按序不可跳）

### 阶段 1：资源化（打地基，卡片自动跟随只能走这条）

1. 改 `scripts/gen-brand-tokens.py`：除现有 `Tokens.ets` 外，**再生成两份 `color.json`**——
   `resources/base/element/color.json`（浅色值）+ `resources/dark/element/color.json`（深色值），
   key 用语义名（`bg / panel / panel2 / line / t1 / t2 / accent / accentText / scrim / hi / danger / favBg / favInk …`）。
2. `Tokens` 常量改指向资源：`static readonly bg: ResourceColor = $r('app.color.bg')`。
   **一次性机械改造，调用点不用动**（`.backgroundColor(Tokens.bg)` 天然接受 `ResourceColor`）。
3. 卡片（`SuenFormCard.ets` / 卡片 `color.json`）同步换资源，验证系统深浅下卡片自动变色。

### 阶段 2：主题态 + 跟随系统

4. 新增 `common/Theme.ets`：`ThemeMode = 'system' | 'dark' | 'light'`；
   `AppStorage` 键 `K_THEME_MODE`；`Theme.apply()` 在 `system` 态调 `setColorMode(COLOR_MODE_NOT_SET)`、
   在 `dark`/`light` 态调 `setColorMode(COLOR_MODE_DARK/LIGHT)`；`preferences` 持久化。
5. `EntryAbility.onConfigurationUpdate` → 若 `themeMode === 'system'` 就 `AppStorage` 里 bump 一个
   `K_SYSTEM_DARK`（供需要的页面读，如状态栏/沉浸式 scrim）；资源化后**颜色本身已由系统自动切**。
6. 设置页「主题」区：三态选择（跟随系统 / 深色 / 浅色），与 web `theme sheet` 同文案同顺序。

### 阶段 3：逐页校验与收口

7. 逐页浅色实机对拍：首页 / 专属 / 收藏 / 搜索 / 设置（三 tab + 四弹窗）/ 播放页（含歌词 sheet、队列、锚定窗、more sheet）/ 迷你条 / Tab 栏 / 空态 / 骨架屏。
8. danger 语义色与图片 tint（`fillColor` 的收藏红心、`card_heart*`）逐个核对比度。

## 四、规模

约 1 天生成器 + 资源化机械改造，1 天主题态与设置页，1–1.5 天逐页浅色打磨与验收 → **3–4 天**。
（卡片双主题需真机/模拟器实拍，不能只靠代码推断。）

## 五、验收（8 条）

| # | 判定 |
|---|---|
| 1 | 设置页可切「跟随系统 / 深色 / 浅色」，重启 app 记忆保持 |
| 2 | `system` 态下，系统切换深浅后 app **即时变色**（不重启、不重进页面） |
| 3 | 全部 12+ 页面在浅色下无「深色残留」（白字白底、深色卡在浅底上、状态栏对比、骨架屏、空态） |

| 7 | 五条命脉回归（登录/播放/后台锁屏/切服保位置/断网播缓存）两套主题各跑一遍 |
| 8 | `check-arkts` 0 ERROR + clean build 无新增 WARN + faultlogger 无新增 jscrash |

## 六、边界与禁止

- ❌ 不改 `web/` 的 `tokens.css` 与主题 store（web 已有三态，是**对齐基准**）；要改须先报 Lead。
- ❌ 颜色只走 `Tokens.*` / `$r('app.color.*')`；**禁止**为图省事在任何页面写裸色值（danger 豁免仍限 `#E5484D`）。
- ❌ 不借主题改造顺手改布局/文案（本单一件事）。
- ⚠️ 卡片跟随**系统**，不跟 app 内手动覆盖（FormAbility 独立渲染，技术上拿不到 app 的 `setColorMode`）——
  这条与用户「卡片自动跟随系统」的原话一致，别自作主张让卡片跟 app。

## 七、坑位（预判）

| 坑 | 说明 |
|---|---|
| `Tokens.ets` 是生成物 | 手改必漂移（文件头就是这么写的）→ 全部改动走 `gen-brand-tokens.py` |
| `string` → `ResourceColor` 类型扩散 | 少数地方把 `Tokens.x` 存进 `@State x: string` 会编译报错，需逐个收窄 |
| 半透明色 | `scrim/hi/posterScrim` 在两套里 alpha 不同，浅色下 `hi` 是 95% 白、深色是 6% 白——别统一 |
| SymbolGlyph 颜色 | `.fontColor([...])` 传的是数组，资源化后类型要对齐 `ResourceColor[]` |
| 卡片资源 | 卡片的 `color.json` 需与 entry 的 key 同名，否则卡片取不到值 |
| `setColorMode` 时机 | 必须在 `AbilityStage`/`onCreate` 早期或用户操作时调，冷启动要按持久化值先设再建 UI（否则闪一次深色） |
