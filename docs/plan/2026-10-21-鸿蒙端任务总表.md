## 一点四、设计基准（**全局，覆盖所有单子 —— 2026-10-21 用户更正**）

**鸿蒙端是移动端原生应用，设计基准 = HarmonyOS Design 官方规范，不是 PC 端 Web。**

PC Web（`DesktopShell` 侧栏 + 海报横滑 + CoverCard 网格 + Neu 拟物）与移动端是**两套交互逻辑
与页面规则**：前者有侧栏导航、悬停态、宽幅布局；后者是底部 Tab、拇指热区、单列信息流。
把 PC Web 当设计依据，产出物会是"手机上的网页"。

| 层 | 基准 |
|---|---|
| **交互/手势（一等）** | **`web/` SPA 的移动端行为**（`max-width:767px` 断点）：列表行右滑收藏/取消、迷你条左右滑动切歌、下拉刷新。手势参数照抄（见 §一点四.1） |
| 交互/布局（二等） | HarmonyOS Design：底部 Tab、大标题、分组列表、系统转场 |
| 组件观感 | **哑光硬件体系**（项目既有视觉语言）：面板色与底色一层色差 + 1px 发丝线 + 顶沿 1px 内高光，全部由 `Tokens` 表达；**不用外阴影**（那是旧拟物的软塑料，两端都弃用） |
| 品牌一致 | 琥珀 accent + 哑光深底 + 品牌 LOGO，"一眼是 SuenMusic"即可 |

**纠偏记录**：用户 2026-10-21 两次纠正——①不要拿 PC Web 当移动端基准（已改）；②**移动版 Web 是"正确的"**，
它就是移动端的既定交互设计，鸿蒙端要做的不是"发明移动交互"，而是**把它的手势逐个原生化**。
下表是移动版 Web 已有的手势清单（鸿蒙端必须一一对齐）：

| web 手势 | 位置 | 鸿蒙对应任务 |

### 一点四.1 手势参数表（照抄，两端手感一致）

来源：`web/src/components/TrackRow.vue`（右滑收藏）与 `QueuePanel.vue`（右滑移除）。

```
SWIPE_GATE        = 8px    // 判定为水平滑动的最小位移
VERTICAL_COMMIT   = 24px   // 竖直认输阈值：先往下拉超过它 → 让位给下拉刷新
SWIPE_DAMP_AT     = 150px  // 超过此值进入阻尼区（×0.25）
SWIPE_THRESHOLD   = 85px   // 松手触发动作的阈值
SWIPE_OUT         = 360px  // 触发后动作区停留的最终位移（配合 200ms 过渡）
SWIPE_EXIT_MS     = 200    // 触发后动作区滑出动画时长
方向              = 只认右滑（动作区从行左侧拉出）；左滑留给未来
合成 click         = 手势结束必须吞掉（capture 阶段），否则误切歌
```

鸿蒙端对应实现：`List` 行内 `PanGesture`/`SwipeGesture`（direction: Horizontal），
或行组件内 `onTouch` 自行判定——由执行方按官方规范选择，但**参数与语义必须一致**。

| 类别 | 含义 | 例子 |

| **契约（必须遵守）** | 服务端字段/路径/语义、状态机时序、验收判定 | `hasMore` 是分片级"还有下一页"不是总数；`shortfall` 不是错误；`audioRendererInfo` 只在 `initialized` 设；切服后 `positionMs` 差 < 3 秒 |

## 三、全局不可破的六条（跨所有任务）

1. **播放状态机由 `stateChange` 唯一驱动**：`url` 只在 `idle` 赋、`audioRendererInfo` 只在 `initialized` 设、`prepare` 在 `initialized`、`play` 在 `prepared`
2. **单首失败不是致命错误**：`failStreak < 3` → 600ms 后跳下一首；`≥ 3` 停下给人话；`fail()` 有单次闸门
3. **AVSession 推送有闸门**：在飞即丢 + 900ms 间隔 + 按 `assetId` 去重（含 `currentMetadata !== null`）
4. **UI 不持有真相**：队列/播放态只读快照（`K_QUEUE_VERSION` / `K_INDEX`），增删改一律走内核方法
5. **缓存只落 `filesDir`**，删除时跳过正在播放的文件
6. **颜色只走 `Tokens.*`**（唯一例外错误色 `#E5484D`）；进入 T5 后尺寸也只走 `Dim.*`
