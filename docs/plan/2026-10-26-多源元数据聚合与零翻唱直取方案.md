## 一、背景与实测破局点

### 1. 痛点复盘
1. **QQ 搜索高频限流（code 2001）**：原架构以 QQ 为唯一元数据与搜索主源，前台搜索、歌手详情页（底层同样调搜索接口）及后台建库极易撞上 `2001` 风控冷却。
2. **单源曲库结构性缺失**：
   - 国风/独立音乐原唱（如《知我 - 国风堂/哦漏》）在 QQ 和酷狗均只有野鸡翻唱，正版原唱只在**网易云**；
   - 独立乐队（如「夏日入侵企划」）代表作《想去海边》《人生浪费指南》《夏末的歌》《尘星》绝大部分在**网易云**，QQ 歌手页仅 17 首且混有盗版变体名（`夏日入～侵企画-极恶～都市`）。
3. **以往「Q 抓元数据 → 再搜网/酷抓音频」的双重搜索浪费**：
   - 服务端实际音频播放靠 **酷狗概念版 VIP（每日自动签到领 SVIP）+ B 站兜底**（当前网易云账号 `vipType = 0` 无黑胶 VIP，且根本不使用 QQ 取音频流）。
   - 若直接以 **酷狗** 为元数据第一顺位，搜索返回的单曲本身就已携带完整播放凭证（`FileHash` / `HQFileHash` / `SQFileHash` / `SuperFileHash` / `AlbumID` / `MixSongID`），**拿到元数据即拿到播放源，点播时无需二次搜索**。

### 2. 原唱官方标记实测发现（解决「酷狗/网易翻唱泛滥」的根本抓手）

## 三、「零翻唱」三级过滤铁律（绝不显示任何翻唱）

### 第一级：单源官方原唱位硬准入
1. **酷狗**：只放行 `IsOriginal === 1` 的曲目，或歌手与已知原唱一致的本人官方 `(Live)` 曲目；其余 `IsOriginal === 0` 一律丢弃。
2. **网易云**：将 `vendors/netease/module/search.js` 单曲搜索切至 `/api/cloudsearch/pc`，**只放行 `originCoverType === 1`** 的曲目；`originCoverType === 2`（翻唱）与 `0`（野鸡合辑/未认证上传）一律丢弃。
3. **QQ（兜底位）**：丢弃 `version === 7`（改编/翻唱）、`version === 28`（DJ 版）及标题含嵌套书名号 `XX《歌名》` 的条目。

### 第二级：跨源原唱对质审判（消灭无标野鸡翻唱）
1. 汇总当次多源结果时，收集所有带官方原唱认证（酷狗 `IsOriginal === 1`、网易云 `originCoverType === 1`、QQ `tag === 11`）的条目，建立 **「归一化歌名 → 官方原唱歌手名集合」** 映射表。
2. 二次扫描所有候选曲目：若某归一化歌名已在映射表中有明确原唱歌手（如网易云认证《知我》原唱为 `国风堂 / 哦漏`），则任何同名但歌手不在该集合内的曲目（如 QQ 返回的 `江肆`、`周羽杰`、`安子须`），一律判定为**无标翻唱**并剔除。

### 第三级：器乐 / DJ / 伴奏 / 变种关键词清洗
1. 全量接入 `services/content-filter.ts`（`isCoverOrInstrumental`）与扩展变种正则（过滤 `钢琴`、`纯音乐`、`伴奏`、`DJ`、`慢摇`、`0.8x`、`变速`、`抒情版`、`深情版`、`R&B版`、`片段`、`串烧`、`铃声` 等）。
2. **唯一保留例外**：**原唱歌手本人**的官方演唱会 `(Live)` 版本予以保留，但排序权重置于录音室原版之后。

## 四、跨源去重主权与列表混排规则

1. **同曲去重键**：
   - `normSongBaseName(歌名) + "|" + isLiveFlag + "|" + sortedNormArtists(歌手)`。
   - 录音室原版与原唱本人 Live 版分属不同去重键，互不吞没；同一录音室原版在多源重复出现时合并为一条。
2. **元数据主权优先级（`酷狗 > 网易云 > QQ`）**：
   - 当同一首歌在酷狗与网易云均有官方原唱时，**保留酷狗条目（`kg_<albumAudioId>`）为主键**——因为酷狗条目自带完整音质 `hash` 与 `albumId`，落入 `tracks` 表后即刻具备「零搜索直连取流」能力。
   - 若网易云同曲条目拥有更高清的专辑封面（`al.picUrl`）或更完整的专辑名，合并时可自动补齐至该酷狗条目。
   - 仅网易云独有的原唱曲目（如《知我》、《想去海边》），保留 **`ne_<songId>`** 入列。
3. **列表排序（精确命中置顶 + 双源原唱穿插 Interleave）**：
   - **Tier 0**：歌名或歌手精确匹配搜索词的录音室原版；
   - **Tier 1**：酷狗原唱列表与网易云独有原唱列表按各自排名 **1:1 交替穿插（Interleave）**，确保搜「夏日入侵企划」时，酷狗的《第一万零一次告白》与网易云的《想去海边》并列排在最顶部；
   - **Tier 2**：原唱歌手本人的官方 `(Live)` 版本排在录音室原版之后。

## 五、按 ID 前缀分流的取流解析链（`services/resolver.ts`）

调整 `resolver.ts` 的 `baseChain`，按曲目 ID 前缀精准备流，彻底消灭无意义的二次搜索与无 VIP 的网易云无效试探：

1. **`kg_<albumAudioId>`（酷狗元数据曲目）**：
   - 从 `tracks` 表（或传入的 `ResolveInput`）直接读取预存的酷狗 `hash` / `qualityHashes` / `albumId` / `albumAudioId`；
   - **0 次搜索**，直接走 `stream.ts` 的 `privilege/lite → user_verify → authorization → tracker/v5/url` 拿 FLAC/320k 直链；
   - 若酷狗取流失败，回退 **B 站**（`resolveTrackSource`）兜底。
2. **`ne_<songId>`（网易云独有原唱曲目）**：
   - 既然该曲以 `ne_` 入列，说明酷狗搜索已无此原唱；
   - 若当前网易云账号具备黑胶 VIP（`vipType >= 10`），直接用 `songId` 调 `songUrlV1`（0 次搜索）；
   - 若当前网易云无 VIP（`vipType === 0`），**直接跳过网易云与酷狗重搜，直奔 B 站（`resolveTrackSource`）匹配音频**。
3. **`qq_<songmid>`（首页 / 排行榜 / 歌单广场 / 历史收藏 / 酷狗限流兜底曲目）**：
   - 调 **酷狗**（`resolveKugouSource`）按歌名+歌手搜索取流；
   - 若酷狗未命中，回退 **B 站**（`resolveTrackSource`）兜底（当网易云无 VIP 时跳过网易云取流）。
