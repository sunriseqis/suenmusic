# 酷狗风控 20028 与人工验证接入

> 状态：代码已落地（服务端 + web + 鸿蒙 + iOS），**未做真人验证实测**；
> 2026-10-28 复查时酷狗风控自行解除，本功能转为「下次撞墙时的备用通道」。

## 一、现象与定位

《淘金小镇》《宝贝爱人》等本该有音源的歌解析失败，返回「无可用源」。逐段追踪取流链路后定位：

| 步骤 | 结果 |
| :-- | :-- |
| 查会员 `get_union_vip` | ✅ status=1，概念版 svip/tvip 均在期 |
| 搜歌 | ✅ 200 |
| `user_verify` | ✅ 200，拿到 auth |
| `get_res_privilege/lite` | ✅ 200，有 320/flac 档位 |
| `/v1/authorization` | ✅ 200，拿到单曲 auth |
| **`/tracker/v5/url`** | ❌ **errcode 20028「本次请求需要验证」** |

响应头同时带回：`ssa-code: gz_tx_event_...`、`access-control-expose-headers: SSA-CODE`。

**结论：不是 cookie 失效，是平台要求人机验证。** 生产机同时段同样失败，排除单机 IP 因素。

## 二、验证类型与取舍

按参考实现（MakcRe/KuGouMusicApi + hoowhoami/EchoMusic）的分类器，上游可能要求 12 种验证：

| 类型 | 判定 | 是否自动处理 |
| :-- | :-- | :-- |
| 腾讯图形验证码 | v_type=23 / `KGCodeTX\|` | ✅ 已实现 |
| 短信验证码 | v_type=32 | ✅ 已实现 |
| 登录确认 | v_type=38 | ✅ 已实现（只刷新状态，不伪造提交） |
| 极验/酷狗滑块/旋转/数美/易盾 | `KGCodeGT/KG/KG2/SM/YD\|` | ❌ 只提示 |
| 实名认证 / 绑定手机 / 账号风控 | v_type=34/36/51 | ❌ 只提示 |

未能自动处理的，统一文案：**「账号存在风险，请前往酷狗客户端处理」**。

> 说明：EchoMusic 也只在 TX/SMS/LOGIN 三条上做了真实现，其余均提示去客户端。

## 三、实现

### 服务端（server/）

- `sources/kugou/crypto.ts`：AES/RSA 加密移植（node:crypto，无新增依赖）
- `sources/kugou/simulate.ts`：行为指纹 `generateSimulate`（sid/edt，226 行）
- `services/kugou-verify.ts`：验证事件（内存 30 分钟）、provider 分类、get_verify_info、verify_user_info、HMAC 票据
- `routes/kugou-verify.ts`：五个接口
- `sources/kugou/stream.ts`：`/tracker/v5/url` 命中 20028 时读 `ssa-code` 登记事件（**不改变取流失败语义**）
- `routes/resolve.ts`：仅在**酷狗确实因 20028 失败且整体失败**时才标 `reason=need_verification` 并下发 `verifyUrl`

### 契约

```
GET  /api/kugou/verify/pending      （登录态，无 t）→ state
GET  /api/kugou/verify/state?t=     → state
POST /api/kugou/verify/refresh?t=   → state
POST /api/kugou/verify/send-sms?t=  body { mobile? } → { ok, message }
POST /api/kugou/verify/submit?t=    body { code } → { ok, message, state }
```

- `t` 是服务端签发的 30 分钟 HMAC 票据，允许匿名携带（验证要在系统浏览器里完成，那侧没有登录态）
- `state = { needed, provider, providerName, supported, message, eventId, txAppId, sessionId, createdAt, expiresAt, verifyUrl, smsMobileHint }`
- 验证通过后自动清三层缓存（内存 LRU / 酷狗失败行 / 登录态缓存），下一次解析即可重新取流

### 三端入口

| 端 | 入口 |
| :-- | :-- |
| Web | 设置页酷狗行出现「需要验证」+「解除验证」；验证页 `/verify/kugou` 允许未登录、移动端友好 |
| 鸿蒙 | 系统通知（带 wantAgent）→ 点开用一个跳转拉起系统浏览器打开验证页 |
| iOS | 本地通知（未授权时退化 Toast）→ 点开 `UIApplication.open` 打开验证页 |

去重：同一 eventId 只提示一次 + 10 分钟窗口，避免连播时每首歌都弹。

## 四、使用方式

1. 播一首**必须有酷狗音源**的歌（酷狗命中失败且 B 站也无源，或把该曲钉到酷狗）
2. 服务端登记验证事件（30 分钟）
3. Web 设置页亮「需要验证」/ 手机收到系统通知
4. 点进验证页 → 过腾讯验证码 → 提交
5. 通过后服务端清缓存，再解析即可拿到酷狗直链

## 六、已知不确定（下次撞墙时优先排查这几条）

1. **sid/edt 是否被上游接受**：参考实现的真实提交会带行为指纹，我们已移植并只在上下游为空时生成；未实机验证。
2. **RSA 公钥版本**：当前用概念版(lite)公钥，若上游按标准版校验会解不开，切换点在 `crypto.ts`。
3. **send_mobile_code 签名**：沿用 lite 签名 + `Cookie: mid`，无网未实测；若被拒优先怀疑该接口要标准版 appid/clientver。
4. **失败码 30791**：若真人验证后上游仍拒绝，先查 sid/edt 与公钥版本。

## 七、同时修掉的运维问题

仓库里存在**两个同名 systemd 单元**抢占同一端口：

- `/etc/systemd/system/suenmusic.service`（system，beta）
- `~/.config/systemd/user/suenmusic.service`（user，dev）

谁先占 3210 谁活，另一个 `EADDRINUSE` 崩溃并被 systemd 反复拉起（system 单元累计重启 **2189 次**）。
实际表现是「服务看起来在跑，但加载的是旧代码」——这轮改动后 `/api/kugou/verify/pending` 一直 404 就是因为这个。

**处置**：删除 user 单元（`stop` + `disable` + 删文件 + `daemon-reload`），保留 system 单元；现单个实例稳定运行。
