# 飞牛私有云（fnOS）原生应用套件（.fpk）打包工程方案

## 一、方案目标与定位

为拓展 SuenMusic 作为个人/家庭私有音乐中心的部署生态，针对目前国内普及迅速的 **飞牛私有云（fnOS / 飞牛 NAS）**，在单仓工程 `fn/` 目录下建立标准的**纯原生运行（Pure Native Runtime）**应用套件工程。

### 核心约束与定位
1. **100% 原生运行，杜绝 Docker 伪应用**：
   - 严禁采用将 `docker-compose.yaml` 打包进套件并在后台拉取镜像的“套壳伪应用”做法；
   - 套件作为标准的 Debian 12（fnOS 宿主底座）原生守护进程运行，享受零虚拟化损耗、零容器网络穿透损耗与系统级生命周期管理；
2. **自包含运行环境（Zero-Dependency Host）**：
   - 套件内置独立的 Node.js 22（Linux x86_64）运行时二进制文件，宿主机无需预装任何 Node.js 环境或包管理器；
   - 利用 Node.js 22 内置的 `node:sqlite`（DatabaseSync）和原生 TypeScript 执行能力，彻底消除外部 C++ 本地编译依赖，做到开箱即用；
3. **官方统一视觉资产**：
   - 使用 SuenMusic 官方 1024x1024 品牌主图生成 256x256、64x64 高清抗锯齿图标，与 iOS/Android/Web 品牌资产严格对齐；
4. **单端口全栈承载**：
   - 服务端内置托管 `web/dist` SPA 静态资产，单端口（3210）统一承载 Web 界面、API 与流媒体代理；
5. **一键构建流水线**：
   - 在 `scripts/build-fn.mjs` 中提供端到端自动化打包脚本，产物统一输出至 `output/suenmusic-v<version>.fpk`。

## 二、套件架构与目录规范

遵循飞牛官方 `fnpack` 规范，工程布局在 `fn/` 根目录：

```text
fn/
├── manifest                     # 飞牛应用核心元数据（appname, version, display_name, service_port, arch=x86_64）
├── ICON.PNG                     # 64x64 官方品牌应用中心图标
├── ICON_256.PNG                 # 256x256 官方品牌高清桌面图标
├── config/
│   ├── privilege                # 运行身份声明（run-as: package 权限隔离，无 docker 用户依赖）
│   └── resource                 # 声明持久化数据目录（data-share: suenmusic 与 suenmusic/data）
├── app/
│   ├── bin/
│   │   └── node                 # 自包含独立 Node.js 22 运行时二进制 (755)
│   ├── server/                  # 服务端源码与纯 JS 生产依赖 (src/index.ts, package.json, node_modules)
│   ├── web/
│   │   └── dist/                # 编译就绪的 Web SPA 前端静态资源
│   └── ui/
│       ├── config               # 桌面快捷方式配置（标题、协议、端口 3210、图标路径）
│       └── images/              # 多尺寸高清桌面图标（icon_64.png, icon_256.png）
├── cmd/
│   ├── main                     # 原生守护进程调度脚本（处理 start, stop, status，PID 监控与优雅退出）
│   ├── install_init             # 安装前初始化钩子
│   ├── install_callback         # 安装后完成钩子
│   ├── uninstall_init           # 卸载前钩子
│   ├── uninstall_callback       # 卸载后清理钩子
│   ├── upgrade_init             # 升级前钩子
│   ├── upgrade_callback         # 升级后钩子
│   ├── config_init              # 配置变更前钩子
│   └── config_callback          # 配置变更后钩子
└── wizard/                      # （可选）安装向导配置目录
```

## 三、核心配置文件设计

### 1. `manifest`
```ini
appname               = suenmusic
version               = 1.5.0
display_name          = SuenMusic
desc                  = 个人/家庭私有音乐服务，支持多源搜索、流媒体代理、全端离线缓存与单一真相源同步
arch                  = x86_64
source                = thirdparty
maintainer            = SuenMusic
distributor           = SuenMusic
desktop_uidir         = ui
desktop_applaunchname = suenmusic.Application
service_port          = 3210
checkport             = true
ctl_stop              = true
```

### 2. `config/privilege`
纯原生 package 权限隔离，声明专用运行用户与组：
```json
{
    "defaults": {
        "run-as": "package"
    },
    "username": "suenmusic",
    "groupname": "suenmusic"
}
```

### 3. `config/resource`
声明原生系统共享数据目录映射（供 NAS 用户管理存储，严禁使用包含斜杠的非法共享名）：
```json
{
    "data-share": {
        "shares": [
            {
                "name": "suenmusic",
                "permission": {
                    "rw": [
                        "suenmusic"
                    ]
                }
            }
        ]
    }
}
```

### 4. `app/ui/config`
桌面快捷图标入口配置：
```json
{
    ".url": {
        "suenmusic.Application": {
            "title": "SuenMusic",
            "icon": "images/icon_{0}.png",
            "type": "url",
            "protocol": "",
            "port": "3210",
            "url": "/",
            "allUsers": false
        }
    }
}
```

### 5. `cmd/main` 原生守护进程控制
- **环境变量注入**：
  - `TRIM_APPDEST`: 套件安装解压根目录（读取 `${TRIM_APPDEST}/bin/node`、`${TRIM_APPDEST}/server`、`${TRIM_APPDEST}/web/dist`）
  - `TRIM_PKGVAR`: 套件持久化数据目录（记录 `${TRIM_PKGVAR}/app.pid`、`${TRIM_PKGVAR}/info.log` 与数据库 `${TRIM_PKGVAR}/data/suenmusic.db`）
- **生命周期动作**：
  - `start`: 校验进程是否已存在，通过 `nohup "${NODE_BIN}" --disable-warning=ExperimentalWarning src/index.ts >> "${LOG_FILE}" 2>&1 &` 原生后台常驻，记录 PID 并校验探针存活；
  - `stop`: 读取 PID，先下发 `kill -TERM` 触发 Graceful Shutdown；若 10 秒内未退出则执行 `kill -KILL` 兜底清理；
  - `status`: 读取 PID 并通过 `kill -0 "$pid"` 校验进程真实性，存活返回 0，未运行返回 3（飞牛标准探针状态码）。

## 四、自动化构建流水线 (`scripts/build-fn.mjs`)

构建流水线包含六大步骤：
1. **版本自动同步**：从项目根目录 `VERSION` 读取版本号，归一化为 semver（`1.5` → `1.5.0`）自动同步至 `fn/manifest`；
2. **官方图标重采样**：提取 `ios/App/App/Assets.xcassets/AppIcon.appiconset/AppIcon-1024.png`，通过 Python PIL (LANCZOS) 重新生成 `fn/ICON.PNG` (64x64)、`fn/ICON_256.PNG` (256x256) 以及 `fn/app/ui/images/*`；
3. **独立 Node.js 运行时装配**：自动下载/复用官方 Node.js 22.14.0 Linux x64 独立二进制，安装至 `fn/app/bin/node`（`chmod 755`）；
4. **服务端源码与 Web SPA 组装**：复制 `web/dist` 至 `fn/app/web/dist`，复制 `server/src`、`server/package.json` 及 `server/node_modules` 至 `fn/app/server`；赋权 `fn/cmd/*` 为可执行；
5. **打包工具链校验**：检测系统全局 `fnpack`（`/usr/local/bin/fnpack`），不存在则自动下载官方二进制；
6. **执行打包归档**：调用 `fnpack build -d .` 打包生成原生套件，归档至 `output/suenmusic-v1.5.0.fpk`，输出 SHA-256 和包体积。
