# 建库与选歌约束优化 · 执行计划（2026-10-29）

> 关联：[建库审计与约束评审](../memory/2026-10-29-建库审计与选歌约束评审.md)
> 用户三条具体场景 + 五条必改已定，本计划是落地清单。

## 一、问题背景

现有整套流程：建库存歌 → 建候选池 → AI 选歌 → 写理由 → 审核 → 落地。
用户从三个具体场景指出问题，子代理用代码审计 + 库实测把根因挖清楚了。

## 二、五条必改

### 1. 数据流：本地回填短路了多源

**现象**：`library_tracks` 2184 首 100% 是 QQ（kg_/ne_ 各 0），多源代码 2026-10-27 才合入，之后零新增。

**根因**（`library-builder.ts:303-314` 与 `:197-207`）：
```
findLocalTracksForArtist 命中 → saveLibraryTracks(本地) → markArtistFetched → return
跳过 fetchArtistSongsMulti，外网多源永不被调用
```
31/31 歌手本地全命中 QQ 歌单池，短路 100% 发生。

**改法**：本地回填**不再 return**，改为「本地保底 + 继续走多源补源」；
对 `hot_fetched_at` 早于多源上线时间（2026-10-27）的歌手**强制重拉**。

### 2. 熟悉度误判：1-2 首歌手被当成熟悉度源头

**现象**：收藏 197 个歌手，1-2 首的 119 个（60%），>10 首的只有 10 个。
`simi` 50% 名额按歌手相似发散，把「只听 1 首」的歌手当成熟悉度。

**改法（阈值定 5）**：
| 收藏数 | 定性 | 处理 |
| :-- | :-- | :-- |
| 1-2 首 | 只喜欢这几首歌 | 当曲风参考，不能当歌手种子 |
| 3-4 首 | 算喜欢 | 可以推，新歌优先 |
| ≥5 首 | 深度喜欢 | 进 TOP 池，新歌必推 |
| ≥10 首 | 巨量（筛过的） | TOP 池 + 降频，新歌必推 |

`ai-recall.ts` 的 `seedArtists()` / `topArtists()` 按 hits 分档；
`simi` 发散改「**topStyles(userId) 曲风匹配 + 相似歌手**」双路，读 `user_style_profile`（已存在）。

### 3. 「未收藏」是弱负信号，接到现有 TOP 规则

**用户语义**：未收藏有动机（听腻/不喜欢），不排除「没想起来」，所以**降权但仍可能推**。

**注意**：现有 TOP 规则（每几天 1 个熟悉歌手 1 首老歌）思路**符合预期，不动**。

**改法**：
- 收藏 5+ 歌手 → TOP 池（现有规则）
- 同一歌手「听过但未收藏」越多 → 冷却期越长（可选，锦上添花）
- 收藏 1-2 首歌手 → 不进 TOP 池，只当曲风参考（新增）

### 4. 新歌识别不及时

**现象**：新歌只来自 QQ 首页 `newSongs` 全站榜前 12，不是歌手维度；
`albumDetailCache` TTL 7 天，新专辑最多延迟 7 天；`getHomeData` 失败/冷却时直接跳过，错过不补。

**改法**：为收藏 5+ 的种子歌手做专辑级新作检测（`getArtistAlbums` 按 `releasedate` 排序）；
失败/冷却时入队补拉而非跳过；最新一张专辑缓存 TTL 缩到 24h。

### 5. 推荐理由空话：流程重构

**用户原话**：「流程不由优化一下。选歌的 AI 负责给理由，前端的部分由审核给。审核觉得选歌 AI
某首歌的推荐写的非常合理而且强烈认可，那么可以落进本歌曲的推荐语页，如果觉得完全在水，那就丢掉，不给前端看。」

**新流程**：
```
选歌 AI 写长理由（详细版，给审核看）
      ↓
审核 AI 判断 + 压缩
      ↓
  ├─ 强烈认可 → 精炼成短句（12-25 字），落进「这首歌的推荐语页」（前端展示）
  └─ 在水     → 丢掉，前端不展示
```

**落地细节**：审核给标签（`approved` / `rejected`）+ 压缩成短句（B+C 方案）。
选歌 AI 不再为「显示长度」分心；审核既做判断又做精炼；前端拿到的都是成品。

## 四、不改的

- TOP 歌手硬约束的方向（强制降频、4 天轮换、偶遇老友上限 1 首）—— 符合预期
- 池内「一位歌手最多 1 首」—— 对，保留
- 已收藏永久排除 / 7 天冻结 / 黑名单物理拦截 —— 对，保留
- seedNew 必进、不占名额、TOP 豁免 —— 机制对，只补识别及时性
- 严格 JSON 输出与理由 12-25 字约束 —— 保留

  推荐语短句是否是审核改写版、新歌是否被及时识别
