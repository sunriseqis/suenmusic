## 一、任务清单（8 项，按顺序做）

### 1. 首页离线快照（P0 —— 飞行模式冷启动现在是死的）

现状：`AppState.loadHome()` 失败 → 首页「加载失败」，而缓存曲其实能播。

要求：
- `AppState` 把**成功**的 `HomeData` JSON 存进 `preferences`：键 `home_snapshot`（字符串）+ `home_snapshot_at`（毫秒时间戳）
- `bootstrap()` 先读快照渲染（有快照就立刻有列表），**再**后台刷新；刷新失败**不覆盖**快照
- 首页顶部显示一行小字：`离线数据 · 最后更新 10-21 12:30`（仅当本次是快照渲染时）
- 快照上限：只存 `newSongs` 前 50 + `toplists` 全量 + `welcomePhrase`，避免 preferences 膨胀

验收：飞行模式冷启动 → 首页有列表 + 顶部离线提示 + 缓存曲可播。

### 2. 歌词翻译双语对照（P1）

- `LyricResult.tlyric` 已存在（可能为空串）
- 解析：`parseLyricLines(tlyric)` 后再按时间戳与原文对齐（|Δt| ≤ 300ms 视为同一行）
- UI：原文一行 + 翻译一行（`Tokens.text2`、字号 -3）
- `SettingsPage` 增加开关「显示歌词翻译」（默认开），存 `preferences` 键 `lyric_translation`
- 翻译为空时不显示占位、不留空行

### 3. 自动选路开关（P1）

- `APIClient.setAutoFailover(enabled: boolean)` + `isAutoFailover()`，`preferences` 键 `auto_failover`（默认 true）
- `failoverIfNeeded()` 首行判断：关闭则直接 `return false`
- `SettingsPage` 增加开关「自动切换服务器」（说明文案：网络异常时自动尝试其它服务端）

### 4. 错误文案统一（P1 —— 现在各页自己造词）

新增 `common/Copy.ets`：

```ts
/** 把任意错误翻译成一句人话。所有页面都必须走它，禁止自造文案。 */
export function describeError(e: Object): string;
/** 按业务码给短语：network / unauthorized / source_unavailable / shortfall / ... */
export function describeCode(code: string, fallback: string): string;
```

映射至少覆盖：
| 场景 | 文案 |
|---|---|
| `code === 'network'`（status 0） | 连不上服务端，请检查网络或服务器地址 |
| `401 / unauthorized` | 登录已失效，请重新登录 |
| `503 + source_unavailable` | 这首暂时找不到可播放音源 |
| `shortfall`（每日推荐） | 曲库还太少，先多听几首再来看 |
| `invalid_platform` / 其它 4xx | 请求被拒绝：`<服务端 message>` |
| 其它 | 出错了，请稍后重试 |

把 `HomePage` / `SearchPage` / `FavoritesPage` / `DailyPage` / `LoginPage` / `PlayerPage` 的错误文案全部改为调 `describeError`。

### 5. ArkTS WARN 清零（P2）

| 位置 | 处理 |
|---|---|
| `APIClient` 的 `pref.flush()` / `req.request()` | 加本地 `try/catch`（`request` 的 catch 已被外层接住，但 ArkTS 静态检查要求本地 catch → 用 `try {…} catch(e) { throw e; }` 不行，需真处理：失败时按网络错误抛出） |
| `EntryAbility.rpc.writeInt` | 同上，包 try/catch 并降级 |
| `MediaPlayerCore` 4 处 SysCap 警告 | 在调用点加 `canIUse('SystemCapability.Multimedia.Media.Core')` / `('SystemCapability.Multimedia.Audio.Core')` 守卫并给出降级提示；或若判定无意义，在代码里注明"deviceTypes 仅 phone/tablet，该能力必然存在" |

目标：`devecocli build` 的 WARN 只剩 `No signingConfig`（预期）。

### 6. 播放失败可重试（P1）

- `MediaPlayerCore` 新增 `async retryCurrent(): Promise<void>`：清 `failStreak`/`failHandled` → `loadCurrent(this.wantPlay)`
- 播放页：`np_error` 非空时显示「重试」按钮（`Tokens.panel2` 底），点了调 `retryCurrent()` 并清 `np_error`
- 首屏不要弹 toast，只在播放页内联展示

### 7. 权限最小化（P1）

核对 `module.json5` 的 `requestPermissions`：
- 只保留 `ohos.permission.INTERNET` + `ohos.permission.KEEP_BACKGROUND_RUNNING`
- 删除其它未使用项
- `abilities[0].backgroundModes` 只留 `audioPlayback`

### 8. 令牌提前续期（P2）

- `APIClient` 记录 `accessExpiresAt`；发出请求前若 `now > expiresAt - 60_000` 且未在刷新中 → 先 `refresh()`
- 目的：避免长时间播放后首个请求 401 → 重放一次造成的可感知延迟

## 二、验收（8 条）

| # | 操作 | 判定 |
|---|---|---|
| 1 | 飞行模式冷启动 | 首页有列表 + 「离线数据 · 最后更新 …」+ 缓存曲可播 |
| 2 | 联网后下拉/重进 | 快照被真实数据替换，离线提示消失 |
| 3 | 有翻译的歌词 | 原文+翻译两行显示；关掉开关后只剩原文；重启仍记忆 |
| 4 | 关闭「自动切换服务器」后断网 | 不自动换服，错误文案是「连不上服务端…」而不是别的 |
| 5 | 触发一次 503 无源 | 提示「这首暂时找不到可播放音源」并自动跳过 |
| 6 | 播放失败后进播放页 | 有「重试」按钮；点击后重新装载当前曲 |
| 7 | 每日推荐 shortfall | 显示「曲库还太少，先多听几首再来看」 |
| 8 | 构建 | WARN 仅剩 `No signingConfig`，0 ERROR |

回归门禁（同前）：后台/锁屏正常、无 `SetAVPlaybackState timeout`、同曲不重复 `updateMetadata`、颜色只走 `Tokens`。
