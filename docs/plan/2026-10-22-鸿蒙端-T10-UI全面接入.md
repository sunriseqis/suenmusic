## 一、定位

这不是打磨，是**功能与元素的全面补齐**：把 web 移动版每个页面的**内容区块、视觉元素、
交互细节**逐个搬进鸿蒙端。T5.5 只做了首页三区块，其余页面与 web 的差距仍然存在
（回收页/专属页无封面视觉、专属页头部信息不全、设置页分区与 web 不一致等）。

**核对方法（每个页面照做）**：web 与鸿蒙**并排开同一服务端的同一页面**，
逐区块比对「有/无、内容、层级、操作」——web 有的鸿蒙不能缺，web 没有的鸿蒙不擅自加。

## 七、平台坑位（必读 —— 前几轮真机踩过的）

| 坑 | 说明 | 规避 |
|---|---|---|
| **Content-Type 注入** | 鸿蒙 http 栈对**空 body 请求也注 `application/json` 头** → Fastify 对「json 头 + 空 body」一律 400。T2 已在 `buildHeaders` 修（有 body=json，无 body=text/plain）；T10 新增的 dislike/persona/guidance 请求**必须沿用 `raw()`/`buildHeaders`**，不要绕开自拼 header | 复用 `APIClient.raw()` |
| **forEach/ForEach key** | key 不含变化字段 → 数据变了 UI 不重绘（T3 编辑名称、T2 收藏序号都踩过）。列表 key 必须**含全部会变的内容字段** | key 生成器自查 |
| **Tabs 横滑与行内水平手势竞争** | `Tabs.scrollable` 必须保持 `false`（T2 已设），勿在重构中恢复 | 回归时验证右滑收藏不跳 Tab |
| **成员名撞 ArkUI 内置属性** | `position/tabIndex/dragPreview` 都踩过；新组件命名前查一遍 | — |
| **Tab 动效** | 页面级位移/透明度在该设备被用户读作"抖动"，**沿用 T5 定稿口径：页面零动效 + 按钮级反馈** | — |
| **颜色纪律** | 只走 `Tokens.*`；danger 语义色（已收藏红底 `#8A1F18/#FFDAD6`）沿用 T2 豁免，新增语义色先报 Lead | — |
