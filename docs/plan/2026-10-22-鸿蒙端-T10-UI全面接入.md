## 一、定位

这不是打磨，是**功能与元素的全面补齐**：把 web 移动版每个页面的**内容区块、视觉元素、
交互细节**逐个搬进鸿蒙端。T5.5 只做了首页三区块，其余页面与 web 的差距仍然存在
（回收页/专属页无封面视觉、专属页头部信息不全、设置页分区与 web 不一致等）。

**核对方法（每个页面照做）**：web 与鸿蒙**并排开同一服务端的同一页面**，
逐区块比对「有/无、内容、层级、操作」——web 有的鸿蒙不能缺，web 没有的鸿蒙不擅自加。

## 二、逐页面差距清单（Lead 基于 web 源码预扫，执行时并排复核）

### 2.1 首页（T5.5 已做三区块；复核残差）
- 新碟海报：区块已有。**核对**：日期角标位置/光泽层/翻页节奏与 web 逐像素比
- 新歌列表：web 每行有**播放按钮**（行内操作），鸿蒙只有整行点击 → 补行内播放钮
- 巅峰榜：已有两列。**核对**：badge 位置、`updateFrequency` 副文案、封面比例
- 缺失项核对：web 首页无其它隐藏区块

### 2.2 专属页（DailyPage）——差距最大
- **头部信息**：web 用 `parseAiHeader(greeting)` 拆**主标题+副题**两级（T5.5 已做），并带
  **AI 生成标识/风控标签防御**（`cleanAiText` 已做）——核对呈现是否与 web 一致
- **推荐理由行**：web 每首推荐曲目带 `reason`（入选理由）副文案——鸿蒙**缺**
- **不喜欢**：web 长按/按钮「不喜欢」→ `POST /api/recommend/dislike` → 立即移出并切歌
  （语义见 `docs/memory`：永久过滤 + 当日歌单移除）——鸿蒙**缺**，这是专属页的核心交互
- **shortfall/generating 态**：已有，核对文案与 web 口径一致

### 2.3 收藏页（FavoritesPage）
- 行视觉权重已提（48 封面）。**核对**：web 收藏行还有「 dislike 旁按钮」？核对 web
  `Favorites.vue` 移动断点的行内动作集合，逐个对齐
- **导入/导出入口**：web 有 `.sm` 导入预览与导出（设置页/收藏页入口）——核对移动断点
  是否露出，露出则鸿蒙补入口（接口已有：`/api/favorites/import`、`/export`）

### 2.4 搜索页（SearchPage）
