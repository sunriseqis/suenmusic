# 客户端全原生化迭代方案（2026-10-21 立项）

> **状态**：**S0（iOS 骨架）已落盘但暂无法验证（手边没有 Xcode）；当前推进 S2（鸿蒙骨架）**。
> 顺序调整：iOS 验证后置，鸿蒙先行 —— 因为鸿蒙侧有 DevEco 可真机验证，iOS 侧暂时只能"写好等编译"。
> **决断**：iOS 用 SwiftUI、鸿蒙用 ArkUI **全原生重做客户端**；
> **Android 封库**（不再更新、不再有 CI 构建、不再分发与上架）；
> **Web 保留为 PC 端唯一客户端 + 管理面板**（PC 不做原生客户端）。
>
> **目标系统版本（已定）**：**iOS 26+**、**HarmonyOS NEXT 6（26.0.0）**，均**不再兼容低版本**。
> iOS 侧连 macOS 15 都能直接跑 iOS 26 虚拟机，所以低版本兼容没有收益，只会多出兼容分支。
> Web 面板反过来要**兼容老浏览器**（PC 端唯一入口，不能挑设备）。
> **关联**：`docs/memory/2026-10-20-终止直连回归服务端.md`、`docs/memory/2026-10-19-iOS直连播放链路与锁屏上限.md`、
> `docs/memory/2026-10-21-六端重审修复与死码清理.md`、`docs/plan/2026-10-20-回归服务端单一真相源架构方案.md`

## 一、为什么这次不允许"混合/折中"

直连实验（10/17–10/19）失败的第一条根因是：

> 锁屏或退后台 5~15 秒后，系统**无条件挂起 WKWebView 内的 JS 引擎** → WBI 签名与流解析失效 → 原生队列只剩 1 首 → 曲末停播 → 系统吊销后台音频权限。

那是**"让 WebView 承担系统级职责"**的代价。我们后来把解析迁回服务端（对），但**鸿蒙至今仍让 WebView 的 `<audio>` 承担"播放"** —— 同一类错误，只是换了一层。

混合方案（播放页原生 + 长尾留 WebView）看着省事，实际是这个项目已经吃过大亏的形态：

1. **两套渲染管线并存** → 转场、手势、返回、安全区、焦点、无障碍各写两遍，且永远有一处对不齐；
2. **状态有两个 owner** → Web 与原生互相回调（直连时代 8 秒 137 次 `makeItem` 的闭环就是这么来的）；
3. **审核与体验两头不靠** → 既没有"原生应用的流畅"，又要付 WebView 的全部坑。

所以：**要么全原生，要么别做这次迭代。**

## 二、目标架构

```
            ┌──────────────────────────────┐
            │  服务端（单一真相源，不变）    │
            │  Fastify + SQLite + 流代理    │
            │  Range/206、令牌、多用户、AI   │
            └───────┬───────────┬──────────┘
                    │ HTTPS/JSON + 流字节
        ┌───────────▼──┐   ┌────▼───────────┐   ┌──────────────────┐
        │ iOS（SwiftUI）│   │ 鸿蒙（ArkUI）   │   │ Web 面板（Vue）   │
        │ AVQueuePlayer │   │ AVPlayer       │   │ 仅管理配置        │
        │ 磁盘 LRU+代理 │   │ request.agent  │   │ cookie 会话       │
        └──────────────┘   └────────────────┘   └──────────────────┘
                 ↑ 播放状态机的唯一 owner = 原生（两端各自）
```

**四道不可动摇的约束**

1. 服务端是唯一真相源；客户端不做解析、不做签名、不存权威数据。
2. 播放状态机只能有一个 owner（原生）；UI 只下发意图、只展示状态。
3. 客户端 UI 里**没有 WebView**。
4. 断网可用性靠**磁盘缓存 + 本地回环代理**（iOS 已有 1438 行实现，鸿蒙照抄语义）。

### 5.3 硬约束（已在官方文档核实，见 `docs/memory/2026-10-21-六端重审修复与死码清理.md` §7.4）

- `STREAM_USAGE_MUSIC` + **必须**接 AVSession + `AUDIO_PLAYBACK` 长时任务；暂停/停止**主动取消**（官方建议 `on('pause')` 后取消），否则"申请了但没在播"会被系统挂起；

- 卡片 `updateDuration` 单位 30 分钟、定时刷新**每卡每天 50 次**；主动 `updateForm` 频率官方无配额（真机自证，暂定 ≥10s）。

## 十一、交付流程与文档归档规则（**从 S3 起强制执行**）

之前把交接单/回执随手写在 `hw/` 根目录，命名也不统一（`S3-增量1-…` vs `2026-10-21-S2-…`），
导致同一件事在三个地方各有一份。以下是唯一正确做法：

| 产物 | 位置 | 命名 | 说明 |
|---|---|---|---|
| 总纲（本文件） | `docs/plan/` | `YYYY-MM-DD-<主题>.md` | 架构与阶段门禁，长期有效 |
| **阶段交接单** | `docs/plan/` | `YYYY-MM-DD-S<n>-交接单-<主题>.md` | 交给本机 IDE 智能体执行的单子 |
| **增量交接单** | `docs/plan/` | `YYYY-MM-DD-S<n>-增量<m>-<主题>.md` | 阶段内的单次交付 |
| **执行回执 + Lead 核验** | `docs/memory/` | `YYYY-MM-DD-S<n>-验收回执与核验.md` | 回执原文要点 + 我的逐条复核 + **事实纠正** |
| 工程手册（结构/约定/踩坑） | `docs/dev/` | `<子项目>-<主题>.md`（如 `hw-native-client.md`） | 面向"下一个人"的常驻手册 |
| 索引 | `docs/memory/MEMORY.md` | 每份 memory 一行 | 指向路径 + 一句话结论 |
| 决策记录 | `docs/memory/` | `YYYY-MM-DD-<主题>.md` | 只放"为什么这么定"，细节用指针 |

**`hw/`、`server/`、`web/`、`ios/` 这些代码目录里不放计划与回执**（各自 `README.md` 除外）。

### 每一轮的固定动作

1. 我写交接单 → `docs/plan/…`，并在本轮对话里给出「要同步哪些代码文件」的清单
2. 执行方按单执行 → 把它自己的回执放哪都行（它机器上没有本仓），**回传给我即可**
3. 我收到回执后：**先核代码**（不听转述）→ 再把回执要点 + 核验结论 + 事实纠正写进
   `docs/memory/YYYY-MM-DD-S<n>-验收回执与核验.md` → 更新 `MEMORY.md` 索引
4. 有偏差的地方：**当场改代码**，并在回执文档里写清"执行方原判断 → 实际情况 → 修法"
