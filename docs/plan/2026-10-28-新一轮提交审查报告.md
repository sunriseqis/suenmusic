## 2. P1（4 条，建议放行前必修）

### S-B1｜酷狗 20028 的 `verifyRequired` 在兜底链被丢弃，通知入口等于死路
- 位置：`server/src/services/resolver.ts:363,409,422`（`return resolveTrackSource(input, …)`）、`server/src/routes/resolve.ts:94-96`
- 证据：`const verifyRequired = !outcome.ok && (outcome.verifyRequired === true || outcome.reason === 'need_verification')`；
  `verifyRequired` 只在 `server/src/sources/kugou/stream.ts:355,435-439` 置位，而 `qqChain/kgChain` 在酷狗失败后**直接返回 B 站结果**，该标记随对象一起被丢掉；
  唯一能活下来的是源钉路径（`resolver.ts:428-429` `pin.source==='kugou'`）。
- 后果：`docs/plan/…酷狗风控20028与人工验证.md:48`「酷狗确实因 20028 失败且整体失败才标 need_verification 并下发 verifyUrl」在**主要链路上永不成立**，
  `ios/SuenMusic/Player/PlaybackService.swift:232`、`hw/entry/…/core/KugouVerify.ets:27` 依赖它 → 端侧验证入口不可达。
- 建议：兜底前记录酷狗侧结果，B 站也失败时回填 `verifyRequired/reason='need_verification'`。

### S-C1｜验证接口匿名可访问 + 无频控 + 票据不绑事件/人不绑角色
- 位置：`server/src/routes/kugou-verify.ts:52-82`、`server/src/services/kugou-verify.ts:679-700`
- 证据：票据形如 `${expiresAt}.${HMAC(expiresAt)}` —— **只绑过期时间**，不绑 eventId / 签发人 / 用户；
  `server/src/app.ts:103` 的全局 `onRequest` 只做 CORS，鉴权全在路由内各自 `requireUser`（我实查确认**无 rate limit 实现**，仅上游 cooldown）。
- 后果：任一登录用户取到 `/pending` 的票据后即可 (a) 触发 `clearMemoryCache()` 全局清内存 LRU、(b) `deleteNegativeSources('kugou')` 删全表负缓存、
  (c) `send-sms` 向**任意**手机号发短信（仅 `/^1\d{10}$/` 格式校验）→ 短信轰炸与上游风控。
- 建议：票据绑 eventId+签发者；`send-sms` 只允许凭据内号码或加严格频控；`clearMemoryCache` 收窄到酷狗相关键。

### IA-R1｜缓存落盘只看状态码与字节数，不校验内容类型 → 坏页永久落盘且永不回上游
- 位置：`ios/SuenMusic/Player/AudioCacheStore.swift:233-268`
- 证据：`guard (200..<300).contains(http.statusCode)` + 字节数比对后**直接 `fm.moveItem(at: tmp, to: bin)`**，无 `http.mimeType` 白名单；
  CDN 回 200 的 HTML 错误页（自带 Content-Length 时字节比对也过）被写成 `.bin`；`AudioEngine.swift:1022` 缓存命中优先、永不回上游。
- 建议：加 `mimeType` 白名单（audio/*、video/*、application/octet-stream），不匹配即丢弃。

### IB-A1｜共享 scheme 的 BlueprintIdentifier 在生成的 pbxproj 中不存在
- 位置：`ios/App/App.xcodeproj/xcshareddata/xcschemes/App.xcscheme:18,34,66,83`
- 证据：4 处 `BlueprintIdentifier = "504EC3031FED79650016851F"`，在 `project.pbxproj` 中命中数 **0**（生成器 `scripts/gen-ios-project.mjs:46` 用 `hid()` 派生，实际 id 为 `2029A639DD…`）。
- 后果：Xcode 打开 scheme 解析不到可构建目标，`xcscheme:28` 的补签 PostAction（`fix-ios-sim-entitlement.sh`）一并失效；CI 用 `-target` 故无感。
- 建议：生成器一并产出 scheme 的 BlueprintIdentifier，并把 `--check` 扩到 scheme。
